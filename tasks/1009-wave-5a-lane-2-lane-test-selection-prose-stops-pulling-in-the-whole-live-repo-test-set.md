- [#1009] [P1][S] **Wave 5a lane 2 (lane-test-selection) -- prose stops pulling in the whole live_repo test set** - filed per `to-cc/WAVE4B-COMMON-2026-09-22.md` rule 1 (still binding in WAVE5A per `to-cc/BATCH-WAVE5A-2026-09-23.md`); frozen contract `LANE-5A-2-test-selection.md`, branch `worktree-lane-test-selection`. Value: on 4 of 5 wave-4B merges the lane's own code reached 0 to 3 test files, yet a mixed code+prose diff unioned in all 58 `live_repo`-marked files, costing 30-64 minutes per merge; the merge-receipts ledger (`logs/MERGE-RECEIPTS.jsonl`, folded into nearly every merge) matched no rule at all and fell to the "unmapped" fail-safe, which is worse -- it forced `full_suite=True` on all five replayed wave-4b merges, and `gates.py`'s per-merge gate REFUSES rather than silently running a selector's full-suite answer. · implements: ADR-120 · Done when: 1. **Narrow prose selection:** a prose or generated edit no longer expands a mixed diff's own `pytest_args()` into the 58-file union; `Selection.marker` stays set and reachable on its own via the new `Selection.docs_tier_args()`, decoupled from the lane's own code/test selection, so the integrator can run it once per batch. 2. **`logs/MERGE-RECEIPTS.jsonl` is mapped** to a fixed rule targeting the two tests that actually assert on it (`tests/test_merge_receipt.py`, `tests/test_lane_digest.py`); its presence in a diff never forces the full suite. 3. **Measured proof:** the selector replayed on the five wave-4b merge diffs, before/after table in this row's own audit. 4. **Tests, red first,** for items 1 and 2 -- verified against the pre-fix module before implementation (measured-proof audit §1-2). 5. **Close-out:** Codex terra review (consumer cited); self-check and purity; handback. **FINDING (Codex terra HIGH, unfixed by design):** `scripts/test_pairing.py`'s `compare` used the old union baked into `select()`'s `test_files` as its only path to live-tree coverage on a mixed diff;
