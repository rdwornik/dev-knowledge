- [#554] [P2][M] **Devcontainer + provisioning script (NB4-G stage 1)** — stage 1 of the NB4-G scale-out: the reproducible container plus provisioning script that lets a lane run OFF this machine, so batch width stops being bounded by one workstation’s measured admission ceiling of 6 concurrent lanes (99.6% CPU, hook starvation at 12 — the serial integration queue, not lane count, is the binding constraint). Four legs, each a failure mode the two NB4-G reports measured rather than a checklist item: a **pinned-`uv` assert** — an unpinned `uv` re-resolves the lockfile, and a lane’s green then stops meaning the hub’s green; **`git fetch --unshallow`** — Codespaces clones shallow while every enforcement organ here reads history (`journal_spine_anchor` walks `--first-parent main` above a dated floor, `block_ff_push` scans for FF signatures), so on a truncated clone those gates are vacuous or actively wrong rather than merely slower; **deterministic hook arming** — `pre-commit install` for all three hook types, because the config’s `default_install_hook_types` only wires them on a fresh install, so a container that skips it is a lane running with its gates silently disarmed (the relic-`core.hooksPath` failure mode reached by another route); and a **fleet-check env gate** — refuse to start rather than run a lane against a half-provisioned environment. The substrate is NOT this row’s question, being already operator-decided: Codespaces free tier for stage 1, then Hetzner CX53 **SHARED** (post-2026 repricing; explicitly not CCX), with VS Code Remote Tunnel + tmux as the control plane. · Done when: one lane runs green (`audit.py health` **and** `pytest -m 'not slow'`) on the Codespaces free tier, and the *identical* script is runnable via `devcontainer up` on a VPS · refs docs/audits/2026-08-16-technical-nb4-g-scaleout-substrate.md, docs/audits/2026-08-16-technical-nb4-g-scaleout-substrate-v2.md, docs/intake/2026-08-17-tech-off-machine-agent-substrate.md, docs/archive/2026-08-17-research-off-machine-agent-fleet-substrate-wf-fe444def.md, #541, #453, #528 · kill-candidates: none — no row owns off-machine provisioning; [#541] owns the substrate DECISION, which the operator has since made, and not the container that executes on it, while [#453] owns the cloud-container PREFLIGHT for an already-provisioned session — it names the unshallow and the `uv`-pin assert in its own Done-when, a real two-of-four-leg overlap recorded here rather than smoothed over, and whichever lands second should discharge by pointing at the first · source: architect authorization at the 2026-08-17 window close (priority-order-v2 slot 3)
