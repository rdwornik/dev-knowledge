- [#736] [P2][M] **Component lifecycle is not data, so nothing can deprecate an organ — an item untriggered and unread for 30 days stays `production` forever** - `AX13-1` of `to-cc/AMEND-BATCH-X-ROSTER-013.md`, which files it as a NEW X2 row; carried into X1-1's lane contract under AX12-1 and filed here by that lane, since AX12-1 rules that nothing stays SAID. Carried verbatim: *"**AX13-1 · NEW row, X2: component lifecycle as data + automatic deprecation.** Every item in the organ index / FPG-1 carries `lifecycle: experimental | production | deprecated | removed` (the field X-C already collected) with `deprecated-since`, `reason`, `replacement`, `removal-floor-version`. The domain census runs on a schedule (nightly after conductor E; at each batch close until then) and flips any item UNTRIGGERED AND UNREAD for ≥ 30 days to `deprecated` automatically; a `deprecated` Python module warns on import via the standard `deprecated` decorator (library-first). RED-first: a fixture item aged past the bar is not flipped → the test fails."* · **The gap is measured, not asserted.** `graph_queries.py process-list` answers 158 processes, 119 triggered, 39 not — and every one of those 39 is held by `ORPHAN_DISPOSITIONS`, a hand-curated register whose commonest reason is the literal string *"lane-built and never adopted"* and whose commonest owner is *"V+1 retirement-or-wiring list"*. That register is the manual precursor this row mechanizes: it records that an absence of triggers was LOOKED AT, and it has no time axis at all, so an organ dispositioned once is dispositioned forever and a list named for a wave that has not run is where 20 of the 39 sit. · **UNTRIGGERED and UNREAD are two different measurements and only one of them exists.** FPG-1 answers UNTRIGGERED today — reachability from the wiring roots over `triggers`/`imports` — but nothing in this repo measures UNREAD, because no organ records that a module was imported or a doc opened at a wall-clock time. The 30-day bar is therefore a conjunction over one live predicate and one that must be built, and a lane that reads the clause as "flip the untriggered ones" will deprecate `export_backlog_view.py`, whose own disposition says a test ASSERTS that nothing reads it. That is the concrete failure the second half of the conjunction exists to prevent, and it is why the read-evidence source is part of this row rather than an implementation detail. · **Library-first is named IN the clause and the named library is not the stdlib answer.** AX13-1 says *"the standard `deprecated` decorator (library-first)"*; `deprecated` is a PyPI package, and `warnings.warn(..., DeprecationWarning, stacklevel=2)` is the stdlib answer to the same need. CLAUDE.md's ladder is stdlib > established dependency, and ADR-106 makes any addition a gated change to `pyproject.toml` + `uv.lock` with `uv` pinned exactly. So the building lane MEASURES the divergence and records it; it does not add a dependency because a clause named one in passing. · **Sequencing is in the clause's own words** — *"nightly after conductor E; at each batch close until then"* — so the schedule leg waits on `[#689]` and the batch-close leg does not. Filing both under one row keeps the two halves from being built against different definitions of the same census. · Done when: every item in the organ index / FPG-1 carries `lifecycle: experimental | production | deprecated | removed` with `deprecated-since`, `reason`, `replacement` and `removal-floor-version`;
