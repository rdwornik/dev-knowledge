Both halves of the Done-when met, and the enrichment with them. **Failure half:** `verify.py` now emits an `--- Actionable ---` section with a four-field block per failing check — `file` / `expected` / `received` / `directive` — parsed from each tool's own output: the pytest block names `path::test` and the `E` assertion line, ruff names `file:line:col` plus the rule code, git names a dirty path and counts the rest. An unparseable tool output still yields a complete block marked `(unattributed - see full output)` rather than throwing — a checker that cannot read its own input degrades, never crashes. **Success half:** proven to stay EXACTLY the 3-line compact form, asserted as a list equality so a fourth line cannot creep in. **Enrichment (semantic exit code + expected-vs-got):** exit is a **bitmask** — pytest 2, ruff 4, git 8 — so `6` means pytest AND ruff are red and the loop can compose. Chosen over a first-failure code deliberately, and the reason is recorded in the module docstring: an iterate-until-green loop seeing the SAME code twice knows it made no progress, which is precisely the anti-retry-loop signal the row asks for, and a first-failure code can express neither. `.claude/skills/verify/SKILL.md` documents the block shape and the code table so the contract is legible to the caller and not only to the script. **14 tests** in the new `tests/test_verify_skill.py`, driven against SEEDED tool output and a stubbed `run()` — running the real suite from inside the suite would be both slow and circular
