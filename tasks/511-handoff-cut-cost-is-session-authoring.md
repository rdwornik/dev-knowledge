- [#511] [P2][M] **The 30-minute handoff cut is ~99.8% session authoring, not machinery — decide what to cut** — the operator's standing complaint is that cutting a bundle costs ~30 minutes of a session's rhythm. **MEASURED 2026-08-07 before any fix was proposed**, best-of-3 on the live hub, into a throwaway `bundle_root` so no immutable artifact was created: `collect_state` **525 ms** · `collect_hints` **831 ms** (`_vision_extract` 0.7 ms, `_intake_index` 11.7 ms) · `generate(assemble=False)` **1,344 ms** · `generate(assemble=True)` **1,708 ms** (the `assemble_paste` subprocess is **364 ms** of that) · cold CLI including interpreter start **3,321 ms** · `verify_handoff_probes.py` on a real bundle **1.2 s**. **Total mechanized cost of a full cut + live probe gate: ~4.5 seconds.** Against a 30-minute wall clock that is **0.25%**, so optimizing the generator cannot move the number and this row is deliberately not a performance row. **Where the time actually goes, from the same cut:** a cold architect bundle ships **15 distinct FILL-IN regions** for CC to author (`HANDOFF_BOOT.md` 8, `RESIDUAL.md` 6, `PROBES.md` 1), a **38,067-byte / 352-line** `PASTE_THIS.md` to review, and **14 probes** that `/handoff-verify` re-derives from live primary sources one by one — that last being the anti-bluff contract's whole point (§5), so it is the expensive thing that is also the load-bearing thing. **The fork this row exists to settle, and it is a doctrine decision rather than an edit:** which of the three loads gets cut — FILL-IN count (against RF-6 "scaffold, not narration"), probe count (against §5's teeth), or the verify pass (against the anti-bluff boundary) — each trades session rhythm for a property the spec deliberately bought. `protocols/HANDOFF_PROCESS.md` is versioned, so any of the three is a spec bump with a `check-against-spec` reconciliation, which is why the consolidation arc measured and filed rather than fixing. **Not a duplicate of [#449]**, which asks whether `PASTE_THIS.md` deserves a hard byte ceiling: that is a growth guard on one artifact, this is the authoring cost of the whole cut. (The 38,067 B above is a COLD architect cut with no supplement fold, so it is not comparable to [#449]'s 49,982 B folded v6 measurement and does not revise it.) · Done when: the operator rules which load is cut and by how much, the ruling is encoded in `HANDOFF_PROCESS.md` with a version bump + `check-against-spec` reconciliation, and a re-measured cut records the new session-side cost against the ~30-minute baseline · refs `scripts/gen_handoff.py`, `scripts/verify_handoff_probes.py`, `protocols/HANDOFF_PROCESS.md` §5 + RF-6, `.claude/commands/handoff-verify.md`, [#449], [#350] · kill-candidates: none — [#449] owns one artifact's byte ceiling and [#350] is the operator-dictated grab-bag of unrelated refinements; no open row owns the cut's session-time cost · serialize-group: handoff
