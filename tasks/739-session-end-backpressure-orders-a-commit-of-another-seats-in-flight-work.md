- [#739] [P2][S] **`session_end_backpressure` reads the working tree but not its authorship, so it orders a seat to commit or stash a CONCURRENT seat's in-flight work** - Filed on operator instruction 2026-09-12 as one of a pair of detectors that return a uniform answer because the discriminating field is absent from what they read; `[#738]` is the other, and **`[#675]` is the class they both belong to**. · **Witnessed, not theorised.** At the dispatcher seat's stop on 2026-09-12 the hook emitted: *"dirty tree: 6 uncommitted change(s) [tasks/684-…, tasks/692-…, tasks/716-… +3 more] -> expected clean at wrap -> commit or stash (git-discipline)"*. **The dispatcher had made zero repo edits in that session.** The six files were the INTEGRATOR's AX24-5 closures, in flight in the shared primary checkout on branch `docs/batch-x-integration` — five task rows flipping `status: open -> closed` plus `tasks/manifest.json`, with `[#727]` correctly excluded per AX24-5. The hook named another seat's work and instructed this one to dispose of it. · **Both offered remedies are destructive here, and the second is worse than the first.** **Commit** takes authorship of a peer's work and drops a write barrier across a half-finished closure arc. **Stash** is strictly worse: `refs/stash` lives in the **common** git directory, not the worktree's private ref space, so a stash taken here yanks the peer's in-flight closures out of the tree repository-wide, and the entry survives `git worktree remove`, `git worktree prune`, the branch delete and every other worktree- or branch-shaped cleanup — findable only by someone who thinks to look. · **The discriminating field is AUTHORSHIP, and the hook never reads it.** It reads `git status` and compares against "expected clean at wrap". Nothing in that predicate distinguishes *this session wrote these files and must bank them* from *another live session is mid-arc in the same checkout*. The one input that would refuse — who wrote the dirty lines — is the one input never read. · **The advisory posture is what made this recoverable, and it should stay.** `session_end_backpressure.py` is advisory in full since the ADR-85 amendment §A5 (no hard leg, cannot block a turn), so the seat could decline with cause and did. **A hard leg on this predicate would have forced the destructive act** — recorded here because the pressure to harden session-end hygiene is real and this is the case that must not be hardened without the discriminator first. · **Shared-checkout concurrency is the norm now, not an edge case:** a background seat and an interactive integrator working the same primary checkout is the ordinary batch shape, so the misfire is expected traffic rather than a rare race. · Done when: the dirty-tree leg **attributes before it advises** — files the current session did not touch are reported as *another seat's in-flight work, left alone* rather than as this session's hygiene debt, and the remedy offered for them is neither commit nor stash; and a **RED-first witness** proves it, with a fixture whose dirty files were written outside the session asserting the advice does NOT say commit-or-stash; and the hook's own text states that `refs/stash` is repository-wide, so a seat that stashes anyway knows the radius · refs `scripts/session_end_backpressure.py`, `.claude/settings.json` (the `Stop` wiring), `.claude/rules/git-discipline.md` (the "clean working tree at session end" rule the hook enforces), ADR-85 §A5 (the amendment that made it advisory in full), `protocols/PLAYBOOK.md` Ch8 (per-lane requirement 4 — the `refs/stash` common-directory reasoning, stated there for lanes and applying identically here), `[#738]` (the sibling detector), `[#675]` (the class) · kill-candidates: none — `[#738]` is the sibling instance in a different organ and neither subsumes the other;
