- [#863] [P1][M] **Hook processes are created SUSPENDED and never resumed -- a timeout cannot fire on a process that never started** - Corrected root cause of the 2026-09-16/17 wedges (seven sessions, 12-18 h each), operator order 2026-09-17. The orphaned hook interpreters were created SUSPENDED and never resumed: **0 s CPU, no image path, one thread in `Wait/Suspended`, parent shell dead**. The script never executed a line. **This falsifies the fix `[#808]` queued**: a bounded execution time cannot fire on a process that never started, so "give every hook a timeout" would NOT have prevented this wedge. The declared `timeout` (10 s) bounded none of them. Nineteen orphans of the prompts guard (`fleet_health.py --prompts-guard`) accumulated from **2026-09-15 10:47** onward, so it was building for two days before it wedged anything. **Measured again 2026-09-17 ~11:35, after the emergency disable landed (`33246c0a`):** 4 suspended `fleet_health.py --prompts-guard` orphans (10:11-10:15) and **1 suspended `session_end_backpressure.py` (11:02) -- a Stop hook, still wired**. So the defect is not PreToolUse-specific; any hook event can hit it. **Two different failure modes must not be merged into one:** `billing_leak_sentinel.ps1` (pid 20684, started 2026-09-16 21:04) is NOT suspended. It has 2.05 s CPU, a real image path and a `Wait/Executive` thread, so it ran and then blocked, and a timeout could in principle reach it. `[#808]`'s bound still stands for that mode, but it does not cover this one. **Ordering defect (operator statement 2026-09-17, recorded as given):** a repo-scoped disable cannot protect sessions that wedge before they can read the repo. **Measured precision, so the fix aims at the right seam:** Claude Code merges every settings layer at startup, before any hook fires: user `~/.claude/settings.json`, project `<checkout>/.claude/settings.json`, `.claude/settings.local.json`, and managed policy (none present on this box). `~/.claude.json` carries no hooks. The repo copy is therefore read from the session's OWN checkout, so the exposure is a lane worktree branched before the disable merged, which keeps the old hooks (settings files are watched and hook edits reach a running session, per the Claude Code settings docs). The hanging SessionStart hook (`billing_leak_sentinel.ps1`) was wired ONLY in the repo copy, never in the user-level file, whose sole SessionStart hook `surface-closures.ps1` showed zero orphans. **Widened 2026-09-17 by operator order after a session wedged in Stop hooks 2/3:** ALL hook families are disabled on BOTH surfaces, with the user-level `~/.claude/settings.json` FIRST (`disableAllHooks: true`; `disableAllHooks` is resolved after settings precedence, so a user-level true holds in every checkout whose project copy does not set it false). **TEMPORARY, NOT SETTLED:** the emergency disable removed the ADR-77 immutable-transcript guard as collateral. That is a real safety loss, accepted ONLY until this row has a mechanism, and re-arming the transcript guard is part of closing it. · Done when: (1) the client's own spawn path is read and it is established WHY a hook process is created suspended on this platform (Windows, Claude Code hook commands through a POSIX shell): name the API call and flag or the job-object or resume step that is skipped, with a reproduction or a cited source, never an inference from symptoms; (2) RED-first: a watchdog detects a hook process with **zero CPU after N seconds** and **kills its whole process tree**, witnessed against a deliberately suspended child; the kill is RECORDED to a durable named surface (hook id, pid, age, session id) and surfaced at SessionStart, never silent; (3) the watchdog is proven to catch the suspended mode AND `[#808]`'s timeout is proven to catch the ran-then-blocked mode, as two separate witnesses; (4) the ADR-77 transcript guard, the prompts guard and the billing-leak sentinel are re-armed only under (2), each with its posture stated, and the `//hooks-EMERGENCY-DISABLED-2026-09-17` key in `.claude/settings.json` is superseded in the same act · refs `.claude/settings.json` (`//hooks-EMERGENCY-DISABLED-2026-09-17`), `scripts/fleet_health.py`, `scripts/session_end_backpressure.py`, `scripts/billing_leak_sentinel.ps1`, `scripts/hooks/block_immutable_edits.py`, merge `33246c0a`, `[#808]`, `[#865]` · kill-candidates: none -- `[#808]` keeps the ran-then-blocked bound and must now name this row as the suspended-mode half rather than claim the whole wedge · source: operator order 2026-09-17, process census 2026-09-17
