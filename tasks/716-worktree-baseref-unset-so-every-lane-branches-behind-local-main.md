- [#716] [P1][S] **`worktree.baseRef` is unset, so every lane branches from `origin/main` and starts behind local `main` -- the mandatory step-0 sync exists to paper over it** - Third of AX7-3's three measured dispatch defects, each filed as its own FILE row with a RED-first test. Carried at `docs/intake/2026-09-11-tech-batch-x-roster.md` (intake 93) Part 5. · **SETTING NAME VERIFIED BY THIS LANE, because AX7-3 asked for exactly that** ("CC verifies the setting name") rather than asking for it to be taken on trust. The setting is `worktree.baseRef`. It is **unset** in this repo's `.claude/settings.json` and in the operator's user settings, both checked. Its documented values are `fresh` -- the DEFAULT, which branches from `origin/<default-branch>` -- and `head`, which branches from the current local HEAD. AX7-3's diagnosis holds: unset means `fresh` means `origin/main`. · **ONE PRECISION THE FIX NEEDS, and it is why this row says more than "set it".** AX7-3 asks that baseRef "points at local `main`", and the available value is `head` -- the DISPATCHING SESSION's current local HEAD, not literally `main` HEAD. The two coincide only when the dispatcher is itself on `main`. A dispatcher sitting on a feature branch would, with `head`, seed every lane from THAT branch instead, which is a different defect wearing the fix's clothes. So the Done-when asserts the PROPERTY -- a lane's base equals `main` HEAD at dispatch -- and lets the setting be whatever makes the property true. · **The cost is measured on this lane itself, which is as close to a reproduction as a row gets.** This lane branched behind and synced TWICE: once at step 0 as its contract mandates, and again mid-run when batch W's `a3374b70` landed. Each sync is a merge commit that exists only because the base was wrong. · **THE STEP-0 SYNC STAYS MANDATORY UNTIL THIS LANDS**, and AX7-3 says so in as many words. That is the standing consequence this row carries: no lane contract may drop its step-0 sync on the grounds that baseRef is being fixed -- it drops only once the test below is green. The reason is not ceremony: a generator run against a base that lags `main` silently DROPS rows that exist on `main`, and the dropped row looks like a clean regeneration. · Done when: a lane's base equals `main` HEAD at dispatch, asserted by a TEST rather than by the setting's value -- so a dispatcher on a non-`main` branch cannot satisfy it accidentally; the RED-first witness FAILS against today's unset configuration before the fix makes it green; and the mandatory step-0 sync is retired from the lane-contract template only in the same change that makes that test green · **Done-when authored by the filing lane** from AX7-3's clause, with the `head`-versus-`main`-HEAD precision added from the verification AX7-3 asked for · refs `docs/intake/2026-09-11-tech-batch-x-roster.md` (intake 93, Part 5 AX7-3), `to-cc/AMEND-BATCH-X-ROSTER-007.md` AX7-3, `to-cc/QUESTION-path-registry-2026-09-11.md` (fix 3 of the three), `.claude/settings.json` (checked: no `worktree.baseRef` key), `[#715]` (the path row these three ship first for), `[#716]`'s siblings `[#717]` and `[#718]`, `[#429]` (worktree provisioning is not portable across the fleet) · kill-candidates: none -- `[#429]` owns whether worktree provisioning works across MACHINES and is silent on which ref a lane branches from; no open row names `baseRef` · source: `to-cc/AMEND-BATCH-X-ROSTER-007.md` AX7-3, id assigned by the operator instruction of 2026-09-11, filed by lane `lane-x-000-batch-x-roster-lands`
