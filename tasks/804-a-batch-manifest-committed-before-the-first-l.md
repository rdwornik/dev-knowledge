- [#804] [P1][M] **No committed batch manifest, no dispatch -- and task-id allocation reads the manifest, not the local maximum** - Operator ruling 2026-09-16, accepting the batch-AA integrator's root cause as the batch's real finding. **Batch AA had no committed manifest**, so nothing allocated ids centrally, and one absence produced every collision the integration then had to hand-resolve: FOUR task-id collisions resolved at integration (`#787`/`#788` lane-vs-main, `#790` aa-13-vs-aa-runtime, `#792` aa-14-vs-aa-runtime -- aa-runtime's four landed as `[#800]`-`[#803]`) and a FIFTH still pending on the live aa-12 branch (its own `tasks/793-*` against main's `[#793]`), TWO quality-register id collisions (`QR-AVAIL-009`, `QR-RES-002`), ONE JOURNAL day-letter collision (aa-runtime's two dispatcher entries against the integrator's 2026-09-15 letters), and an UNARMED integration exemption (the ADR-110 lane exemption reads the manifest, so with none the integration branch ran as an ordinary branch). Two renumbers in one day, and each one also rewrote every citation of the renumbered id. · **WHY A CONVENTION IS NOT ENOUGH.** ADR-110 §3 already says the manifest is committed AT DISPATCH; batch AA dispatched six lanes without one and nothing noticed until merge. A rule that is only checked at integration is checked after all the damage it prevents has been done. · **THE ALLOCATOR HALF.** Every lane allocated `max(local ids) + 1`. From a worktree that maximum cannot see a sibling's unpushed branch (`[#788]`'s measured instance), so the answer every surface agrees on is wrong by construction. The manifest is the only surface that exists before any lane runs, so it is the only one that can hand out disjoint id BLOCKS (task ids, QR ids per attribute, JOURNAL day letters) per lane. The integrator seat had to fake this on 2026-09-16 by reserving 800-805 for itself and leaving 794-799 to the still-live aa-12, recorded only in JOURNAL 2026-09-16 (d) -- a manual manifest with no reader, which cannot stop aa-12 taking 794 or anything else. · Done when: (1) the dispatch verb REFUSES to boot a batch's first lane unless `batch_manifest` for that batch is committed on `main` (not merely present in a worktree or the prompts dir), and the refusal names the missing file; (2) the manifest carries a per-lane id block for task ids, and the id allocator a lane uses reads its block from the manifest and refuses an id outside it -- the local maximum is never consulted; (3) a RED-first witness reproduces batch AA's shape: two lanes started from the same base both allocate, and the test asserts disjoint ids; (4) QR-register ids and JOURNAL letters are either given blocks too, or this row records by ruling why they are not · refs `[#788]` (the local-maximum allocator defect, measured), `[#574]` (manifest EMISSION by gen_lane_contract), `[#793]` (the withdrawn-lane half of the same batch), ADR-110 §3, `scripts/batch_manifest.py`, JOURNAL 2026-09-16 · kill-candidates: `[#788]` -- this row's Done-when (2) is `[#788]`'s fix stated as the manifest's reader; close `[#788]` into this row when (2) lands, or keep it if the allocator ships before the refusal. `[#574]` stays open: emitting a manifest is not refusing to dispatch without one · source: operator ruling 2026-09-16 on the batch-AA integration report
