- [#821] [P1][M] **`dispatch_drift` validates the repo against one machine's local deployed state, not the repo itself** - THE SYSTEMIC FINDING, 2026-09-16, lane-ab-810 -- filed P1 because the mechanism it names is general, not limited to this one incident. `dispatch_drift` (`scripts/audit_checks/check_dispatch_drift.py` + `scripts/dispatch_drift.py`) is a COMMIT-tier pre-commit hook that resolves every literal command in PLAYBOOK.md Ch8's dispatch table via `Get-Command` on the **local host**. For 9 days, `.dev-knowledge` main's Ch8 row 5 (`Harvest-Codespace <codespace-name> -Lane <slug>`) named a function that existed ONLY in this one operator's `~/.dispatch-helpers/` deployed copy -- win-tooling's own tracked `main` did not have it (`origin/worktree-lane-u-000-dispatch-receipt-is-work`, merged 2026-09-16, see `[#819]`). `dispatch_drift` passed green on every commit to `.dev-knowledge` main during that window, on this machine, purely because this machine's local deployment happened to carry code the win-tooling repo itself had not yet accepted. The lane's own `SESSION` file already warned of this exact hazard in its "ordering hazard for the integrator" paragraph: re-deploying win-tooling from a plain `main` checkout would wedge every hub commit relying on the row -- a warning that sat unactioned because nothing forced anyone to read it before green stayed green. **A gate that passes by accident of local deployment is worse than absent, because the green is meaningless** -- it does not test what it claims to test (that the repo's own dispatch table is resolvable), it tests what happens to be true of one operator's `$HOME` on one day. The gate's own docstring already partially names this limitation but treats it as a known, accepted constraint rather than a defect to close. · Done when: `dispatch_drift`'s resolution step can distinguish "resolvable because win-tooling's own tracked source provides this" from "resolvable only because this machine's local deployed copy happens to carry it" -- at minimum, a CI/container-tier run (already the gate's documented "warn, never green-by-skip" posture per its own docstring) is wired to actually run on some cadence so a Ch8 command absent from win-tooling's tracked `main` cannot pass silently on developer machines for 9 days; RED-first witness: a Ch8 command present in local deployment but absent from win-tooling's tracked source should fail the gate, not pass it · refs `scripts/audit_checks/check_dispatch_drift.py`, `scripts/dispatch_drift.py`, `protocols/PLAYBOOK.md` Ch8 row 5, `.dev-knowledge` JOURNAL 2026-09-07, `H:\My Drive\CLAUDE PROMPT DIR\to-browser\archive\2026-09-07\SESSION-lane-u-000-dispatch-receipt-is-work.md` ("ordering hazard for the integrator"), `[#819]`, `[#820]` · kill-candidates: none -- newly filed · source: operator ruling 2026-09-16 (third ruling, "the most important thing you found"), lane-ab-810
