- [#675] [P2][M] **Manifest tooling reads a heterogeneous node list with a bare `.get` default, so every node of the other shape reads as the default** - **THE CHECK PASSES BECAUSE IT CANNOT SEE ITS OWN CASE - the seventh witnessed instance in this window.** `tasks/manifest.json` carries a **heterogeneous** node list: a node is either `{"task": N, "file": ...}` or `{"prose": ...}`, and **no node carries a `type` key at all**. Any reader that reaches for `node.get(key, default)` therefore gets the default for every node of the OTHER shape - not an error, not a miss, but a *plausible value* - so the read succeeds over the wrong half of the list. **The failure is silent at every layer that could have caught it:** the script **exits 0**; `validate_backlog` **passes**, because the BACKLOG view it validates is well-formed; and `manifest.json` is **structurally valid**, because `manifest_node_problem` and `manifest_sequence_problems` both check node SHAPE and a defaulting read is not a shape defect. The manifest is semantically wrong while every gate that looks at it is green. **Caught this session only by reading the printed indices by eye** - the same detection mode, and the same absence of a mechanism, that produced `[#673]` and `[#674]` at the batch-V seat close earlier in this same session. **The in-repo sites are currently correct, and that is the trap:** `gen_task_tree.py` discriminates by key PRESENCE (`if "task" in node`) at every traversal - `reassemble_from_tree`, `render_view`, `_task_count` and `_scan_source` - so the corpus offers no failing example, no test fixes the discipline in place, and the next ad-hoc reader written against this list has nothing to trip over. · **THE EIGHTH INSTANCE IS THIS ROW'S OWN FILING, and it is at PROCEDURE level.** Filing a ONE-LINE BACKLOG row provisioned a worktree that then had to be torn down. The lane apparatus fires on the CONTRACT, never on what the contract actually writes, so a task that mutates no code still pays the full provision-and-cleanup round trip - branch, seed, commit, merge, prune, remove, verify. The check that cannot see its own case is here the PROVISIONING DECISION itself: nothing between the contract and the worktree ever asks how large the change is, so the one input that would have refused is the one input never read. Same class as the defaulting read above, one layer up - a mechanism returns a uniform answer because the discriminating field is absent from what it looks at. **Teardown is half the act and it is not the author's to skip; it is the merger's to complete.** · **THE NINTH INSTANCE, measured the same day and one turn later: a ONE-FILE, TEXT-ONLY row merged OUT-OF-BATCH cost ~12 minutes and TWO merges.** Three mechanisms compounded, and none of them can see the size of what it is deciding about. **(a) The ADR-110 anchor exemption is bound to “an open batch”, not to work class.** Batch V had closed 8/8 and no manifest declared an open batch, so a single-file text change took **no exemption at all** — the identical posture a twelve-lane code arc would take. The discriminating field is the batch's state; the change's nature is never read. **(b) The anchor rule is SELF-REFERENTIAL, so two commits is the structural minimum.** A JOURNAL entry cannot name a SHA that does not exist when the entry is authored, so an arc that must anchor its own merge needs commit 1 (the artifact) and commit 2 (the entry naming it) — and a one-file row has no natural artifact commit, which is precisely the single-commit-branch trap. The minimum is imposed by the rule's shape, not by the work. **(c) The apparatus fires on the CONTRACT, never on what the contract writes** — the eighth instance restated at the merge end rather than the provisioning end. Each mechanism is individually correct; together they price a two-line documentation edit at a full integration arc. · Done when: node access in manifest tooling is **type-discriminated** (`node["type"] == "task"`) rather than resolved by a defaulting read - which requires the node schema to carry the discriminator it currently lacks, so the schema change and its regeneration are in scope; and **one test FAILS when a heterogeneous node list is read with a bare `.get` default** - a RED-first witness per ADR-108 section B, proven to bite BEFORE the fix makes it green, and still RED if discrimination is later weakened back to a defaulting read; and a **SIZE GATE refuses worktree provisioning for a contract whose only writes are `BACKLOG.md` / `tasks/`**, so a filing-only task never provisions a lane at all; and a **text-only diff takes a SINGLE-COMMIT path with its anchor in the same commit**, which requires the anchor predicate to admit an entry that names its own commit for that class — measured against the baseline the operator froze 2026-09-12, which REPLACES the earlier `12 -> under 2` target: **84 min wall = 11.3 targeted tests + 72.7 residual ceremony (itemised views ~90 and ~63, nothing measured today)**. The parenthesis is part of the baseline and not commentary -- the two itemised views disagree with each other and with the wall figure, and no measurement was taken on the day it was frozen -- so every report against it NAMES THE SPREAD rather than hiding it.
