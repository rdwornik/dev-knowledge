- [#681] [P2][S] **`protocols/OPERATOR-INTERFACE.md` documents a paste sentinel and a model-switch line the live organs no longer emit, so the file is present, cited, and wrong on both** - **Witnessed 2026-09-10 while striking six of seven interface behaviours from the 2026-09-10 architect supplement's Q7 as "already documented".** Six strikes were correct and two of them left a residue, which is the finding: **being documented is not being correct**, and a strike-on-presence check cannot tell the two apart. Two sites, one class, filed as one row because one read of the file produces both and one edit closes both. · **Site 1 - the sentinel.** `OPERATOR-INTERFACE.md:143-145` documents that `PASTE_THIS.md` "ships a terminal `=== END OF PASTE ===` sentinel so a truncated one is visible on sight". The live assembler emits the sentinel **carrying counts** - `scripts/assemble_paste.py` wrote `=== END OF PASTE — 5 sections · 53761 bytes ===` at the 2026-09-10 cut. The documented form is a strict prefix of the live one, so a reader who trusts the file and matches the documented string exactly finds nothing, while the counts - the part that makes a truncation detectable **by arithmetic** rather than by eye - are undocumented and therefore uncontracted. The supplement's own author relied on the counts and cited them as a behaviour the file does not name; they were right about the file and the strike was right about the behaviour. · **Site 2 - the model-switch line.** `:165` carries both strings verbatim (`ROUTINE — Opus is enough` / `RULING AHEAD — Fable (est. ~N k tokens: <files>)`), so the *format* is documented. What neither form carries is an explicit **stay / return / switch** verb: the line names a model and a cost and leaves the operator to infer whether he is being asked to switch now, to stay where he is, or to switch back after the act. **The operator reported this ambiguity in this window in those terms** - the supplement records that he "said plainly he could not tell the two apart; the tag was overloaded". A documented format that is reliably misread is a defect in the format, not in the reader. · **Why this is a mechanism and not two typos:** `OPERATOR-INTERFACE.md` is prose describing organs that ship their own strings, and **no organ reads the prose**. `assemble_paste.py` can change its sentinel and the browser contract can change its switch line with nothing failing, because the coupling is a human promise. This is the same shape as the class the 2026-09-10 window named `declared enforcement without enforcement`, applied to the interface file rather than to a gate. · **The adjacent rows do not absorb it:** `[#679]` owns the return path from a ruling to the `QUESTION-*.md` it answers and `[#680]` owns generated bundle files that no row claims - both are about artifacts nothing links, whereas this is a description that no longer matches the thing described. · Done when: `OPERATOR-INTERFACE.md` states the sentinel in the form the assembler actually emits, including what the counts are for, and the model-switch line carries an explicit stay/return/switch verb; **and the sentinel stops being a prose promise** - the documented form is derived from or checked against `assemble_paste.PASTE_BYTE_CEILING`'s neighbourhood in the same module that writes it, so a change to the emitted string fails something; and **one test FAILS when the documented sentinel and the emitted sentinel disagree** - a RED-first witness per ADR-108 section B, proven to bite before the check makes it green; and the 2026-09-10 `5 sections · 53761 bytes` cut is the fixture · refs `protocols/OPERATOR-INTERFACE.md` (:143-145 the sentinel, :165 the switch line), `scripts/assemble_paste.py`, `docs/handoffs/2026-09-10-dev-knowledge-architect/SUPPLEMENT.md` (the transcription note recording both residues), `[#679]`, `[#680]`, ADR-108 · kill-candidates: none - no open row names `OPERATOR-INTERFACE.md` as its subject; `[#679]` and `[#680]` are the adjacent mechanisms and own different file classes · **Archived annotations:** `tasks/archive/681.md`
