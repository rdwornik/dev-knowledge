Carried at `docs/intake/2026-09-11-tech-batch-x-roster.md` (intake 93) Part 8. · **It is a different defect class from the rest of the red baseline, which is why AX8-3 splits it out.** The baseline reds fail the same way every run; this one passes when run alone and fails under `-n auto`, so it is an ORDER- and PROCESS-dependent failure rather than a stable one. Merging it into the baseline count would let a genuinely intermittent test be dispositioned as a known-red constant, which is the wrong verdict. · **The mechanism, and it is a trap worth stating in general form.** An identity assertion over a module-level `frozenset` holds within one process because the constant is interned to one object; under xdist each worker imports the module afresh, so an assert on IDENTITY rather than EQUALITY compares objects from different import instances. A spec-derived constant makes it worse: the value is computed at import, so two workers can hold equal-but-distinct objects and the identity assert is simply wrong about what it is testing. · **The fix is almost certainly the assertion, not the parallelism.** Identity is rarely the property under test; equality is.
