- [#749] [P1][M] **Two lanes may be dispatched for the same row under different slugs, because every duplicate check compares slugs rather than rows** - Witnessed live on 2026-09-13 in batch X4, slots 3 and 3' (`docs/audits/2026-09-13-technical-batch-x4-manifest.md` sections 4.1, 4.2 and finding 2). `lane-x-675-instrument-holes` fired at 13:20:40 and `lane-x-675-instrument-fixes` at 13:30:11 - two sessions, two worktrees, two branches, **one row `[#675]`**. · **Every existing guard compares the wrong key.** `scripts/seat_refusals.py::refuse_lane_ceiling`'s DUPLICATE leg catches an identical slug repeated in one plan; two *different* slugs are two different lanes to it. `scripts/validate_branch_naming.py::LANE_BRANCH_RE` validates the grammar `lane-<letter>-<digits>-<slug>` and is indifferent to how many branches share the `<digits>`. `scripts/batch_manifest.py::freeze_manifest_contract_agreement` asserts **set equality** between manifest slugs and contract slugs, so a manifest naming both duplicates agrees with contracts naming both duplicates and the check passes. `scripts/single_flight.py` claims on the lane identity, not the row. **The row id is parsed by the grammar and then discarded by every consumer.** A live fixture already demonstrates it: `lane-x-734-retire-stage` and `lane-x-734-retire-stage-2` pass the ceiling check cleanly. · **The cost is a silent collision, not wasted tokens.** Task ids are allocated sequentially from the tree the allocating seat can see, and a lane cannot see a sibling branch - so two lanes filing the same findings pick the **same ids**. Batch X4's slot 3 had "THREE rows filed, one per hole" as Done-contract item 1 while the integrator had already filed `[#742]`, `[#743]`, `[#744]` for exactly those holes; had slot 3 run to completion, two trees would have carried different bodies under the same three ids and the duplicate would have landed at integration with nothing flagging it. The dispatcher caught this **by reading the primary tree incidentally** (finding 2), which is not a mechanism. The wasted tokens are the cheap part: 15 Opus messages, 7,147 output, 1,129,174 cache-read. · **The refusal must not forbid a deliberate re-cut** - that is precisely what batch X4 did next, and correctly, as a NEW CONTRACT rather than a mid-flight message (ADR-110 per-lane requirement 1). The predicate is an **undisposed** duplicate: a row already carrying a live or completed lane in the open batch. Disposing of the first lane (stopped, torn down, recorded) must clear the way for the second, or the refusal blocks the one correct response to its own finding. · **Where the row-to-lane map has to come from:** `scripts/batch_manifest.py::manifest_lane_slugs` (line 659) already reads the open batch's declared slugs, and `open_batches` (line 384) resolves which batch is open; the row id is the `<digits>` group the slug grammar already isolates. Do not glob the transport - `seat_refusals.py:371-385` records why (superseded re-cuts on the transport produce false collisions, measured 2026-09-12), and this refusal would manufacture exactly that false positive on every legitimate re-cut. · Done when: a contract whose row already has a live or completed lane in the open batch is REFUSED at step 0, with the ROW and BOTH slugs in the message; a lane with a **recorded disposition** does not trigger it, and a test asserts that, so a deliberate re-cut stays possible; the map is built from `manifest_lane_slugs` plus the live worktree set rather than from the transport directory; **the RED-first witness already exists and is the acceptance test** - `tests/test_dispatch_refusal_holes_x4.py::test_a_second_lane_for_a_row_that_already_has_one_is_REFUSED`, currently `xfail(strict=True)`, so the implementing lane MUST remove the marker or go RED on the XPASS; and the existing `lane-x-734-retire-stage` / `-stage-2` fixture is re-read in the same pass, since it is either a second instance of this defect or a deliberate exception that must be recorded as one · **Filed by the integrator seat at batch X4 integration**, from the operator's instruction of 2026-09-13 · refs `scripts/seat_refusals.py` (`refuse_lane_ceiling` line 248, DUPLICATE leg lines 274-282, the transport-glob warning lines 371-385), `scripts/batch_manifest.py` (`manifest_lane_slugs` line 659, `open_batches` line 384, `freeze_manifest_contract_agreement` line 683), `scripts/validate_branch_naming.py` (`LANE_BRANCH_RE` line 85), `scripts/single_flight.py` (claims on lane identity, not row), `tests/test_dispatch_refusal_holes_x4.py`, `docs/audits/2026-09-13-technical-batch-x4-manifest.md` (sections 4.1, 4.2, finding 2 - the witness), `[#748]` (the sibling refusal from the same batch), `[#530]` (single-flight, the adjacent duplicate-dispatch guard), ADR-108 (section B, RED-first), ADR-110 (per-lane requirement 1 - a correction re-enters as a new contract) · kill-candidates: none -- `[#530]` owns single-flight claiming on the lane identity and stays open;
