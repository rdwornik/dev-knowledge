- [#766] [P2][M] **The session boot payload has a byte budget on one file and none on the whole -- every tool, command and skill description is paid at startup** -- AJ M04 L04 measures the cost of the thing this repo does not measure: *"mamy część narzędzi czy MCP Server, które deklarują bardzo dużą liczbę narzędzi, na przykład 50 czy 100 narzędzi. Każdy z tych narzędzi ma swój opis, ma opis struktury wejściowej i wyjściowej, i efekt jest taki, że taki jeden MCP Server potrafi zjeść kilkadziesiąt tysięcy tokenów na starcie serwera"* -- one server declaring 50-100 tools, each with its description and its input and output schema, eats tens of thousands of tokens at startup (`AJ_M04_transkrypcje.md:702-706`, sha256 `ebd8753f...`; verdict NORM, verified). · **What is gated today, and it is exactly one file.** `tests/test_claude_md_byte_cap.py` holds `CLAUDE.md` to 24,576 B and says why in the file's own header -- *"a line count is gameable by density, and bytes are what a session pays"*. That reasoning is right and its scope is one file. · **What is NOT gated, and all of it loads at session start.** `AGENTS.md` (imported by `CLAUDE.md` via `@`), the two `@`-imported generated fragments `.claude/generated/commands-repo.md` and `.claude/generated/recent-adrs.md`, `.claude/methodology-roster.md`, `.claude/CLAUDE-FLOOR.md`, the repo-level and user-level command and skill rosters the picker surfaces, and the `SessionStart` hook output. Each is separately justified and nothing measures their sum. · **Two OPEN rows both ADD to the unmeasured total**, which is why this is worth filing now rather than after: `[#728]` generates one skill per question-answering organ in `ecosystem/organ-index.md`, and `[#729]` adds MCP tool schemas -- the precise payload M04 is measuring. Neither row is wrong; neither has a budget to spend against. · **This is NOT a restatement of `[#589]`.** `[#589]` bars the `BACKLOG.md` VIEW at 72,000 B, and `BACKLOG.md` is not read at session start -- it is a document a session opens on demand. This row is about the boot payload, a different corpus with a different reason to be bounded. · Done when: the session-start payload is enumerated as a named set rather than inferred, its total size is measured by a check that runs in CI or at commit time, and a budget is declared with the same explicit reasoning `test_claude_md_byte_cap` already carries -- so that a row proposing a new always-loaded surface has a number to argue against instead of a silence · refs `AJ_M04_transkrypcje.md:702-706` (the measured cost, quoted above), `docs/audits/2026-09-15-technical-lane-z-10-aj-m04-evidence/LOCATOR-VERIFICATION.md` (item 42, verified), `tests/test_claude_md_byte_cap.py` (the one budget that exists, `3721f4fc`), `CLAUDE.md` §1 (the first-read set), `[#728]` (adds generated skills to the payload), `[#729]` (adds MCP tool schemas to the payload), `[#589]` (the BACKLOG view bar -- a different corpus) · kill-candidates: none -- `[#589]` bounds a document read on demand rather than the boot payload and survives this row's closure unchanged; `[#728]` and `[#729]` are CONSUMERS of the budget this row asks for and would each be easier to rule on once it exists, so folding either into this row would lose the thing being budgeted · source: batch Z lane z-10, AJ M04 first pass, `[#765]`
