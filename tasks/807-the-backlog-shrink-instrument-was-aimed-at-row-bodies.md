- [#807] [P2][S] **The backlog-shrink instrument was aimed at the wrong corpus: `archive_row_body` relocates task-file bodies, the view renders manifest prose** - Operator ruling 2026-09-16, on the browser seat's measurement of `BACKLOG.md`. · **The mechanism, read from the code.** `scripts/gen_task_tree.py::render_view` emits every `{"prose": ...}` node of `tasks/manifest.json` verbatim plus ONE `project_row` line per task (band, title, pointer); no body text reaches `BACKLOG.md`. `scripts/archive_row_body.py` relocates clauses inside `tasks/<id>-*.md` BODIES. So it cannot move the view by one byte, by construction -- and the 2026-09-14 paired run proved it: 60 rows relocated, `BACKLOG.md` 91,514 B before and 91,514 B after (`docs/audits/2026-09-14-technical-lane-y-754-backlog-to-bar-evidence.md`). · **Where the view's mass actually was.** At `3d435d36`, 99,961 B = 61,436 B of 361 row lines + 38,525 B (38.5%) of manifest prose; the `[E8]` ARC-5 block alone carried 25.5 KB of prose and no row. That prose is DATA, removable by a manifest edit: this row's own commit relocated ten blocks verbatim to `docs/audits/2026-09-16-technical-backlog-view-narration-relocated.md`, a pointer at each site, touching no row. · **Two rows repeated the false explanation and are corrected in the same commit:** `[#731]` (planned the view drain through `archive_row_body.py`) and `[#754]` (called the 72,000 B gap a row-count act, not a narration drain). · **The finding this pass uncovered outranks the pass.** Manifest prose has been FLAT since the 2026-09-01 re-baseline (37,893 -> 38,525 B) while row lines nearly doubled (32,383 -> 61,436 B); on 2026-09-16, before this commit, 10 rows entered the view and none left. The relocation is a one-time recovery against a growth rate that refills it; the defect is the filing-to-closing ratio, which is `[#731]`'s closure-budget clause. · Done when: (1) the view-size report in `scripts/gen_task_tree.py` (`view_problems` or the regen summary) states the split -- row-line bytes vs manifest-prose bytes -- so an overage names the corpus that grew; (2) RED-first tests in `tests/test_gen_task_tree.py` pin both halves of the mechanism: a body-only relocation leaves the rendered view byte-identical, and removing a prose node shrinks it; (3) no open row or protocol names `scripts/archive_row_body.py` as a remedy for `BACKLOG.md` size · refs `scripts/gen_task_tree.py` (`render_view`, `project_row`), `scripts/archive_row_body.py`, `tasks/manifest.json`, `BACKLOG.md`, `docs/audits/2026-09-16-technical-backlog-view-narration-relocated.md`, `docs/audits/2026-09-14-technical-lane-y-754-backlog-to-bar-evidence.md` (the paired run), `[#589]` (the view bar), `[#731]`, `[#754]`, `[#612]` (owns `archive_row_body.py`, sound for its own corpus) · kill-candidates: none -- `[#731]` and `[#754]` are corrected in place rather than superseded, and `[#612]`'s mechanism is correct for task bodies · source: operator ruling 2026-09-16
