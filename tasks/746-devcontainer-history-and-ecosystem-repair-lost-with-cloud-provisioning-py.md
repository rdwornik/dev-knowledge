- [#746] [P1][M] **Devcontainer history-sufficiency (B1) and ecosystem-registration (L5) repair, lost with `scripts/cloud_provisioning.py`** — `scripts/cloud_provisioning.py` was retired at `3c9418cc` ([#734]) for being an unreferenced census orphan, but its two live consumers were `.devcontainer/provision.sh`'s `leg2b_history`/`leg5_ecosystem`/`gate()` (six call sites, [#664] removed them as dead callers rather than restoring the module) and it was never a duplicate of anything — no other surface implements what it did. **What was actually lost, not "restore the module":** (1) **B1 history sufficiency** — a cloud clone can be unshallow (L2) and still lack the REFS a first-parent-spine-walking instrument reads (the 2026-08-19 proof lane's container had 5329 commits and no local `main`); `cloud_provisioning.py history [--repair]` asserted every ref in `.devcontainer/provisioning.yaml`'s `required_refs` resolves and is current with origin, and repaired it by fetching + fast-forwarding — REFUSING (never force-updating) a ref that had diverged or reached the remote tip only off the first-parent spine. (2) **L5 ecosystem self-registration** — `audit.py health` counts `ecosystem/*/state.yaml`, that glob is gitignored, so a fresh container (no primary checkout to copy from, unlike `scripts/worktree_seed.py` on the workstation) always reports "repos registered (none)" and fails health; `cloud_provisioning.py ecosystem [--repair]` ran `audit.audit_repo` + `audit.save_state` against the container's own checkout to self-register it. **Measured cost of the gap, not assumed:** with the module gone and its callers not yet removed, every one of the six call sites exited 2 ("can't open file"), which `provision.sh`'s own `case`/`|| die` handling treated as failure — so a fresh `bash .devcontainer/provision.sh` died at `leg2b_history`, and `--gate` (wired to `postStartCommand`) refused every container start, from `3c9418cc` until [#664] landed, each with a "re-provision" message that could not succeed. [#664]'s removal stops that crash but does not restore either leg — a container provisioned today gets no B1/L5 assertion at all, silently, which is the gap this row tracks. · **AMENDED 2026-09-15 (lane-z-746) — P2 -> P1, because the gap stopped being silent and now REFUSES the container.** Witnessed on the operator's probe codespace `lane-z-substrate-probe` (created 2026-09-14 23:36Z off `-b main`), `/workspaces/.codespaces/.persistedshare/creation.log`: the image snapshot served a source tree at `1059d04d` (2026-09-01, **1401 commits behind**), `refresh_source_tree` fast-forwarded the TREE to `b5270d63` — and the already-running `bash` went on executing the SNAPSHOT's pre-[#664] `provision.sh`, whose `leg2b_history` still called the retired module: two `can't open file '.../scripts/cloud_provisioning.py': [Errno 2]`, then `[provision] REFUSED: B1 the history guard could not look (exit 2)`, then `postCreateCommand ... failed with exit code 1` -> `Container creation failed.` -> `Creating recovery container.` So [#664]'s removal does NOT stop the crash for a codespace created from an image snapshot older than `3c9418cc`, and `prebuild.trigger: on_configuration_change` means that snapshot refreshes only when `.devcontainer/devcontainer.json` or its Dockerfile changes. **TWO defects, not one:** (a) this row's B1/L5 gap, and (b) `provision.sh` mutating the very file it is executing — `.devcontainer/provisioning.yaml` claims `refresh_source_tree` "makes the image's own age irrelevant", which is now MEASURED FALSE for `provision.sh` itself.
