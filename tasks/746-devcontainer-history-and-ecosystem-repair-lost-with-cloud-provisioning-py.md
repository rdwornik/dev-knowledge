- [#746] [P2][M] **Devcontainer history-sufficiency (B1) and ecosystem-registration (L5) repair, lost with `scripts/cloud_provisioning.py`** — `scripts/cloud_provisioning.py` was retired at `3c9418cc` ([#734]) for being an unreferenced census orphan, but its two live consumers were `.devcontainer/provision.sh`'s `leg2b_history`/`leg5_ecosystem`/`gate()` (six call sites, [#664] removed them as dead callers rather than restoring the module) and it was never a duplicate of anything — no other surface implements what it did. **What was actually lost, not "restore the module":** (1) **B1 history sufficiency** — a cloud clone can be unshallow (L2) and still lack the REFS a first-parent-spine-walking instrument reads (the 2026-08-19 proof lane's container had 5329 commits and no local `main`); `cloud_provisioning.py history [--repair]` asserted every ref in `.devcontainer/provisioning.yaml`'s `required_refs` resolves and is current with origin, and repaired it by fetching + fast-forwarding — REFUSING (never force-updating) a ref that had diverged or reached the remote tip only off the first-parent spine. (2) **L5 ecosystem self-registration** — `audit.py health` counts `ecosystem/*/state.yaml`, that glob is gitignored, so a fresh container (no primary checkout to copy from, unlike `scripts/worktree_seed.py` on the workstation) always reports "repos registered (none)" and fails health; `cloud_provisioning.py ecosystem [--repair]` ran `audit.audit_repo` + `audit.save_state` against the container's own checkout to self-register it. **Measured cost of the gap, not assumed:** with the module gone and its callers not yet removed, every one of the six call sites exited 2 ("can't open file"), which `provision.sh`'s own `case`/`|| die` handling treated as failure — so a fresh `bash .devcontainer/provision.sh` died at `leg2b_history`, and `--gate` (wired to `postStartCommand`) refused every container start, from `3c9418cc` until [#664] landed, each with a "re-provision" message that could not succeed. [#664]'s removal stops that crash but does not restore either leg — a container provisioned today gets no B1/L5 assertion at all, silently, which is the gap this row tracks. · Done when: `.devcontainer/provision.sh` (or a documented successor) again asserts — and can repair — both (1) that every ref named in `.devcontainer/provisioning.yaml`'s `required_refs` resolves and is current with origin along the first-parent spine it is walked on, and (2) that at least one repo is registered under `ecosystem/` in a fresh container; proven on a fresh Codespaces container the way `docs/audits/2026-08-19-technical-554-proof.md` proved the original four legs · refs [#554] (the four-leg parent row — L1-L4 only, predates the 2026-08-21 B1/L5 addition and was never updated to carry it), [#734] (retired the module), [#664] (removed the dead callers, wrote this row), `.devcontainer/provisioning.yaml`, `docs/audits/2026-08-19-technical-554-proof.md`, `docs/audits/2026-08-21-*` (B1/L5 addition, terra HIGH rounds) · kill-candidates: none — no open row owns cloud-provisioning history/ecosystem repair; [#554] covers only the original four legs and was never amended for the 2026-08-21 B1/L5 addition, so it cannot be superseded by this row and does not supersede it either · source: [#664]'s lane, filed per its Done-contract item 4 ("ONE row for what provisioning's history/ecosystem repair actually needs, not a row that says 'restore the module'")
