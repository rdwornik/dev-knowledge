- [#891] [P1][M] **Lane handback contract -- lanes write a ten-field HANDBACK-<lane>.md to the transport as their mandatory final step** - Architect declaration 2026-09-18 (`to-cc/DECLARE-LANE-HANDBACK-CONTRACT-2026-09-18.md`, seat 2026-09-17-dev-knowledge-architect). **The lane return leg does not exist.** Lanes commit their reports into the repo (`docs/audits/...`) on their own worktree branches, unmerged and mostly unpushed; the architect seat reads the Drive transport, not git. So no path carries a lane's result to the seat that must evaluate it -- on 2026-09-17 (batch AC) the operator pasted terminal output by hand and became the transport. Seats write `SESSION-*.md` to `to-browser/`; lanes write nothing there. This is the mirror of the outbound defect in `FINDING-transport-on-execution-path-2026-09-17.md` (on the transport, `to-browser/`): the transport sits on the execution path, where it must not, and is absent from the return path, where it must be -- same root cause, nobody defined where a lane's output goes for the architect. **The contract:** as its mandatory final step every lane writes `to-browser/HANDBACK-<lane-id>.md`, under 6,000 B, carrying exactly ten fields -- (1) IDENTITY: lane id, worktree, branch, every commit SHA, model ordered vs model that ran (read from the session transcript), wall time, token/credit cost; (2) DONE-WHEN VERDICT: the Done-when quoted verbatim, then MET / NOT MET / PARTIAL per clause, never one overall verdict; (3) CHANGE: files with +/- counts and an asserted yes/no on touching anything outside the declared footprint; (4) WITNESS PER CLAIM: every factual statement paired with the command that produced it, an unwitnessed claim labelled a hypothesis; (5) TESTS AGAINST BASELINE: what ran, what passed, what was already red before the lane started; (6) ORGANS VS RAW SCANS: which organs were called (FPG-1, `decision_coverage`, `graph_queries`, orphan census, `gen_task_tree`) and which questions a raw grep/rg/find/git-log answered instead -- feeds AX9-5; (7) REFUSALS AND ESCALATIONS: what was declined, under which decision-budget class, what needs ruling; (8) RESIDUE: named, for integrator / operator / later lane; (9) ARMED GUARD SET: which hooks and gates were live while the lane ran; (10) ANTI-CLAIMS: what the lane explicitly did not verify. Prose without these fields is not a handback. **Home is the contract template, not prompt prose** -- a recurring instruction written as prompt text is a routing failure. Batch AC was consolidated by hand once (`to-browser/HANDBACK-batch-AC-consolidated.md`, 2026-09-18) because its lanes had no such step; that one-off is the witness, not the fix. · Done when: (1) `templates/prompt-template.md` carries the handback as a mandatory final step -- path `to-browser/HANDBACK-<lane-id>.md`, the 6,000 B cap and the ten fields by name -- with a version bump; PLAYBOOK §2 "Creating a Claude Code Prompt" points at it rather than restating it; (2) `scripts/gen_lane_contract.py` emits that step in every contract it assembles, and its `--check` leg refuses a contract that lacks it -- RED-first witness: a contract with the step removed fails `--check`; (3) a handback is checkable by machine: a file missing any of the ten field headings, or over 6,000 B, is refused by a named checker, RED-first witnessed on a fixture; (4) the first batch dispatched after (1)-(2) lands returns one `HANDBACK-<lane-id>.md` per lane on the transport with no operator paste, recorded in that batch's integration JOURNAL entry · refs `templates/prompt-template.md`, `scripts/gen_lane_contract.py`, `protocols/PLAYBOOK.md` §2, `[#539]`, `[#672]`, `[#752]`; transport: `to-cc/DECLARE-LANE-HANDBACK-CONTRACT-2026-09-18.md`, `to-browser/FINDING-transport-on-execution-path-2026-09-17.md` · source: architect declaration 2026-09-18
