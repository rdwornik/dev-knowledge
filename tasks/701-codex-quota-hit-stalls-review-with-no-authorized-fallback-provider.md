This is the row. · **Fifty minutes is the measured number and it understates the cost**, because review sits on the critical path to merge: a stalled reviewer stalls the lane, and in a batch it stalls the integration queue behind it. At the ceiling the roster is targeting -- 8 to 10 lanes a night -- a provider that can stop the queue for an hour is the single point of failure the whole unattended-night goal is built against. · **A fallback is not "use any model that answers".** The reviewer's independence is the reviewer MODEL, not the invoker -- AW5-2 rules exactly that for W-2 -- so a fallback that reaches for whatever is available silently converts an independent review into a self-review. The fallback must be an ADMITTED reviewer, chosen by rule, and the choice must be visible afterwards. · **Visible is the load-bearing half.** If the tally does not record WHICH provider answered, a fallback and a primary review are indistinguishable in the record, and the first thing anyone will want to know when a review turns out wrong is which model produced it. · Done when: a review that cannot reach Codex resolves to a named fallback provider BY RULE rather than by the seat's improvisation; the fallback is an admitted reviewer rather than any reachable model, with its admission resolved against the provider registry; and the tally records which provider answered, so a fallback review is visible as one rather than silent · **Done-when authored by the filing lane, not carried**: the roster names this item in a section-4 prose list that carries no Done-when column · refs `docs/intake/2026-09-11-tech-batch-x-roster.md` (intake 93, section 4), `to-browser/LEDGER-OPERATOR-EXPECTATIONS-2026-09-10.md` row C5 (the 50 minutes and the no-row status), `to-cc/AMEND-BATCH-W-005.md` AW5-2 (independence is the reviewer model, not the invoker), `ecosystem/provider-registry.yaml`, `[#627]` (agy's admission for the ANALYSIS role -- the admission mechanism a reviewer fallback would reuse), `[#649]` and `[#699]` (the tally that must record the answering provider), `[#691]` (provider routing as an unordered role set with no admission gate), `[#689]` · kill-candidates: none -- `[#691]` owns the ROUTING table's shape and admission gate and is silent on what happens when the routed provider is unreachable; `[#627]` owns one candidate's admission to a different role · source: `to-cc/DECLARE-BATCH-X-ROSTER-2026-09-11.md` section 4 (LEDGER C5), filed 2026-09-11 by lane `lane-x-000-batch-x-roster-lands`
