- [#843] [P1][M] **A frozen contract's premise clause is carried from a digest, not verified against main at freeze time** - `scripts/gen_lane_contract.py`'s `cmd_emit`/`render_contract` accepts a premise clause -- a claim about a file's or module's current state -- as author-supplied prose and freezes it verbatim. Nothing at freeze time re-reads the file or module the clause is ABOUT against `main`; the clause is carried forward from whatever digest or roster entry the architect wrote it from, and a digest is a snapshot, stale the moment `main` moves past it. · **Three instances this window, all the same shape, and the dispatcher/architect owns them rather than the lanes that hit them.** `[#667]` (lane y-755): the render premise reported REFUTED at `docs/audits/2026-09-14-technical-lane-y-755-docs-cut-finish.md` section 2, Q10-paused. `[#810]` (lane-ab-810-substrate-repair, running concurrently in this same batch): the operator's own characterization, given directly rather than read from a landed audit -- that lane's own end-of-lane artifact carries the specifics once it merges -- is "810's two-sided drift": a premise about which copy of a module led drifted from which copy actually did. `[#694]` (this lane): LEDGER F6's "four modules unwired" was three modules already DELETED by `lane-x-664-spine-armed` (`c9ea3b07`, `3a380fd8`) days before this contract froze, flagged stale by `docs/audits/2026-09-13-census-x-664-delete-list.md` section 4.2 and never acted on before the freeze. · **The common root, stated by the operator rather than inferred by this row:** all three premises came from digests the architect wrote without re-verifying current state at freeze time. A contract clause asserting a file's or module's state is a claim about `main`, checkable the moment before the freeze -- not a claim about the digest that produced it, and a frozen contract has no mechanism that tells the two apart. · Done when: `gen_lane_contract.py`'s freeze step (or a paired pre-freeze check callable from `/lane-boot` or the architect's own authoring flow) resolves every file/module path a premise clause names against `main` HEAD and refuses, or visibly flags, when the clause's claimed state (exists / deleted / wired / unwired) disagrees with what `main` actually holds; RED-first, a fixture contract naming a file `main` has since deleted (or wired) trips the refusal · refs `scripts/gen_lane_contract.py` (`cmd_emit`, `render_contract`), `scripts/batch_manifest.py::freeze_manifest_contract_agreement`, `protocols/STANDING_RULINGS.md` (Q10, the refuted-premise pause rule; Decision Budget V-2), `docs/audits/2026-09-14-technical-lane-y-755-docs-cut-finish.md` section 2 (`[#667]`), `[#810]` (lane-ab-810-substrate-repair), `[#694]` (this lane's own premise correction, `c0565024`), `docs/audits/2026-09-13-census-x-664-delete-list.md` section 4.2 · kill-candidates: none -- this is a new finding against the contract-freezing mechanism itself; no open row already covers a freeze-time state check · source: operator order 2026-09-16, lane-ab-694-cost-telemetry
