- [#761] [P2][S] **The edge-class census prices its own false positive as cheap, but paying it is an escalation class, so lanes route around the gate instead** — surfaced live by batch Y lane `y-751` and filed by the integrator at that lane's request; the lane correctly declined to file it itself, because the fix touches a curated register. · **The predicate, verified rather than quoted.** `graph_queries.is_edge_computation_shape` returns `extracts and (scans >= 1 or reads >= 1)`, where `extracts = regexes >= _MIN_REGEXES or ast_calls >= 1` and `_MIN_REGEXES = 2` (`scripts/graph_queries.py:776`, `:915`). So any module that compiles a second regex AND scans or reads a file is a candidate private five-kind edge computation, and `graph-edge-class-census` refuses the commit unless a row of `EDGE_COMPUTATIONS` (`scripts/graph_queries.py:831`) verdicts it. · **THE DEFECT IS A PRICE, NOT A PREDICATE.** The gate declares its own cost model in its own docstring: *"RECALL OVER PRECISION, deliberately. A false positive costs one verdict row in the register, which is cheap and informative; a false negative is a private edge computation that lands unseen, which is the thing the ratchet exists to stop."* The recall preference is right and should not change. What is wrong is the claim that the false positive is **cheap**: `EDGE_COMPUTATIONS` is a **curated** register — the module states *"THE MEASUREMENT IS THE REGISTER, and the register is not a view"* (`:748`) — so a lane adding a row to it performs a curated-baseline touch, which is a **V-2 escalation class (a)**. The gate therefore assumes a cheap act that governance classifies as an escalation, and the party that pays is never the party that set the price. · **The measured consequence: the gate is routed around rather than satisfied.** Lane `y-751` needed a slug-to-directory matcher. Written as the obvious `(?:^|-)…(?:-|$)` regex it would have been that module's SECOND `re.` call, and the census refused the commit. The refusal is a **false positive on the merits**: the text being matched is a *session-store directory name*, which lies OUTSIDE the repo, so a slug-to-directory match is not a corpus-structure relation and is none of the five kinds. Rather than escalate, the lane spelled the same predicate as four string comparisons (`lane_cost._matches_segment`) and documented the reason in its docstring so nobody "simplifies" it back. It landed at `b864e7d0` with `Edge-class ratchet` PASSING. **The gate's census is therefore already one module short of the truth, and it recorded nothing about it.** · **This is the second recorded instance of the module's predicate not matching its own population**, which is why the fix belongs to the predicate's owner and not to a lane: the same docstring records that the predicate lane `v-664` STATED for its section 2.5 table (*"a module that walks the tree and compiles two or more regexes"*) does not reproduce that table — four of its twenty-one rows fail it. A gate whose stated predicate and stated cost are both approximations needs one ruling, not a third workaround. · **What a lane must NOT do, recorded so the next one does not do it.** Adding the register row is escalation; rewriting the predicate is the architect's; and hand-rolling around the gate — which is what happened here and was the right call under a lane's decision budget — leaves the census silently incomplete. There is currently no third option, and that absence is the row. · **SECOND WITNESS, 2026-09-17 (operator order, recorded by integrator-AB): a different lane paid a different price.** Lane `ab-802` (`[#802]`, merged `645ec4db`) gave `scripts/conductor.py` its first `import re` and a two-plus-regex parser of `logs/SUITE-BASELINE-FREEZE.md`; `graph-edge-class-census` refused the commit, and the lane ADDED a `not-an-edge` row for `conductor.py` to `EDGE_COMPUTATIONS` itself -- the curated-baseline touch this row names as escalation class (a) -- and recorded it as a decision under its budget (lane artifact section 5 item 5). Its own verdict is that the code is NOT an edge computation (a declared roster read back, sub-file node ids FPG-1 cannot represent), so the gate caught code that RESEMBLES an edge computation rather than one that IS. **Two witnesses, two different workarounds:** `y-751` rewrote its predicate without a regex (the census silently one module short), `ab-802` wrote the curated register without escalating (the escalation class silently not honoured). Each lane pays in a different currency, the party paying is never the party that set the price, and **no surface counts the false-positive rate** -- so a third instance will again look like the first. · Done when: a module whose text-scanning target lies outside the repo corpus is either excluded by the predicate or expressible as a NON-CORPUS verdict kind a lane may record without a curated-baseline touch, with the choice ruled by the architect rather than by a lane; `is_edge_computation_shape`'s docstring no longer prices a false positive as cheap without naming the escalation class that paying it incurs; and `lane_cost._matches_segment` is either admitted to the register under that new kind or left as-is by a recorded decision rather than by a lane's workaround; **and** the census's false-positive rate is a measured number -- each `not-an-edge` verdict and each recorded workaround (the `y-751` and `ab-802` instances first) counted against the modules it flagged, reported by the census itself, with `ab-802`'s `conductor.py` row either ratified under the ruled mechanism or re-recorded through it · refs `scripts/graph_queries.py:748` (the register is not a view), `:776` (`_MIN_REGEXES`), `:831` (`EDGE_COMPUTATIONS`), `:915` (the predicate), `docs/audits/2026-09-14-technical-lane-y-751-cost-in-money-packet.md` (the lane's open item 10, where this was carried), `[#664]` (owns the graph and its clause-2 gates), `[#751]` (the lane that hit it), `[#802]` (the second, merged `645ec4db`) · kill-candidates: none — `[#664]` owns the census's existence and its clause-2 wiring, not the cost model of its false positives, and no open row carries the escalation-class mismatch this one names · source: integrator seat, batch Y, filed on behalf of lane `y-751`
