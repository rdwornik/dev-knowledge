That split is what produced four symptoms in one window (`[#716]` baseRef unset, `[#717]` `-Model` dropped from the launch line, `[#718]` contract written where the verb does not read, `[#740]` the fence the verb refuses) and a truncated `My Drive` path before them. Each was patched where it surfaced; none could be prevented, because no surface owned the seam. **Dispatch is methodology: every consumer repo will need it, so it belongs to the thing that ships to every consumer.** · **THE SPLIT THIS ROW MUST GET RIGHT is what is universal versus what is local.** AX25-3 draws it: the **component** is hub-owned, shipped on the floor, and **OS-independent**; the **machine-local values** — paths, credentials, substrate availability — stay in `win-tooling` config. A floor component that hard-codes a Windows path, a drive letter or a PowerShell-only verb has not moved ownership, it has exported one machine's assumptions to every consumer, which is strictly worse than the split it replaces. · **SCOPE IS DECIDED BY THE FACT-READ, NOT BY INFERENCE — this is a binding constraint on the row, quoted from AX25-3:** *"Scope is decided by the fact-read below, not by inference: where each verb currently lives, what it depends on, and what a consumer repo would need."* A fact-read was running at filing time and its output had not reached this row, so **this row deliberately does NOT enumerate the verbs, their dependencies or the consumer requirement** — writing that list from what the dispatcher seat happened to observe would be exactly the inference AX25-3 forbids, and would freeze a guess into a row that outlives it. The three questions above are the fact-read's, and its answers set this row's footprint. · **AX25-4 BOUNDS THE ADJACENT WORK AND THIS ROW MUST NOT OVERRUN IT**, quoted: *"Do not gold-plate the retiring path. `DECLARE-DISPATCH-RETIREMENT` already rules that the PowerShell dispatch retires once one batch has run on conductor E. Work on the verb is therefore bounded to AX25-2's conformance test plus whatever E's runner needs; everything else waits for E."* So this row is **ownership and shape**, not a rewrite of the retiring PowerShell verb. The interaction is live and must be resolved rather than assumed: if the PowerShell path retires onto conductor E, the hub-owned floor component is plausibly E's runner contract rather than a port of the current verb — which is precisely a question for the fact-read, not for this row's author. · **AX25-5 is the consumer-facing reason this matters**, quoted: *"The browser never composes a launch: it states intent and the repo resolves the verb — the prompt distiller `[#617]` with the organ skills (AX9-2).
