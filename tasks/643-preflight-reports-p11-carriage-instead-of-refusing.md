- [#643] [P1][M] **The handoff preflight reports P11 carriage after the cut instead of refusing it, and two consecutive bundles shipped the same defect** - `gen_handoff.py`'s nine-row preflight (`preflight_rows` / `assert_preflight` / `--preflight-only`) refuses a cut on ship-gate state, question disposition and seven other hygiene rows, but it does **not** evaluate P11's decision-file carriage at all. P11 is a probe the bundle *ships*, so the carriage defect is discovered by `/handoff-verify` **after** the bundle is cut, committed and merged - and a merged handoff is immutable, so the only repair is a superseding cut. Measured 2026-09-08: `2026-09-08-dev-knowledge-architect` failed P11 and `-2` failed P11 **on the same 25-file transport set**, because nothing between them tested carriage before writing. The row 1 and row 7 amendments landed the same day both made a *preflight* row the place where debt is refused; P11 is the third member of that family and never got its row. **The two legs do not gate at the same stage, and this is the design content of the row, not an afterthought.** Leg 1 (a flush-left `carried-by:` in the file HEAD whose value resolves on `main`) reads only the transport and `main`, so it is fully checkable **before** the cut and belongs in `preflight_rows` as a refusal. Leg 2 (a `carried-by: OPEN` must be **named in this bundle's residual**) cannot be checked at preflight, because the residual does not exist until the operator fills it - exactly the shape row 1 already documents for its own second conjunct. Leg 2 therefore needs a **second, later gate at assemble time** (`assemble_paste.py`, where `RESIDUAL.md` is filled and the framing flips cold->FILLED), which is the first moment both operands exist. A single preflight row that claims to cover both would be the same false-completeness P11 itself exists to catch. **Beware the leg ORDER when implementing:** the stated `carried-by:` value decides which leg applies, and several live decision files carry explanatory prose containing paths that *do* resolve on `main` while their stated value is the literal `OPEN` - so a path-first reading passes them on evidence that is not their carrier value, and silently under-counts the OPEN set (this is precisely how the `-1` run under-read the failure as 2 files when it was 7) · Done when: leg 1 is a `preflight_rows` row that REFUSES the cut, with a RED-first test per ADR-108 §B proving a missing/unresolvable flush-left key blocks `generate()` before it writes; AND leg 2 is a distinct assemble-time gate proving an `OPEN` carrier absent from the filled residual blocks assembly; AND both cite `DECLARE-PREFLIGHT-SHIPGATE-ROW-2026-09-08` / `DECLARE-PREFLIGHT-QUESTION-ROW-2026-09-08` as the family precedent for where a handoff refuses debt; AND `.claude/commands/handoff.md` states the two-stage split so a seat is not told a single row covers both · refs `protocols/HANDOFF_PROCESS.md` §5 (the P11 contract and the anchored-key-plus-value form), `scripts/gen_handoff.py` (`preflight_rows`, `_row_ship_gate`, `_row_question_disposition`), `scripts/assemble_paste.py`, `to-browser/HANDOFF-VERIFY-2026-09-08-architect-2.md` (the live 25-file measurement: 18 resolve, 7 short - 2 with no flush-left key, 5 OPEN-and-unnamed), `[#642]` · source: browser seat ruling 2026-09-08, filed by the handoff seat after the second consecutive cut shipped the same defect
