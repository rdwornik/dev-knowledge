The lane placement -- joining X1-1's lane or standing alone -- is the dispatcher's call on serialize-groups. · **The defect is the operator's own observation and it is structural rather than a lapse:** the model builds tools it never calls, greps instead of querying, and creates organs that duplicate existing ones. A raw `grep` always works well enough to look like an answer, so nothing ever forces the query. The organ is then maintained and never used, which is the INVENTORY class from intake 92 arriving from the model's side rather than the harness's. · **PRECONDITION DISCHARGED BY THIS LANE, which AX9-1 asked for explicitly** ("CC verifies on this version that a PreToolUse deny on Bash actually blocks (a known upstream issue reported the opposite)"). **It blocks.** The evidence is this filing session itself: its Bash calls were denied several times by the worktree-isolation `PreToolUse` guard, each refusal reaching the model as exception text and stopping the call before it ran. The repo's ADR-77 transcript-immutability `PreToolUse` guard is documented fail-closed on the same mechanism. So the fallback AX9-1 holds in reserve -- moving the rule to `UserPromptSubmit` / skill hooks -- is NOT required on this version, and the row starts from a verified mechanism rather than an assumed one. · **The DENIAL is the cheap half; the POINTER is the row.** A refusal that only says no trains avoidance. The exception text must NAME the organ to run -- `graph_queries.py why|process-list`, the impacted-test selector, the organ-index -- so the refusal teaches the substitution. That is the same principle the operator's rule states for process deviations generally: an exception that teaches the next seat rather than passing silently. · **Scope is GOVERNED QUESTIONS, not searching.** AX9-1 enumerates them: what is this file, who triggers it, where does X live, which tests cover Y, is there already an organ for Z. A grep for a string in a file is not a governed question and must stay allowed -- over-broad matching here wedges every session, which is a known and expensive failure mode for a match-all `PreToolUse` rule. · Done when: a `PreToolUse` hook on `Bash` and `Grep` DENIES a raw search (`grep`, `rg`, `find`, `Select-String`) over the governed questions AX9-1 enumerates, with exception text naming the organ to run instead; a RED-first trip-test sends a raw grep and asserts BOTH the denial and the pointer; ordinary non-governed searching is unaffected, proven by a test that a plain string search still runs; and the component is declared **floor: MUST** · **Done-when carried from AX9-1's clauses**, with the over-match guard added by the filing lane · refs `docs/intake/2026-09-11-tech-batch-x-roster.md` (intake 93, Part 9 AX9-1), `to-cc/AMEND-BATCH-X-ROSTER-009.md` AX9-1, `scripts/graph_queries.py` (`why`, `process-list` -- the organs to point at), `scripts/impacted_tests.py`, `ecosystem/organ-index.md`, `[#728]` (organ skills -- the same problem addressed by discovery rather than refusal), `[#729]` (the queries as tools, which is what makes the pointer actionable), `[#694]` (where AX9-5's raw-search-vs-organ-call metric lands) · kill-candidates: none -- `[#728]` and `[#729]` are the other two legs of AX9's same thesis and address discovery and reachability where this row addresses refusal; none of the three substitutes for another · source: `to-cc/AMEND-BATCH-X-ROSTER-009.md` AX9-1, filed by lane `lane-x-000-batch-x-roster-lands`
