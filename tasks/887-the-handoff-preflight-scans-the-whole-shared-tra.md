- [#887] [P1][S] **The handoff preflight scans the whole shared transport, not the handing-off seat's own files -- a concurrent workstream's decision files refuse this seat's cut** - Operator ruling 2026-09-17, at the `.dev-knowledge` architect handoff cut. The preflight row `p11_carriage` (`gen_handoff.decision_files`, `[#643]` leg 1) takes EVERY top-level `DECLARE-`/`AMEND-`/`BATCH-` file in `to-cc/` and `to-browser/` as this window's population. It has no notion of which workstream a file belongs to. On 2026-09-17 it refused the cut on seven files from the operator's concurrent CV and GitHub work on the same transport: `to-cc/AMEND-CV-V10-001.md`, `to-cc/AMEND-GITHUB-REVIEW-001.md`, `to-cc/AMEND-GITHUB-TIDY-001.md`, `to-cc/DECLARE-cv-content-2026-09-10.md`, `to-cc/DECLARE-cv-f2-2026-09-10.md`, `to-cc/DECLARE-cv-feedback-2026-09-10.md`, `to-cc/DECLARE-cv-positioning-2026-09-10.md`. None of them carries a `carried-by:`, and none is this repo's to carry. The standing rule is that a seat reads only its own files, so the gate is enforcing a population the seat is forbidden to act on. **Ruled, not to be worked around:** no `carried-by:` home is invented for another workstream's file, and those files are not edited or moved by this seat. The only moves left are a gate change or a refused cut, which makes this a defect, not debt. `_question_files` (row `question_disposition`) reads the same transport the same way and carries the same exposure, although no foreign QUESTION file fired on 2026-09-17. · Done when: (1) the workstream a transport file belongs to is read from the file itself or from a declared registry -- never inferred from a filename pattern such as `cv`/`GITHUB` -- and a file with no readable workstream is REPORTED as unattributed, never silently dropped from or silently added to the population; (2) `p11_carriage` and `question_disposition` judge only the handing-off repo's files and name every excluded file with its workstream in their evidence line; RED-first witness: a fixture transport holding one foreign `DECLARE-` file with no `carried-by:` refuses today and passes after, while an in-scope file with no `carried-by:` still refuses; (3) leg 2 in `scripts/assemble_paste.py` reads the same population through the same predicate, so the two stages can never disagree about scope · refs `scripts/gen_handoff.py` (`decision_files`, `_row_p11_carriage`, `_question_files`, `_row_question_disposition`), `scripts/assemble_paste.py`, `protocols/HANDOFF_PROCESS.md` §5 (P11), `[#643]`, `to-browser/RATIFICATION-2026-09-17.md` · kill-candidates: none -- `[#643]` built the carriage predicate; this row bounds its population · source: operator ruling 2026-09-17, handoff preflight refusal
