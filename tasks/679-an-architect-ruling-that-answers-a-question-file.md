- [#679] [P2][S] **An architect ruling that answers a `QUESTION-*.md` does not write the `disposition:` back onto the file that asked, so the ruling is given and not landed** - **Witnessed 2026-09-10, and the cost was a refused handoff cut.** `QUESTION-dispatcher-V.md` asked whether the `carried-by:` write-time refusal belonged to V-5 item (c) or V-6. **It was answered on 2026-09-08, in `AMEND-BATCH-V-002` section 4** ("V-5/V-6 `carried-by:` refusal collision resolved to V-6"), and the answer **never travelled back to the file that asked**. Two days later `gen_handoff.py --preflight-only` still reported `question_disposition: FAIL - 1 of 22 QUESTION file(s) are neither ANSWERED nor CARRIED`, and `generate()` refused the window-close cut. The preflight was **right**: by its own predicate the question carried no `disposition:` key, and the ruling that discharged it was invisible from the file. · **The class, stated so it is not read as one seat's slip:** this is the same defect the night mission's `REVIEW.md` finding #1 names - *a conclusion that governs work lives somewhere the reader of the governed artifact cannot see it*. There it was a decision on the transport that committed audits cite as authority; here it is a decision in an `AMEND-` file that the QUESTION it answers does not cite. **The declaration exists; the link does not.** · **Why a mechanism and not diligence:** the answer WAS written, by a seat doing its job, into the correct artifact for its own act. Nothing about writing `AMEND-BATCH-V-002` section 4 prompts its author to also edit a file in `to-browser/`, and no organ reads the two together. A rule that depends on the ruler remembering a second write has a known failure rate, and 2026-09-08 to 2026-09-10 is one measured instance of it. · **The adjacent rows do not absorb this:** `[#642]` is the *receiving surface* for the eleven carried questions of batches T and U and rules nothing itself - it owns whether a question has an owner, never whether a ruling routed back; `[#643]` owns the P11 *carriage* leg of the preflight (`carried-by:` on DECLARE-/AMEND-/BATCH- files), a different key on a different file class. · Done when: an `ANSWER-*`/`DECLARE-*`/`AMEND-*` that discharges a `QUESTION-<seat>.md` **writes the flush-left `disposition:` line onto that QUESTION file in the same act**, enforced rather than asked - either a write-time refusal in the filing path (the shape `[#643]`'s leg 1 already uses) or a preflight row that FAILs when a transport `ANSWER-<seat>.md` exists while `QUESTION-<seat>.md` carries no `disposition:`; and **one test FAILS when the disposition is absent while the answer exists** - a RED-first witness per ADR-108 section B, proven to bite before the check makes it green; and the 2026-09-08 `dispatcher-V` case is the fixture · refs `scripts/gen_handoff.py` (`_question_disposition_verdict`, `_DISPOSITION_KEY_RE`, the `question_disposition` preflight row), `to-cc/DECLARE-PREFLIGHT-QUESTION-ROW-2026-09-08.md` (the ruling the row implements), `to-cc/ANSWER-dispatcher-V.md`, `to-browser/QUESTION-dispatcher-V.md`, `docs/audits/2026-09-10-technical-night-aj-m03/REVIEW.md` section 1 row 7, `[#642]`, `[#643]`, ADR-108 · kill-candidates: none - `[#642]` owns question OWNERSHIP and `[#643]` owns `carried-by:` carriage on decision files; neither owns the return path from a ruling to the question it answers, and no other open row names `disposition:` at all · **Archived annotations:** `tasks/archive/679.md`
