- [#676] [P2][M] **No check verifies that each provider CLI's non-interactive invocation shape still works, so a mis-invoked tool is indistinguishable from a dead one** - **A SEAT REPORTED `agy` ABANDONED AS UNRELIABLE AND THE TOOL WAS FINE; the finding recorded an INVOCATION failure and named it a TOOL failure.** Measured 2026-09-09 across seven providers, one minimal prompt each: **five answered** (`codex`, `agy`, `copilot`, `cursor-agent`, `grok`) and **two could not be reached at all** - and of the five, **two answered only after the invocation was corrected**. `codex exec` on its configured default died at HTTP 400 (`'gpt-6-astra' model requires a newer version of Codex`) while the identical call with `-c model=gpt-5.6-sol` returned in 15s; `cursor-agent -p` died at `Workspace Trust Required` while `-p --trust` returned in 26s. **Both look exactly like an unavailable provider from the outside** - non-zero exit, no answer - and both are the caller's error. **The registry cannot catch this, by construction:** `ecosystem/provider-registry.yaml` carries `version_command:` per row, which proves a binary is PRESENT and answers `--version` locally; it carries **no prompt-shaped invocation at all**, so nothing anywhere in the repo asserts that a provider still ANSWERS. The two absences measured today prove the gap is not hypothetical and that presence-checking is the wrong instrument: `glm` is **on PATH and executable-by-mode while being a 564,819-byte HTML document** (`<!DOCTYPE html>` at byte 9, a saved GitHub page under an `.exe` name) - a `version_command` probe reports it INSTALLED - and `deepseek` has no binary on any surface. **Four outcomes are currently collapsed into one:** binary absent · binary corrupt · reachable but mis-invoked · answered. Only the fourth is a live provider and only the second and third are actionable by us, so a check that cannot tell them apart reports the wrong repair every time. · **The cost is real and is named here rather than discovered at review:** five network calls at 15-31s each, one of which meters a Copilot premium request, is not payable on every commit - so the invocation-shape half (offline, deterministic, the half that would actually have caught both corrections above) is what belongs at commit tier, and the answering half belongs behind an opt-in flag the nightly routine passes. · Done when: `provider-registry.yaml` carries the **non-interactive invocation shape as data** per row (prompt-shaped, alongside the existing `version_command`), including the flags without which the call fails - `--trust` for cursor, `-c model=` for codex, `--dangerously-skip-permissions` and prompt-attached `--print=` for agy, `-p/--single` for grok, no `--model` for copilot; and a **commit-tier check** asserts every such row's shape is present, well-formed and agrees with the CLI's own advertised flags, **discriminating the four outcomes above rather than emitting a single reachable/unreachable bit**; and **one test FAILS when a row's probe shape is absent or names a flag the CLI does not accept** - a RED-first witness per ADR-108 section B, proven to bite before the check makes it green; and the **network leg is opt-in**, not on the commit path; and a **corrupt binary is reported as corrupt** - the `glm.exe` case must not read as INSTALLED · refs `ecosystem/provider-registry.yaml` (the `version_command:` rows, and the `cursor` / `deepseek` comment blocks this measurement partly supersedes - cursor ANSWERED today), `scripts/provider_registry.py`, `scripts/check_provider_registry.py`, `tests/test_provider_registry.py`, `scripts/changelog_sentinel.py` (today's only `version_command` consumer), `ecosystem/tool-versions.yaml`, ADR-108 (section B, RED-first), ADR-98 (admission - a liveness probe is NOT an admission and grants no role) · kill-candidates: none - no open row owns provider invocation shape; the registry rows that mention CLI availability are comment blocks in a data file, not backlog items, and `[#675]` owns a defaulting READ over a heterogeneous node list, which is a different mechanism · **Archived annotations:** `tasks/archive/676.md`
