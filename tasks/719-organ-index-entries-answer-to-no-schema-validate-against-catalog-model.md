- [#719] [P2][M] **`ecosystem/organ-index` entries answer to no schema -- validate them against Backstage `catalog-model`'s Component shape with our own gate** - AX7-4 of `to-cc/AMEND-BATCH-X-ROSTER-007.md`, carried at `docs/intake/2026-09-11-tech-batch-x-roster.md` (intake 93) Part 5. · **Library-first applied to a SHAPE rather than to a runtime, and that distinction is the whole design.** Backstage's `catalog-model` already defines what an organ entry needs -- owner, lifecycle, system, dependsOn -- as a published JSON schema a large ecosystem has already argued about. Adopting the SCHEMA costs a validation gate; adopting BACKSTAGE costs a service, a database and a deployment this repo has no use for. AX7-4 takes the first and explicitly refuses the second: validated "by our own gate; no Backstage runtime". · **The portal question is deferred on a NAMED CONDITION rather than rejected**, which is what stops it being relitigated every few months: revisited only if lane X-C's census shows a scale that needs BROWSING. Until a measured organ count makes browsing necessary, a generated index answers the same question for free. · **`owner` is the field that changes behaviour**, and it is why this row sits under enforced governance rather than tooling. An organ with no owner is the orphan class seen from the other side: the process census can say a process has no TRIGGER, and this schema can say it has NOBODY ANSWERING for it. `lifecycle` does the same for retirement -- it gives an organ a state to be in other than present, which is precisely what `[#481]` found missing when enforcement coverage named an organ that had already been retired. · **The first fill is already being produced**, so this row does not invent its own data: lane X-C's domain census emits `owner` and `lifecycle` per folder-domain and AX7-4 names those columns as the first fill.
