- [#769] [P2][S] **An unattended lane has no cancel for a long-running gate -- the only lever is killing the session** -- AJ M04 L04 names the failure shape and its consequence: *"jeżeli nie zaimplementujecie cancel przy długich operacjach, może to zablokować cały wątek czatu tak długo, jak czat nie stwierdzi, że trzeba uwalić dane połączenie, bo no nic dobrego już nie przyniesie"* (`AJ_M04_transkrypcje.md:721-723`, verified) -- without a cancel mechanism for long operations the whole chat thread is blocked until the client decides to kill the connection. · **Measured in this lane, not inferred.** Two of this lane's commits exceeded a 120 s tool timeout and then a 400 s one and had to be moved to the background to survive; the pre-commit registry here runs roughly thirty hooks including a graph rebuild, an orphan census, a full audit self-conformance pass and a task-tree regeneration. · **The asymmetry is the finding, and it is created by the dispatch constants themselves.** An attended seat interrupts a wedged gate with Ctrl-C. A lane dispatched `--bg --permission-mode bypassPermissions` -- which is every LOCAL lane the ADR-110 batch protocol fires, and which the contract generator puts on the line deliberately so a background lane has nobody to answer a prompt -- has no interactive channel at all. The only remaining lever is killing the session, which loses the turn's context and any uncommitted work with it. · **This compounds with `[#768]` rather than duplicating it.** `[#768]` is about a refusal a lane cannot ATTRIBUTE; this row is about a run a lane cannot STOP. A gate that is both unattributable and uninterruptible is the shape that produced this repo's recorded `--no-verify` incidents. · **Not a proposal to make the gates faster.** The hooks earn their time; what is missing is a bound and a way out. · Done when: a commit-tier gate run carries a declared time bound, and a `--bg` lane exceeding it gets a refusal that names which hook was still running rather than an indefinite wait -- so a wedged gate is a reported outcome with a named cause instead of a session that has to be killed to end · refs `AJ_M04_transkrypcje.md:721-723` (the rule, quoted above), `docs/audits/2026-09-15-technical-lane-z-10-aj-m04-evidence/LOCATOR-VERIFICATION.md` (item 44 -- verified), `.pre-commit-config.yaml` (the hook registry whose run is being bounded), `[#768]` (the attribution half of the same pain), `[#528]` (lane latency -- owns the FULL SUITE's placement, not the commit gate's bound) · kill-candidates: none -- `[#528]` moves the full suite to integration and leaves every per-commit hook run exactly where it is, which is the run this row bounds; `[#768]` makes a refusal attributable and would not shorten or interrupt one · source: batch Z lane z-10, AJ M04 first pass, `[#784]`
