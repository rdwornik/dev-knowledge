- [#801] [P2][S] **Opus is a flat 2.50x Sonnet on every leg — a false 5x figure circulated and a token-shape argument was built on it** — filed from `DIGEST-2026-09-15-unrecorded-findings.md` §4. **THE FACT:** `ecosystem/provider-registry.yaml` prices `claude-opus-5` at input 5.0 / output 25.0 and `claude-sonnet-5` at input 2.0 / output 10.0. **5.0/2.0 = 2.50x and 25.0/10.0 = 2.50x** — the same ratio on both legs. Because `cache_write` (x1.25) and `cache_read` (x0.1) are multipliers on the INPUT rate, **both cache legs are 2.50x too**; confirmed live through `resolve_rate` (opus cache_read 0.5, sonnet cache_read 0.2). **Moving work Opus→Sonnet saves exactly 60%, whatever the token shape.** · **THE DEFECT THIS ROW RECORDS is not the arithmetic, it is the propagation.** A read-only lane reported "5.0x Sonnet input, 2.5x output" on 2026-09-15; the dispatcher relayed it without checking, and built a conclusion on the supposed asymmetry — "do not model it as a flat multiplier; weight by which half is input-heavy versus output-heavy". **That conclusion was wrong and the arithmetic was one division away from being checked.** Lane aa-2 caught it by verifying against the cited lines rather than accepting the relay. The sibling error survived because "5.0x Haiku on both" in the same sentence IS correct (5.0/1.0 and 25.0/5.0), so the line read as internally consistent. · **Why it is worth a row rather than a correction in place:** any estimate built on the 80%-on-input figure **overstates the input saving by a third**, and estimates travel further than corrections.
