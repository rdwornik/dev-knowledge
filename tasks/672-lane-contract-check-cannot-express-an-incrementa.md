- [#672] [P2][M] **`lane-contract-check` cannot express an incremental contract addition, and its docstring disagrees with its YAML** — **the same class as P11 — a check that cannot check its own case — and the class is the point, not the one-off inconvenience.** `scripts/gen_lane_contract.py::check` compares an open batch's manifest slugs against ONLY the contracts it is handed in argv (`_check_manifest_contract_agreement(contracts)`, whose comparison `batch_manifest.freeze_manifest_contract_agreement` is SET EQUALITY BOTH WAYS), and the pre-commit hook hands it the STAGED set. **So a commit ADDING contracts to an already-frozen batch is always a strict subset and always refuses**, with the manifest's other rows reported as "named by no matching contract". There is no staging arrangement that satisfies it: reverting the manifest instead makes the new contracts "named by no manifest row". **Code and config also disagree:** `check`'s own docstring states the hook runs `always_run: true` + `pass_filenames: false` (`[#630]`), and `.pre-commit-config.yaml`'s `lane-contract-check` block carries `always_run: true` but OMITS `pass_filenames`, which defaults TRUE — half the declared pair is absent while the docstring describes both. **`pass_filenames: false` is NOT the fix**: with zero paths the checker shape-checks nothing and the manifest predicate reports "0 contract(s) given — 0 checked", so the gate would pass vacuously — the same defect one layer down. **Witnessed 2026-09-09** freezing the two late-lane contracts (AMEND-BATCH-V-003, `e8d39d7d`), which needed a declared `SKIP=lane-contract-check` with the property verified by hand instead: the same checker over all eight contracts returned 8/8 OK and "contract-manifest predicate ([#630]): 1 open batch(es), 8 contract(s) — OK" · Done when: `check` resolves a batch's contract set from the MANIFEST'S OWN DIRECTORY rather than from argv, with a trip-test proving an incremental addition to a frozen batch passes and a genuinely mismatched set still refuses both ways; the gate cannot reach the "0 checked" vacuous state on a commit that stages a contract; and the `pass_filenames` disagreement between `check`'s docstring and `.pre-commit-config.yaml` is closed in whichever direction the fix makes true, so neither describes a hook that does not exist · refs `scripts/gen_lane_contract.py` (`check`, `_check_manifest_contract_agreement`), `.pre-commit-config.yaml` (`lane-contract-check`), `scripts/batch_manifest.py::freeze_manifest_contract_agreement`, `[#630]`, `docs/audits/2026-09-08-technical-batch-v-manifest.md` (AMEND-BATCH-V-003), `[#652]` · kill-candidates: none — `[#630]` is the row that BUILT this predicate and is closed by its landing;
