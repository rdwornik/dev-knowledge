- [#750] [P1][M] **A merge can land with no receipt, the completeness predicate flattens a verdict state machine into a boolean, and `wall_seconds` records serial time rather than the arc span** - Reserved at the batch Y freeze (`docs/audits/2026-09-14-technical-batch-y-manifest.md`) and ruled by **AY1-1** in `to-cc/AMEND-BATCH-Y-ROSTER-001.md`: *"completeness is judged on the suite step's VERDICT STATE, not its exit code. `PASS` or `PRE-EXISTING` -> COMPLETE with the state recorded by name; `REGRESSED`, or a verdict that cannot be read -> INCOMPLETE and the merge is refused. Forcing the step to exit 0 is ruled out by name (`[#744]`'s false pass)."* **Three defects, one module, and all three are recorded in the live ledger rather than reasoned about.** · **(1) THE COMPLETENESS PREDICATE IS UNREACHABLE BY CONSTRUCTION, so `[#744]`'s fix bought a number that can never be computed.** `Receipt.incompleteness_reason()` leg 3 refuses any receipt with a failed step and `failed_steps()` is `[s for s in self.steps if not s.ok]`; `REQUIRED_STEPS` includes `suite`; and the suite step's `ok` comes from `actions_verdict`, whose `Verdict.ok` is `self.state == STATE_PASS` under a docstring that says so in capitals — *"ONLY `PASS` is ok. Every other state is non-zero, including PRE-EXISTING"*. While `main`'s Actions `pytest` job is **pre-existing red** — measured 2026-09-13, `actions_verdict --sha 57f46622 --baseline 786ed642` → exit 1, state `PRE-EXISTING` — **every** receipt is incomplete however clean the merge was, and target 3.6's median stays **UNDEFINED, not zero**, after six flawless merges. The consequence for the rule this row also asks for is exact: *"a merge that lands without a COMPLETE receipt is refused"* refuses **every** merge, fail-closed, the moment it ships. The distinction that rescues it already exists one layer up and is thrown away at the boundary — the receipt records a flattened `ok` where `actions_verdict` computed a five-state machine. · **(2) `wall_seconds()` SUMMED THE TIMED CHILDREN AND PRINTED THE SUM AS THE ARC'S WALL TIME.** `logs/MERGE-RECEIPTS.jsonl` row `lane-x-675-step-7` was opened `2026-09-12T19:13:21` and closed `22:14:41` — **a span of 3h01m20s** — and recorded **`"wall_seconds": 1.776`**, because the one child it wrapped ran for 1.776 s. The sibling row `lane-x-675-step-4` spans 28m54s and records 1121.543 s (18m42s), losing 10m12s the same way. **The lost time is not incidental — it is the entire quantity this programme exists to itemise.** The baseline is `84 min wall = 11.3 targeted tests + 72.7 residual ceremony`, and the 72.7 lives precisely in the gaps *between* timed steps: reading a diff, deciding, waiting on a reviewer. An arithmetic that cannot see those gaps reports the 84-minute merge as an 11-minute one, meets target 3.6 spectacularly, and leaves the `~90`/`~63` disagreement exactly where it was — nothing in the receipt attributes the other 73 minutes, which is the row `[#675]` was filed about. Same failure class as an unrecorded STEP, one layer up at the arc: a plausible, flattering value returned because the discriminating field is absent from what the reader looks at. · **(3) NOTHING REFUSES A MERGE THAT LANDS WITH NO RECEIPT AT ALL, and the receipt cannot even name which merge it is of.** `/lane-integrate` opens ONE receipt per BATCH (`open --slug batch-<n>`), so `REQUIRED_STEPS` is satisfied by whichever lane happened to record a step id first, the per-merge itemisation target 3.1 asks for does not exist, and a median over such rows is a median over BATCHES reported as *"median merge minutes"* — the `kind`-field failure with the discriminator moved one level out. The receipt carries no merge SHA, so *"does this merge have a receipt"* is not a question the ledger can answer, and the whole of the enforcement is the command file's own honest limit: *"it times what it is asked to time"*. · **What must NOT be done, ruled out by name:** forcing the suite step to exit 0, adding a flag that types a verdict state onto a receipt, or admitting `REGRESSED` as complete. Each buys a defined median by making the measurement lie, which is `[#744]`'s false pass reached by a cheaper route. · Done when: `/lane-integrate` writes a `kind=merge` receipt **per merge** carrying wall, test and ceremony minutes, each receipt bound to the merge SHA it timed; completeness is judged on the suite step's recorded verdict **STATE** — `PASS` or `PRE-EXISTING` is COMPLETE **with the state recorded BY NAME** on the receipt and in the ledger row, `REGRESSED` or a state that cannot be read (`NO-RUN`, `IN-PROGRESS`, `GH-UNAVAILABLE`, `JOBS-UNREADABLE`, `UNATTRIBUTED`, or absent) is INCOMPLETE and **refuses the merge**, with the state named in the refusal; a `tests`-class step's exit code is out of the predicate and still **printed**, so the pivot cannot launder a red step into silence; there is **no flag anywhere** that can type a state onto a receipt and a test asserts each absence; `wall_seconds` is the span `opened -> closed` with the summed-children figure kept under its own name and the **untimed remainder reported by name**, so the baseline's two buckets sum to the arc rather than to the part of it that happened to be timed; a merge in the integrator's walk range with **no COMPLETE receipt** is REFUSED by a command with an exit code, which NAMES both the unreceipted merges and the receipted ones and distinguishes a clean walk from an empty range rather than printing OK for both; a bad revision range **fails closed** rather than reporting zero merges; and the RED-first witnesses per ADR-108 §B exist and are red before the enforcing code — a merge with no receipt fails, a `REGRESSED` receipt fails, a `PRE-EXISTING` receipt PASSES · **Done-when authored by lane `lane-y-750-merge-receipts`** from its frozen contract and ruling AY1-1 · refs `scripts/merge_receipt.py` (`Receipt.incompleteness_reason` leg 3, `failed_steps`, `wall_seconds`, `baseline_split`, `median_report`, `REQUIRED_STEPS`), `tests/test_merge_receipt.py` (the RED-first witnesses), `scripts/actions_verdict.py` (`Verdict.ok`, `STATE_PASS` / `STATE_PRE_EXISTING` / `STATE_REGRESSED` / `STATE_NO_RUN` / `STATE_IN_PROGRESS` / `STATE_UNAVAILABLE` / `STATE_JOBS_UNREADABLE` / `STATE_UNATTRIBUTED`, `REMEDIES`, `verdict_for`'s `fetch` seam), `.claude/commands/lane-integrate.md` (§2's merge walk and §3's refuse-to-finish checklist), `logs/MERGE-RECEIPTS.jsonl` (rows `lane-x-675-step-4` and `lane-x-675-step-7` — the two witnesses), `docs/audits/2026-09-14-technical-batch-y-manifest.md`, `to-cc/AMEND-BATCH-Y-ROSTER-001.md` (ruling AY1-1), `[#675]` (targets 3.1/3.2/3.3/3.6 — the parent programme, open), `[#744]` (the completeness predicate this row makes reachable, open), `[#742]` (the `JOBS-UNREADABLE` state this row's refusal reads), `[#752]` (sequenced behind this row on `scripts/merge_receipt.py`), ADR-108 (§B, RED-first), ADR-111 · kill-candidates: none -- `[#675]` owns the six-target merge-cost programme and stays open as this row's parent;
