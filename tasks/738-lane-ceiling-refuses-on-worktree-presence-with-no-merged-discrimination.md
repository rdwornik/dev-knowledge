- [#738] [P2][S] **`lane-ceiling --check-worktrees` refuses on worktree PRESENCE, so a wave-2 batch is refused by a prior wave's lane awaiting merge and the only offered remedy destroys it** - Filed on operator instruction 2026-09-12 as one of a pair of detectors that return a uniform answer because the discriminating field is absent from what they read; `[#739]` is the other, and **`[#675]` is the class they both belong to**. · **Witnessed, not theorised.** The dispatcher seat ran the STEP 0 refusal exactly as `SEAT-BOOT-dispatcher.md` §2 instructs — `uv run --locked python scripts/seat_refusals.py lane-ceiling --check-worktrees --lane … --lane … --lane …` for a three-lane wave-2 plan — and got: *"REFUSED [lane-ceiling]: the ceiling was checked LATE: 1 lane(s) already provisioned (…/lane-x-691-routing-half-a) — run this at STEP 0, before the first worktree exists; run afterwards the number is decorative and every remaining option is a teardown"*. **The count was never the problem:** the same three lanes without `--check-worktrees` return `lane-ceiling: PASS — 3 lane(s) <= 6, checked before any worktree exists`. · **The refused-on worktree was work AX24-1 ordered MERGED, not torn down.** `lane-x-691-routing-half-a` held wave 1's routing Half A, unmerged at the time of the check. The refusal's only stated remedy is teardown, and taking it would have destroyed seven commits of unmerged work — so the seat could neither satisfy the gate nor act on its advice. · **The discriminating field is the worktree's MERGE STATE, and the check never reads it.** `git merge-base --is-ancestor <branch> main` is one command and separates the two populations completely: a lane already contained in `main` is a husk and teardown is correct; a lane not yet contained is unmerged work and teardown is data loss. The check reads only presence, so it returns the identical refusal — and the identical dangerous remedy — for both. · **It was harmless ONLY by accident this time.** AX24-1 independently ordered the merge first, so the one action that cleared the gate was already the ruled next step. A batch that legitimately wanted to open wave 2 alongside a pending merge gets a refusal it cannot clear without destroying work, and the accident does not generalise. · **`--provisioned` is not an escape.** It is the self-report alternative to `--check-worktrees` (the boot prose explicitly prefers the live read *"rather than asking you to self-report what you have already provisioned"*), and the refusal fires on any provisioned lane from either source. There is no flag expressing "provisioned by a prior wave, pending integration", so the only way past is to drop the live-read flag — i.e. to defeat the check rather than satisfy it. · Done when: `lane-ceiling --check-worktrees` **discriminates by merge state** — a worktree whose branch is already an ancestor of `main` is reported as a husk owed teardown, and a worktree whose branch is NOT an ancestor is reported as unmerged work that must be merged or preserved, **never as a teardown candidate**; and a **RED-first witness per population** proves the two verdicts differ before the fix makes them differ — one fixture with a merged branch, one with an unmerged branch, the second asserting the refusal text does not offer teardown; and the refusal names the merge-state command it used, so the seat can check the claim rather than trust it · refs `scripts/seat_refusals.py` (`lane-ceiling`, `--check-worktrees`, `--provisioned`), `protocols/PLAYBOOK.md` Ch8 ("The ceiling is checked at STEP 0, and it is a REFUSAL"), ADR-110 (the six-lane ceiling), `docs/audits/2026-09-11-technical-batch-x-manifest.md`, `[#739]` (the sibling detector), `[#675]` (the class: a check that passes or fails uniformly because the discriminating field is absent from what it reads), `[#716]` (the adjacent worktree-provisioning defect, closed 2026-09-12) · kill-candidates: none — `[#739]` is the sibling instance in a different organ and neither subsumes the other; `[#675]` owns the CLASS and a defaulting read over a heterogeneous node list, and would describe this defect rather than fix this organ · source: dispatcher seat, batch X wave 2 boot, 2026-09-12; recorded live in `to-browser/SESSION-dispatcher.md` §3 and filed on the operator's explicit instruction in the same session
