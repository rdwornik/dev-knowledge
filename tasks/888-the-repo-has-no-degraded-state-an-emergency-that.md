- [#888] [P1][M] **The repo has no DEGRADED state -- an emergency that removes a required component can only lie to the gate or stop work** - Operator order 2026-09-17, at the architect handoff cut, filed for the next window because it outlives that handoff. There is no way to record "this required component is deliberately absent, owned by X, expiring on Y". `fleet_parity._eval_row` emits `MUST-absent` for a missing required surface and returns before it reads any declaration, and ADR-102 forbids marking a MUST row `waivable`. So when the 2026-09-17 emergency (`disableAllHooks`, merges `33246c0a`, `9af353f7`) removed three required hooks (`settings-precommit-arm`, `settings-stop-backpressure`, `settings-deny-and-point`), the pre-handoff preflight refused the cut on three hard-fails and the repo had exactly two moves: demote the tier, which lies to the gate and turns a temporary state permanent with no expiry, or stop work. **A third move was found only because a measurement existed:** lane ab-808's per-hook bypass rates (`docs/audits/2026-09-16-technical-lane-ab-808-guard-timeout.md` AMENDMENT 1) showed the three required hooks were not among the nine wedging ones, so the fix was to restore those three and disable the nine individually (`.claude/settings.json` key `//hooks-RESTORED-AND-DISABLED-INDIVIDUALLY-2026-09-17`, proven in three live sessions). That measurement must not be a precondition for making an emergency recordable: the next emergency may have no measurement, or may genuinely need a required component off.
