An organ the model cannot find is not used, and refusing the grep without making the organ findable just leaves the model stuck. The two rows are complements and should land in that understanding. · **Progressive disclosure makes the DESCRIPTION the load-bearing field, and AX9-2 says so directly.** The model does not read every skill body when choosing; it matches on descriptions. So a description that names the organ ("queries the file-purpose graph") is nearly useless, and one that states the SITUATION ("use when you need to know what triggers a file, or whether an organ already answers a need") is what gets matched. The row's quality lives entirely in that field. · **RENDERED FROM THE INDEX, NEVER HAND-WRITTEN**, which is what stops this becoming another surface that rots. A hand-written skill per organ would drift from the organ-index the first time an organ was added, and the drift would be invisible -- the skill would keep describing an organ that changed. Generation makes the index the single source and the skills a view of it. It also means `[#719]`'s schema work directly improves this: an organ-index entry with `owner` and `lifecycle` renders a better description than one without. · **AX9-2 names this as `[#617]`'s simplest form and its first deliverable** -- the prompt distiller's thesis is that the repo distils intent into the commands, skills and hooks a given model runs, and rendering skills from the organ index is that mechanism at its smallest. `[#617]` stays the general row; this is the first concrete instance and does not close it. · Done when: every organ in `ecosystem/organ-index.md` that ANSWERS A QUESTION has a corresponding skill RENDERED from the index rather than hand-written; each description states WHEN to invoke it -- the situation, not the organ's name -- since that is what progressive disclosure matches on; a freshness gate refuses a hand-edited generated skill or an index entry whose skill did not re-render; and no skill is authored for an organ that answers no question · **Done-when authored by the filing lane** from AX9-2's clauses · refs `docs/intake/2026-09-11-tech-batch-x-roster.md` (intake 93, Part 9 AX9-2), `to-cc/AMEND-BATCH-X-ROSTER-009.md` AX9-2, `ecosystem/organ-index.md` (the source), `.claude/skills/`, `[#617]` (the prompt distiller this is the first deliverable of -- NOT closed by this row), `[#727]` (the refusal leg), `[#729]` (the tools leg), `[#719]` (the organ-index schema whose fields improve these descriptions), `[#132]` (the organ-index generator) · kill-candidates: none -- `[#617]` is the general distiller and this row is explicitly named as its FIRST deliverable rather than its whole; `[#132]` owns generating the index this renders FROM · source: `to-cc/AMEND-BATCH-X-ROSTER-009.md` AX9-2, filed by lane `lane-x-000-batch-x-roster-lands`
