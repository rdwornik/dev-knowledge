- [#631] [P1][M] **A freeze cannot bind a rule that post-dates it — and nothing re-validates a frozen batch when the rules change** — **Integrator defect (c), ruled 2026-09-01, [#629]-class.** Batch F froze seven lane contracts through both gate layers with zero deviations. **Hours later the GO added a rule — "no lane runs without a review lane" — and ALL SEVEN lanes violated it**, because no frozen contract named a reviewer and the manifest declared none. The freeze was correct against the rules that existed when it ran; it is simply not bound by a rule invented afterwards, and **nothing anywhere notices that.** The same window produced a second instance: R-MODELS ruled sonnet for workers, and six of the seven contracts declare `opus` because they were generated from a default and frozen before anyone measured what dispatch actually applied (`docs/audits/2026-09-01-verification-model-routing-witness.md`). **The general shape: a freeze is a point-in-time assertion against a rule set, and the rule set is not pinned, not versioned, and not re-checked at dispatch.** A batch can therefore be simultaneously *validly frozen* and *non-compliant*, with both facts true and neither visible — the exact ambiguity `[#629]` and `[#630]` exist to remove one layer down · Done when: the freeze RECORDS the rule set it validated against (a version, a ruling-register cursor, or the set of rule ids live at freeze — the mechanism is the arc's to choose); **dispatch RE-VALIDATES against the live rule set and REFUSES a batch whose rules have moved since its freeze**, naming which rule arrived after and which lanes it touches; an additive amendment is the sanctioned discharge and is recognised as one, so a re-freeze is required only when the delta SUBTRACTS (the `[#629]` boundary); and one RED-first witness replays batch F's own case — seven lanes frozen, a review-lane rule added afterwards, refusal naming all seven · refs `docs/audits/2026-09-01-technical-batch-f-manifest.md` (AMENDMENT 2, the live instance), `docs/audits/2026-09-01-verification-model-routing-witness.md` (the second instance), `scripts/validate_substrate.py`, `scripts/batch_manifest.py`, `[#629]`, `[#630]`, `[#614]` · kill-candidates: none — `[#629]` is a contract contradicting itself and `[#630]` is two surfaces disagreeing at one moment; this is the SAME surface disagreeing with itself across TIME, which neither predicate can see · **RULED MECHANISM (operator, ADR-108 §A, 2026-09-01) — THE CONTRACT'S ROUTING TABLE IS THE SINGLE SOURCE OF MODEL TRUTH.** Three surfaces default to `opus` independently today and none checks another, which is how five batch-E lanes ran opus with every committed surface reporting otherwise. The ruled shape, three legs: **(i)** `DispatchHelpers` **drops its `[string]$Model = 'opus'` default (line 96) and READS the contract** — a default that silently outranks a frozen declaration is the defect, not a convenience; **(ii)** `gen_lane_contract` **asserts contract-model == dispatch-model**, exactly as it already does for the dispatch VERB, whose refusal text is the precedent in its own words — *"two forms free to disagree is the class this generator removes"*, closed for the verb and left open for the model; **(iii)** the ledger's model column **reads the `.jsonl` turn witness, never the declaration** — and `[#615]` is what would make that witness a repo surface rather than a per-machine one, since `~/.claude/projects/` is outside the repo and is not a governance surface.
