The lane ran the suite at its default parallel invocation and then found its own result disqualified on two independent grounds, BOTH recorded the same day in `docs/audits/2026-09-11-technical-w278-ship-gate-baseline.md`: (1) that audit's own closing section states plainly that a run from a WORKTREE is inflated by worktree-context artifacts -- *"the pass/fail COUNTS above are worktree-inflated. The wall-times are the transferable half; the pass/fail counts are not"* -- and this lane runs from a worktree; (2) the same audit states that *"measured while a sibling run saturates sixteen workers measures the sibling"*, and three sibling lanes were live on the box throughout. A number produced under both conditions would not be the Windows baseline; it would be an artifact of where and when it was taken. · **THE NEAREST VALID MEASURED NUMBER, and its caveat, so the row starts from evidence rather than nothing:** the W-7 ship-gate baseline measured the full suite at `2040653c` with `pytest -n auto --dist worksteal --max-worker-restart=0 --timeout=900 --tb=no -q` and recorded **33 failed · 5682 passed · 8 skipped** in 1446.49 s. That 33 is itself worktree-inflated by its own note, which is consistent with the operator's 26-28 once worktree artifacts are removed -- and the gap between 33 and 26-28 is roughly the size of the worktree-artifact set, which is a finding in itself rather than noise. · **SO THE FIRST ACT OF THIS ROW IS THE MEASUREMENT, AND ITS CONDITIONS ARE PART OF THE WORK:** the count must be taken from the PRIMARY CHECKOUT on an otherwise quiet box, because nowhere else produces a number that means anything. That a routine repo fact is this hard to establish is not incidental to the row -- it is the same defect seen from another side. · **Why a red baseline is worse than the failures in it.** A suite with a known-red set has no usable pass/fail signal: every run must be diffed against a remembered list, and the remembering is done by whoever is looking. A new failure lands inside the noise and is indistinguishable from the noise. This is the same defect class as a stale generated index -- the artifact still renders, so nobody notices it stopped meaning anything. · **Each is fixed OR dispositioned with a reason, and there is no third state.** A disposition is not a defeat: a test that cannot pass on Windows for a stated, recorded reason is honest, and `skipif` with a reason plus a reporting surface is a mechanism. What is not admissible is a test that just fails every run and is stepped over. Note the coupling that makes this non-trivial: adding a `skipif` trips the proof-layer ratchet (`[#638]`), so the disposition route has its own gate to satisfy and cannot be applied wholesale. · **Test management is four rows and AX8-3 names the set**: B1 impacted selection (`[#278]` / `[#703]`), B2 refusal without a test, B3 one full suite per batch (AX1-3), and this row. This is the baseline half -- without it the other three measure against noise. · Done when: each of the permanently-RED tests on the Windows baseline is either FIXED or DISPOSITIONED with a recorded reason; **the baseline count is first established from the PRIMARY CHECKOUT on an unloaded box** and recorded with its commit, since a worktree run and a run under sibling load both measure something else; the count is re-measured the same way at the closing commit; no test remains in the fails-every-run-and-is-stepped-over state; and the disposition route satisfies the proof-layer ratchet rather than bypassing it · **Done-when authored by the filing lane** from AX8-3, with the measured count substituted for the amendment's 26 per the operator's correction · refs `docs/intake/2026-09-11-tech-batch-x-roster.md` (intake 93, Part 8 AX8-3), `to-cc/AMEND-BATCH-X-ROSTER-008.md` AX8-3, `[#725]` (the xdist frozenset-identity pollution AX8-3 directs to its own row), `[#278]` (the test-suite-hygiene epic), `[#703]` (empty-selection hardening), `[#638]` (the proof-layer ratchet a `skipif` disposition trips), `[#583]` (green-by-skip -- a check that cannot obtain green), `[#673]` (six batch-V suite REDs unattributed), `[#457]` (inherited live-repo test failures) · kill-candidates: none -- `[#673]` owns SIX specific batch-V reds and their attribution, a subset this row would subsume only if they are still in the set at close; `[#457]` owns failures inherited from live-repo coupling rather than the Windows baseline as a whole; both should be read beside this row at grooming and may fold into it · source: `to-cc/AMEND-BATCH-X-ROSTER-008.md` AX8-3 with the operator's correction of 2026-09-11, filed by lane `lane-x-000-batch-x-roster-lands`
