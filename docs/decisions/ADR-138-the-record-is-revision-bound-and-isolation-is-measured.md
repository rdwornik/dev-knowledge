# ADR-138: The record is revision-bound and isolation is measured -- one cause enum, the verdict key in the receipt, a hash-frozen contract, and two computed rates

## Context

The harness records outcomes but not causes: five closed enums classify an outcome (phase_receipt Outcome and status, lane_report State, challenge Verdict, known_reds buckets) and none names why a run failed. [#1047] asks for a 9-category agent-error enum in `scripts/review_packet.py`, but that module assembles context and by its own invariant judges nothing (`scripts/review_packet.py:41`), so it has no verdict schema to carry one. Phases are spawned and receipted by `scripts/run_phase.py`, not by the conductor (`scripts/conductor.py:902` runs the doit round): run_phase hashes the inputs (`scripts/run_phase.py:435`) and mints the nonce, but it resolves `{base}` to the string `origin/main` (`scripts/run_phase.py:294`) and records no base, head or tree sha, so a receipt binds its input, not the revision it judged. ADR-121 D5 specifies the verdict key, in an event log that does not exist. The contract writers refuse an existing file but `--force` overrides it, the contract path has no round (`scripts/gen_lane_contract.py:2366`), and no frozen hash is recorded. No ledger holds reviewer verdicts against a key and no script computes an approval rate or kappa. Independence is checked by model-name equality (`scripts/decide_checks.py:265`) and by (provider, session_id) (ADR-134 D4), which proves different sessions, not different context; `--add-dir` does not confine agy (`docs/audits/2026-08-29-technical-nb2-o-packet.md:233`). The registry knows four model families. The AJ batch measured independence outside the repo, and its M2 re-ruling measured self-adjudication: 22 of 33 rulings flipped, 20 toward the challenger.

## Decision

The design extends what exists (option O2 of the evidence): the ADR-134 records gain the fields, run_phase fills them, one schema enum carries the cause, and one measure module computes (c) and (d). No new organ beyond that module; no event log is assumed.

- **D1 -- one closed cause enum, `FailureClass`, beside Severity.** A single `Literal` in `ecosystem/schema/phase_receipt.py`, next to `Severity`, with two prefixed groups and one residual:
  - `agent:` the nine [#1047] categories, unchanged in meaning: misread-question, wrong-entity, stale-source, omitted-evidence, wrong-tool, misread-evidence, bad-inference, should-have-abstained, weak-answer.
  - `mechanism:` spawn-failed, timeout, killed, nonzero-exit, no-valid-payload, quota, network, gate-red, input-refused, contract-stale, merge-conflict.
  - `UNCLASSIFIED`.
  Carriers and the single-cause rule: `PhasePayload` gains a top-level `failure_class` the agent writes when its outcome is FAIL or REFUSE, and each `Finding` may carry one (optional). `PhaseReceipt.failure_class` is always present when status is FAILED or KILLED or the outcome is FAIL or REFUSE, and holds exactly one value chosen by run_phase deterministically: (1) a mechanism cause derived from run_phase's own run branches (spawn failure, timeout, kill, non-zero exit, no fresh valid payload; the branches that today set `reason`, `scripts/run_phase.py:205-216`) wins; else (2) the payload's top-level `failure_class`; else (3) the cause of the highest-severity finding that has one, ties broken by finding id; else (4) `UNCLASSIFIED`, written by run_phase, never by an agent, so a receipt is always written and never fails validation for want of a cause. The ADR-134 `StageRecord` copies its stage's cause. The UNCLASSIFIED share is a reported number. A data table in the same module maps existing enum values that imply a cause (known_reds buckets to `mechanism:gate-red`) so no existing enum is rewritten. Adding a member is a schema version bump. `review_packet.py` is not changed: [#1047]'s done-when names a module that judges nothing, so this ADR proposes that its done-when be read as "the verdict schema" = PhasePayload and PhaseReceipt (an operator question). What it adds beyond ADR-134/122: ADR-134's StageRecord has no outcome and ADR-122's `status_reason` is free text.
- **D2 -- the verdict key travels in the receipt now (ADR-121 D5, without the log).** In the same schema version as ADR-134's `session_id`, `PhaseReceipt` and `StageRecord` gain `base_sha` (the resolved sha of `{base}`, which run_phase passes to the phase instead of the ref name), `head_sha` and `tree_sha` (stamped by run_phase at harvest, after the phase exits, so a P2 or P3 receipt binds the tree that phase produced, and a review receipt binds the tree that was current when the reviewer finished), `contract_sha256`, `baseline_id` (the known-reds or suite baseline the phase stamped, or absent when the phase runs no suite) and `comparison_policy` (the id and version of the comparator that turned results into the verdict, e.g. the known-reds comparator; absent when none). With gate (`phase`), `input_hash` and the ADR-134 execution context (provider, session_id, served model) these are ADR-121 D5's key; contract hash and comparison policy are separate fields, not one. For a review or judge phase, the diff `base_sha..head_sha` as given to the reviewer is written as a file and listed in `inputs`, so `input_hash` covers the bytes the reviewer was given; a reviewer's payload must echo the `tree_sha` it was given, and a mismatch with the harvest stamp makes the receipt stale. This binds what the reviewer was given, not what it attended to; no record can prove the latter. `land_lane` refuses a merge unless every receipt that ADR-134's stages 5 and 6 require exists, is complete, and carries the `tree_sha` of the lane tip being merged and the current `contract_sha256`; `baseline_id` and `comparison_policy` are compared only among receipts that carry one. Tree, not commit, so an unchanged tree under a new commit still lands. Carrier: receipts are gitignored per worktree (`logs/receipts/`), and land_lane runs in an integration worktree; land_lane reads the lane worktree's `logs/receipts/LANE-<slug>/` by path, read-only, the same sibling read ADR-133's ruling allows and the same artifact ADR-134's landing check reads; a lane whose worktree is gone cannot land on this check (refused, naming the missing path). The nonce keeps its narrower meaning (S-03 as ruled at DIGEST-AJ-FULL-ANALYSIS-2026-10-31.md:40). M2 flip agy:G-17 (DIGEST-AJ-P78-MEASUREMENT-2026-11-01.md:64), "the base binding is partly present", is answered here: the input binding exists in run_phase and is kept; the revision binding is added. When ADR-121 is ratified, a verdict event carries these fields and the carrier becomes the shared ref.
- **D3 -- a contract is frozen by hash; a later write is refused or detected.** Stage 2 writes a StageRecord with `contract_sha256` over the contract bytes, keyed by (lane, round); that record is the freeze. After it exists, `gen_lane_contract.py emit` and `distill` refuse the contract path even with `--force`; the only way to write it is a new `--refreeze` flag that writes the contract, writes a new stage-2 record for round + 1, and so makes every receipt carrying the old `contract_sha256` stale and its stage incomplete. The contract path stays round-less (`LANE-<slug>.md`); the round lives in the freeze record. A write by any other means (an editor, a script) cannot be prevented; it is detected: run_phase refuses to spawn a phase when the contract file's sha differs from the current freeze, and D2's land check refuses on a mismatch. The guarantee is that a reviewed contract and the landed contract are provably the same bytes, not that the file cannot change.
- **D4 -- approval quality is measured against an adjudicated key, never against another reviewer.** One module, `scripts/verdict_quality.py` (stdlib only), reads receipts and writes an append-only key ledger `logs/VERDICT-KEY.jsonl` and a computed report.
  - Scope: P6 review and P7 judge receipts that carry D2's fields. `lane_report` Review verdicts have no tree binding and are out of scope until they do.
  - The key view: the frozen contract and the diff `base_sha..head_sha` from the receipt, nothing else; not the ADR-134 D3 view verbatim, because that view carries the P6 reviewer receipts and would show a judge the verdict it re-judges.
  - The judges: two judges from two families other than the producer's and the judged reviewer's, chosen from the registry's `family:` field and its judge-eligible roles. With four families known, that leaves at most two, so there is no tie-break: an item is keyed when the two agree and is `UNKEYED (disagreement)` when they do not; an item with fewer than two eligible families is `UNKEYED (no families)`. Both counts are reported; the orchestrator and the producer's family never rule.
  - The rates: rubber-stamp rate = keyed approvals the key finds defective / keyed approvals; false-reject rate likewise; each with a Wilson 95 percent interval. Cohen's kappa between verdict and key, with a seeded bootstrap 95 percent interval (1,000 resamples). Below 30 keyed approvals a rate is `NOT COMPUTED` with its n.
  - The threshold: WARN when the Wilson lower bound of the rubber-stamp rate exceeds 0.10. Advisory: nothing blocks on it in this ADR.
  - Reviewer-to-reviewer reversal (the 13/36 of DIGEST-AJ-FULL-ANALYSIS-2026-10-31.md:42) is reported as disagreement, a separate number, never as rubber-stamping. [#625] is a different key (rule adherence of instructions); this ADR neither folds into it nor depends on it.
- **D5 -- independence of two readers is a computed number with a threshold.** The same module computes, for a declared reader pair (two reviewers of one tree, two /decide evaluators, two extractors of one source):
  - quote-Jaccard over each reader's quoted spans: text inside backticks or double quotes, at least 20 characters, whitespace-collapsed and case-folded; the copy signal;
  - finding-Jaccard over finding targets: `Finding` gains an optional `target` (`path:line` or a record id) in the same schema bump; a target without one is parsed from `evidence` by a `path:line` pattern; two targets match when the path is equal and the lines lie within 3 of each other at the same `tree_sha`; findings at different tree shas are not compared;
  - a quote provenance check: each quote is located in the reader's legitimate sources (its harness `inputs`, plus for a reviewer every file of the tree at `tree_sha` and the diff); a quote found only in the other reader's output is a copy defect, a quote found in none of them is an out-of-scope quote. This detects copying and out-of-scope quoting; it cannot show what a reader read without quoting, and it does not claim to (ADR-134's own line: session ids prove different sessions, not different context).
  Empty sets: both empty gives `NOT COMPUTED (no items)`, never 0 or 1; one empty gives 0. Thresholds are data in one table: independent when quote-Jaccard <= 0.5 and finding-Jaccard <= 0.5, the AJ threshold (DIGEST-AJ-FULL-ANALYSIS-2026-10-31.md:123). A copy defect is reported as not independent whatever the Jaccard. The result is written to the StageRecord of the stage with two readers (ADR-134 stage 5) as `independence: {quote_j, finding_j, copy_defects, out_of_scope, thresholds_sha, verdict}`. ADR-134's (provider, session_id) check stays the precondition. Everything in D5 is advisory: it reports and blocks nothing for two batch closes; blocking is an operator decision on that data.
- **D6 -- how (c) and (d) apply to /decide's evaluators (the fix itself is row 1837 (`tasks/1837-decide-independent-adjudication-as-code.md:3`)).** P9 review section 3.3 (DIGEST-AJ-P9-REVIEW-2026-11-01.md:50-53) names the structure: the producer answers challenges to its own work, measured as biased (DIGEST-AJ-P78-MEASUREMENT-2026-11-01.md:83). Applied, with keys and links specified here (the recording itself is built with row 1837, and decide_checks.py is not changed by this ADR):
  - Artifact links: each evaluator record carries, in its header, `run-id`, and `adr-sha256` and `evidence-sha256` (sha256 of the draft ADR and evidence file bytes it was given). The response table's section carries the same two hashes for the revision the producer answered from. A key ruling records the hashes of the revision it re-judged.
  - Stable, ungrouped keys: a verdict item's key is `(run-id, evaluator file sha256, finding id)`. A response row names exactly one finding id; a slash-combined row (`id1 / id2`, which `scripts/decide_checks.py:276` accepts today) is not a keyable item and is reported as UNKEYED (grouped) until split.
  - The join: a key ruling joins its response row by that key, and only when the ruling's `adr-sha256` and `evidence-sha256` equal the evaluator's; otherwise the item is UNKEYED (revision mismatch).
  - The measures: D4 keys the producer's Rejected and partly rows and reports a false-reject rate with its interval; D5 reports the two evaluators' quote- and finding-Jaccard over the same revision. Both are reports; any blocking of ratification belongs to row 1837.
- **D7 -- not built here.** No event log, no projection, no new pre-commit gate, no change to decide_checks.py or review_packet.py. No dependency: kappa, its bootstrap and the Wilson interval are hand-rolled because stdlib statistics has none and scikit-learn would be a locked dependency (recorded in the evidence, library-first). No sampling schedule. Tests use synthetic fixtures committed by the build lane; no AJ knowledge-base content enters the repo (the KB's public-repo rule, DIGEST-AJ-FULL-ANALYSIS-2026-10-31.md:144). Nothing is built by this ADR; the build is a later lane after ratification, in the order D1, D2+D3 (one schema bump with ADR-134's PhaseReceipt v2), D5, D4.

Open for the operator: (1) the D4 threshold (Wilson lower bound above 0.10) and minimum n of 30; (2) whether D5 should block after two advisory batch closes; (3) the D4 judge families, given at most two remain after exclusion and the registry judge role admits openai and anthropic models; (4) whether [#1047] is satisfied by D1 in phase_receipt, since review_packet.py has no verdict schema; (5) the key sampling cadence.

## Quality attributes

- **Quality attribute(s):** verifiability (a verdict is bound to the tree and contract it was given; a failure has one closed cause), integrity (a changed contract is refused or detected before it lands), measurability (approval quality and reader independence are numbers with intervals and thresholds, or NOT COMPUTED with a reason), modifiability (a cause or a threshold is a data change).
- **Scenario:** Source: a lane, a reviewer, a /decide producer, or the operator. Stimulus: a phase fails; a reviewer approves; a contract is edited after its freeze; a commit lands after review; two readers report on one source; the operator asks how often approvals are rubber stamps. Artifact: PhaseReceipt, StageRecord, run_phase, gen_lane_contract, land_lane, `scripts/verdict_quality.py`. Environment: a lane worktree and an integration worktree before ADR-121 exists, then after. Response: a failed receipt carries one FailureClass and is always written; a contract write after freeze is refused, or detected at spawn and land; a land whose tree differs from the reviewed tree, or with a required review missing, is refused; the report gives rates with intervals or NOT COMPUTED with n; a reader pair gives quote- and finding-Jaccard and a verdict.
- **Response measure:** 100 percent of FAILED or KILLED receipts or FAIL/REFUSE outcomes carry exactly one FailureClass, and a fixture with an empty-findings FAIL payload and one with a bare non-zero exit each still write a valid receipt (tests); a contract write after freeze exits non-zero even with --force, and --refreeze makes old receipts stale (tests); a land with a mismatched tree sha, a missing required receipt, or a stale contract hash is refused, and receipts without a baseline do not refuse (fixture tests); every rate below n=30 reads NOT COMPUTED and kappa's interval comes from the seeded bootstrap (tests); synthetic reader pairs with a planted copied quote, a planted out-of-scope quote and two empty finding sets give copy defect, out-of-scope and NOT COMPUTED (fixture tests); zero dependencies added to pyproject.toml or uv.lock.
- **Decision evidence:** the matrix in the design evidence (O2 3.20 against O4 2.45, O1 2.40, O5 2.30, O3 2.30, O0 2.25), whose only measured lead is reuse: the receipt fields O2 extends (`ecosystem/schema/phase_receipt.py:181`, `ecosystem/schema/phase_receipt.py:195`), the receipt builder that already hashes inputs (`scripts/run_phase.py:240`, `scripts/run_phase.py:435`) and the existing contract refusal (`scripts/gen_lane_contract.py:2367`); the absence probes (no cause enum, no revision sha, no rate or kappa code, no reader-Jaccard code); the M2 flip agy:G-17 and the P9 section 3.3 structure; the evaluator responses.

## Flip-condition

- Switch D2 and D3's carrier to ADR-121 events if ADR-121 is ratified before the build lane starts; the fields stay the same.
- Split D1 into two enums (agent and mechanism) if after two batch closes more than 20 percent of failures are UNCLASSIFIED or a record honestly needs both an agent and a mechanism cause.
- Drop tree-sha binding for commit-sha binding if the build lane measures that a landing path rewrites trees after review (none is known).
- If the sibling read of D2 proves unavailable in practice (lane worktrees torn down before landing), carry the key fields in the lane's merge trailers (ADR-135's single trailer writer) instead.
- Make D4 or D5 blocking only on two batch closes of data and an operator ruling; drop D5's finding-Jaccard leg if it flags pairs that the D4 key shows found the same real defect.
- Adopt a statistics dependency only if the measure module grows past simple rates, through a separate ADR-106 decision.

## Alternatives considered

- **O0 status quo:** rejected; no cause, no revision binding, nothing measured (matrix 2.25).
- **O1 each of (a)-(d) as its own organ:** rejected; four organs to wire and gate where two are fields on records that exist (2.40).
- **O3 wait for ADR-121's event log:** rejected; a log stores verdicts but measures nothing, it is Proposed, and D2 already uses its key so the later fold is a carrier change (2.30).
- **O4 one registry-driven check set read by existing gates:** rejected as the frame; its useful part, the cause mapping table and the thresholds as data, is kept inside D1 and D5 (2.45).
- **O5 [#1047] literally plus /decide-only checks:** rejected; review_packet.py has no verdict schema to carry the enum, receipts would stay without a cause, and only /decide would be measured (2.30).
