## Context

VISION.md (per ADR-33) declares .dev-knowledge as auditor for ecosystem
repos. Lifecycle section explicitly states: "Verification mechanism:
implemented via .dev-knowledge auditor (Stream C audit tool — pending)."

ADR-36 formalizes audit tool architecture. Without this tool:
- No systematic Scale tier assessment (per ADR-40, when ratified)
- No VISION.md compliance verification (per ADR-33)
- No file naming compliance verification (per ADR-34)
- No lessons discovery configuration check (per ADR-35)
- No architecture compliance check (per ADR-38)
- No actionable reports for child repo browser chats
- No ecosystem state tracking over time

Council research debate (council-out-20260430-125039-*) validated
architectural choices via prior art:
- Append-only audit logs pattern (mirrors Git mechanics)
- LLM Wiki pattern (Karpathy) — structured Markdown over SQLite/vectors
- Transient catalogs (sirup pattern) — derived index regenerated on demand
- Session Handoff Protocol — handoff folder is emerging industry standard

Council decision debate (council-out-20260430-123043-*) covered Q1-Q12.

## Decision

### Scope (Q1) — MVP audit checks (P1)

In-scope MVP (P1):
- VISION.md presence per ADR-33 (Standard or Lite tier)
- VISION.md frontmatter parseable (version, tier, owner, scale)
- Scale declared in VISION.md frontmatter
- ADR-31 baseline violations
- Cross-repo dependencies declared (per ADR-33 trigger-based mandate)
- Universal repo architecture compliance (per ADR-38)

In-scope P2:
- File naming compliance (per ADR-34, all file types)
- Handoff folder existence per HANDOFF_PROCESS v2.0
- Two-phase handoff format compliance (per ADR-37)

Deferred (until ADR-35 implementation):
- Lessons discovery configured (env var documented, CLAUDE.md note present)
- Lessons reindex freshness

Deferred (until ADR-40 implementation):
- Scale tier mismatch (declared in VISION vs computed by tier algorithm)

Out-of-scope:
- Content quality assessment
- ADR coverage heuristics
- Security scans (separate future ADR)

### Output format (Q2) — Both report and handoff folders

Every `audit run` produces:
- **Single ecosystem report**: `docs/audits/YYYY-MM-DD-ecosystem-audit.md`
  (markdown summary across all repos)
- **Per-non-compliant-repo handoff folder** (P2 only):
  `docs/handoffs/YYYY-MM-DD-{repo}-audit-sync/`
- **JSON sidecar** inside handoff: `manifest.json` for machine consumption

No CLI-only mode. Every run produces files for traceability.

### Ecosystem state storage (Q3) — Distributed with schema separation

Distributed per-repo folders:

```
.dev-knowledge/ecosystem/
├── {repo}/
│   ├── state.yaml         # workspace-local inventory
│   └── history/           # audit findings, append-only
│       ├── 2026-04-30.md
│       └── 2026-05-15.md
└── ecosystem-index.yaml   # derived rollup, regenerated by `audit registry update`
```

Schema separation (per Council OpenAI argument):
- **Canonical truth**: child repo VISION.md frontmatter (per ADR-33)
- **state.yaml**: workspace-local inventory only (path, enabled status,
  dependencies)
- **history/**: append-only audit log per repo (validates research
  finding: append-only audit logs pattern)
- **ecosystem-index.yaml**: derived rollup, regenerated by audit tool

### Scale assessment (Q4) — Manual in VISION.md frontmatter

Audit reads `scale:` from child VISION.md and cross-checks against
state.yaml intended scale. Mismatch = audit finding (NOT auto-resolution).

When ADR-40 (Scale Tier Evaluation) is ratified, audit tool will
compute tier algorithmically and compare with declared. Until then,
manual declaration is sole source.

### Read/write boundary (Q5) — Hard constraint, read-only for child repos

Tool writes ONLY to:
- `.dev-knowledge/ecosystem/{repo}/state.yaml` (registry update)
- `.dev-knowledge/ecosystem/{repo}/history/` (audit logs append-only)
- `.dev-knowledge/ecosystem-index.yaml` (derived index)
- `.dev-knowledge/docs/audits/` (ecosystem reports)
- `.dev-knowledge/docs/handoffs/` (audit handoff folders, P2)

NEVER touches child repos. Read-only contract is hard constraint
in ADR-36, enforced via tool architecture (no write paths to child
repo paths).

### CLI (Q6) — 4 commands (Click + Rich)

```
audit run                  # full ecosystem; writes report + handoffs (P2)
audit repo <name>          # single repo
audit registry update      # regenerate ecosystem-index.yaml
audit health               # quick TTY status, no file writes
```

Drop `audit registry list` (use `cat ecosystem-index.yaml`) and
`audit handoff <repo>` (folded into `audit repo <name> --handoff`).
4 commands, not 6.

### Schedule (Q7) — Manual only for MVP

Pre-commit integration deferred. Cron deferred. Revisit at P3 based
on usage. Scheduled runs add operational surface (failure modes,
stale lock files) without proven need.

### Handoff folder content (Q8) — Two-phase format per ADR-37

Audit handoff folder structure:

```
docs/handoffs/YYYY-MM-DD-{repo}-audit-sync/
├── upload-instructions.md
├── first-message.md            # STRONG mandate per ADR-37 ("MUST validate")
└── contents/
    ├── HANDOFF.md              # two-phase format per ADR-37
    │   ├── ## Current State    # audit findings, what's compliant, what's not
    │   ├── ## Future State     # recommended actions, priority, dependencies
    │   └── ## Detailed Context # ADR-32 9-section structure beneath
    ├── manifest.json           # audit metadata + git_commit SHA
    ├── tree.txt                # repo file tree snapshot
    └── relevant-decisions/     # ADR references (NOT paragraph extracts)
        ├── ADR-33-vision.md    # full file copy if relevant
        ├── ADR-34-naming.md
        └── ADR-38-architecture.md
```

ADR section linking (full file copies), NOT paragraph extraction —
synthesis flagged paragraph extraction as regex nightmare.

### Implementation phasing (Q9) — 4 phases

**P1 MVP (separate session):** Build audit run + ecosystem state +
markdown report
- Click CLI scaffold (`audit run`, `audit health`)
- Ecosystem state schema (state.yaml + history/)
- Audit checks: VISION.md, ADR-31 baseline, ADR-38 architecture
  compliance
- Single markdown report output
- Tests: schema roundtrip, check execution, report generation

**P2 (separate session):** Handoff folder generator
- HANDOFF.md generation per non-compliant repo
- manifest.json + tree.txt + relevant-decisions/
- ADR-37 two-phase format integration

**P3 (separate session):** Scheduled / triggered runs (if usage demands)
- Optional cron / Task Scheduler integration
- Pre-commit hook on .dev-knowledge

**P4 (separate session):** LLM-augmented narrative reports
- Hybrid Python + LLM (per Rob's pushback: "fully LLM-driven goal")
- LLM generates narrative gap interpretation in handoff
- Deterministic checks remain Python; narrative is LLM-augmented

### ADR scope (Q10) — Single ADR-36

All Q1-Q12 covered in this document. No split into ADR-36 + ADR-37.

### Audit history persistence (Q11) — Per-repo append-only

`.dev-knowledge/ecosystem/{repo}/history/YYYY-MM-DD.md`

Append-only (research finding: append-only audit logs pattern mirrors
Git mechanics). Naming: date-only since repo is in folder path
(avoids double-nested `audits/{repo}/audits/` that Rob flagged).

Retention: keep all for now. Quarterly archive to
`ecosystem/{repo}/history/archive/YYYY-Q{N}/` if file count grows
problematic. Defer retention policy refinement to P4.

### Dev/CLAUDE.md (Q12) — DROPPED from scope

Dev/CLAUDE.md was empirically determined to be unused (file removed
from Dev/ during this session per Rob's verification). Out of scope
ADR-36. No further consideration.

### Implementation philosophy (Rob's pushback)

P1 starts hybrid Python + LLM:
- Deterministic checks (file presence, frontmatter parse, naming
  compliance) = pure Python
- Narrative gap reports in handoff = LLM-augmented (better human-readable
  guidance)

P4 goal: fully LLM-driven where possible, with deterministic checks as
verification layer. Audit tool itself becomes more "Scrum Master" agent,
less script.

### OPA / Rego (out of scope)

Council research surfaced OPA + Rego as policy-as-code alternative.
For solo dev with LLM-driven approach, Python validators sufficient.
OPA adds binary dependency + new language for marginal benefit at
this scale. Out of scope ADR-36, may revisit if ecosystem grows
significantly.

### Universalization (per ADR-33 pattern)

- **Mandate**: .dev-knowledge runs audit; child repos consumed read-only
- **Recommendation**: child repos provide compliant VISION.md (ADR-33),
  architecture (ADR-38), and state.yaml entry in ecosystem
- **Migration**: ai-council, corp-monorepo immediate cohort (Phase 2);
  corp-ops, corp-sca-time-automation trigger-based per ADR-33
- **Cross-repo audit (Phase 3)**: becomes possible after MVP ships +
  child repo VISION migration completes

### Research-validated architectural choices

From Council research debate (council-out-20260430-125039-*):

- **Append-only history per repo** validates Q11 decision
- **LLM Wiki pattern (Karpathy)** validates structured Markdown over
  SQLite/vector databases for state.yaml + history/
- **Transient catalogs (sirup)** validates ecosystem-index.yaml as
  derived (regenerated on demand) vs hand-maintained
- **Session Handoff Protocol** validates ADR-32/ADR-37 handoff folder
  format as emerging industry standard

Anti-patterns avoided:
- Backstage/IDP heavy infrastructure (research finding: abandonment
  failures)
- Auto-fix mode (research finding: silent context decay risk)
- Hand-maintained central indexes (research finding: drift inevitable)
- Paragraph extraction from markdown ADRs (synthesis flagged as
  regex nightmare)

### Implementation considerations (P1 details)

**Missing repo handling:** state.yaml has `path:` field. If path not
resolvable, audit emits warning + finding "REPO_UNAVAILABLE" rather
than crashing. Required in MVP (synthesis blind spot).

**Idempotency (P2 handoff):** include `git_commit: <sha>` in handoff
manifest.json. Browser chat verifies repo HEAD before executing fixes
(mitigates stale handoff risk per ADR-37 drift mitigation).

## Consequences

### Positive
- Audit tool unblocks Phase 2 universalization rollout
- Distributed canonical/derived pattern matches LESSONS.md (ADR-35),
  VISION.md (ADR-33)
- Read-only contract eliminates entire class of bugs (no cross-repo
  writes possible)
- 4-phase implementation prevents big-bang
- Handoff folder format reuses ADR-32 + ADR-37 (no new format invented)
- Research validates architectural choices via prior art
- Hybrid P1 → fully LLM-driven P4 path defined

### Negative
- Workspace inventory (state.yaml) introduces small canonical/derived
  ambiguity (mitigated by schema separation: VISION = canonical truth,
  state.yaml = workspace metadata only)
- ADR section linking (P2) instead of paragraph extraction = larger
  handoff payloads (~10KB) but reliable
- Manual schedule means audit may run rarely (Rob discipline-dependent)
- Audit tool as "Scrum Master" implies Rob acts on findings —
  enforcement is honor system

### Follow-ups
- P1 implementation (separate session): build CLI + schema + checks
- P2 implementation (separate session): handoff generator
- ai-council compliance verification (Phase 2)
- corp-monorepo compliance verification (Phase 2)
- corp-ops, corp-sca-time-automation trigger-based migration by 2026-06-30
- 6-month review: measure audit usage, surface refinements
- Council CLI dual-write trigger logic (separate concern, not blocking
  ADR-36): test debates currently pollute curated transcripts
