# ADR-83: Protocols-archive convention — where superseded protocols go

- **Status:** Accepted
- **Date:** 2026-06-11
- **Related:** ADR-39 (file lifecycle governance — immutable records superseded by a new file, not edited in place; this ADR is the protocols-folder instance of that pattern); ADR-60 (docs/ taxonomy — `archive/` = superseded/dormant; same role here for `protocols/`); ADR-82 + #149 (HANDOFF_PROCESS v5 promotion — the event that will eventually archive v4.4 under this convention); CLAUDE.md §4 File lifecycle / §5 critical rules
- **Decommission:** none. This ADR adds a convention; it removes nothing and moves no files.

<!-- scope: meta -->

## Context

`protocols/` holds the repo's live operating specs (`PLAYBOOK.md`, `ESSENTIALS.md`, `HANDOFF_PROCESS.md` v4.4, etc.). When a protocol is superseded it must leave the live set so a reader never has to disambiguate two specs claiming the same authority — but the superseded file is institutional record and must be preserved, not deleted (ADR-39 spirit; CLAUDE.md §5 immutability).

The repo already does this in practice: `protocols/archive/HANDOFF_PROCESS_v3.4.md` was moved aside on 2026-05-29 with a blockquote tombstone at file top. But the convention was never written down, so there is no documented rule for *where* a superseded protocol goes or *what* marks it as frozen. The next supersession (v4.4 → v5 at the #149 flip) needs a codified target.

This ADR codifies the **existing** convention; it does not invent a new format and does not move any file.

## Decision

**Superseded or dead protocols move to `protocols/archive/<name>.md` carrying a blockquote tombstone at the top of the file. `protocols/` (top level) holds only live specs.**

- **Tombstone format** — the blockquote already used by `HANDOFF_PROCESS_v3.4.md` is the standard (codify-the-existing, zero retrofit; that file already conforms). The opening blockquote MUST carry:
  1. the **archived date** — `> **ARCHIVED YYYY-MM-DD:**`
  2. the **superseded-by target + path** — `superseded by <successor> at `protocols/<path>``
  3. a **frozen-record line** — `Do NOT edit this file; it is a frozen historical record.`
  - A one-line *why*/supersession summary between (2) and (3) is encouraged but not required.
  - Canonical shape (from v3.4):
    > **ARCHIVED 2026-05-29:** superseded by v4 at `protocols/HANDOFF_PROCESS.md`. Preserved per ADR-39 spirit + historical reference. […summary…]. Do NOT edit this file; it is a frozen historical record.
- **`protocols/archive/` already exists** — a move populates it; it is not created anew, and an **empty** `protocols/archive/` is never created for nothing.
- **Live `protocols/` membership** — only files actively referenced as the current way of working. A deliberately-parked stub (an intentional anchor for future work) and a parallel-shipped beta are NOT "dead" and stay live; only a *superseded* or genuinely *abandoned* file is archived.

## Inventory at adoption (2026-06-11)

- **Live:** `HANDOFF_PROCESS.md` (v4.4 — **canonical, gated**; see below), `PLAYBOOK.md`, `ESSENTIALS.md`, `AI_COUNCIL_PROCESS.md`, `ENVIRONMENT.md`, `SESSION_SETUP.md`.
- **Live — parallel-shipped beta (NOT dead):** `HANDOFF_PROCESS_v5.md`, `HANDOFF_BOOT.md` (ADR-82; run alongside v4.4 until the #149 flip).
- **Live — intentional anchor (NOT dead):** `AGENT_FRAMEWORK.md` (a v0.1 not-implemented stub deliberately parked to hold the operator's structural signal; referenced by BACKLOG #1). Archiving it would lose a live forward-pointer.
- **Already archived:** `archive/HANDOFF_PROCESS_v3.4.md` (tombstoned 2026-05-29 — the template this ADR codifies).

**No file moves under this ADR** — no top-level `protocols/` file is currently dead-and-non-gated.

## Hard gate — v4.4 is NOT archived here

`protocols/HANDOFF_PROCESS.md` (v4.4) **stays canonical** for real handoffs until the v5 promotion (the Council + fresh-eyes gated flip, ADR-82). Archiving it now would leave the repo with **no canonical handoff process**. Its archival under this convention is a **#149/#151 flip-step**, explicitly out of scope for this ADR. This ADR defines *where it will go and how it will be marked* — nothing more. (Follow-through tracked as a backlog item.)

## Borderline — deferred to an architect session

- **`AGENT_FRAMEWORK.md` fate** (promote to a real spec vs retire) and **the v5/boot beta promotion** are design decisions, not housekeeping. They are left to a future architect session; this ADR does not guess them.

## Consequences

- **Easier:** a superseded protocol has one documented destination + a uniform frozen-record marker; the v4→v5 flip has a ready target; a reader of `protocols/` top level can trust every file there is live.
- **Cost:** the convention is enforced by discipline + review, not a hook (Layer-2 stays validators-only; no orchestration added). A future check could assert "every `protocols/archive/*.md` opens with an ARCHIVED blockquote" if drift appears.

## Alternatives considered

- **Key-value frontmatter tombstone** (`status: archived` / `superseded-by:` / `archived:`). Rejected: would diverge from the existing v3.4 blockquote and leave two formats (or force a retrofit) for no parsing need today — nothing machine-reads protocol tombstones.
- **Delete superseded protocols** (rely on git history). Rejected: violates the ADR-39 / CLAUDE.md §5 preserve-don't-delete rule for institutional records; git history is the *technical* record, the tombstoned file is the *navigable* one.
