## Context

`ecosystem/harness.yaml` declares a 12-stage spine that `scripts/dodo.py` runs through pydoit. Stages 1-12 cover a unit of work from its row to its landing gates. Everything after — the agent call, the second-provider review, the gate run, the merge — is a set of separate organs (`dispatch.py` plus the caller-side shim, `codex_review.py`, `audit.py` / `ship-gate`, the `/lane-integrate` command) that **a human strings together**. The operator is the event loop between them.

Four facts, each measured in the linked records, bear on the decision:

1. **The spine cannot yet be relied on to resume.** `dodo.py:75` sets `uptodate: [False]`; probe **B3** ran it and re-ran it unchanged: **FAIL** — both runs re-executed stages 1-6 in full and both halted at stage 7 (exit 2). No run was deliberately interrupted, so B3 shows that completed stages are re-executed, not that a killed run loses a step. Stage 7 exits 2 (`[#922]`) and stage 11 is `command: null`, so the spine does not currently run end to end.
2. **Stages 13-16 have organs but no runner.** The MAPPING record (§4) names, per stage, the existing organs and the concrete missing piece: 13 (no adapter, no stage row), 14 (a review packet and a Codex wrapper exist, tracked-review evidence does not), 15 (`audit.py`, ship-gate, ruff and impacted-test hooks exist; the gate set is not one declared list), 16 (`/lane-integrate` is the protocol; a merge-side GO reader and a single entry point are missing).
3. **The mechanisms exist and work in isolation.** **B1** (Claude Agent SDK) **PASS**: one process, two tools, one deny hook, one budget, cost reported per call. **B2** (`codex exec`) **PARTIAL**: it runs read-only with stdin closed, but reports usage tokens only — no cost, no served-model id. **B4** (nested `--bg` spawn) **PASS**: the nested job got its own Agent View row and job record, so AM-5's premise ("a nested session gets no row") is false a third time.
4. **Two texts bar a session-side stage 13**: ADR-28's invariant read as written, and PLAYBOOK Ch8 **AM-5** ("never spawned from the primary session or any other session"). B4 refutes AM-5's *premise*; DECLARE R7 and its amendment A4 authorize the B4 re-witness and the launch of the evaluating lane and **re-rule nothing else**.

## Decision

- **D1 — The loop is 16 stages in one declared spine.** Stages 1-12 as today. **13 RUN** (an agent call behind an adapter: dispatch, the Claude Agent SDK, `codex exec` — a model is an input-to-output function behind it), **14 REVIEW** (a second provider), **15 GATES** (audit / ship-gate / ruff / impacted tests — one declared list), **16 MERGE** (the `/lane-integrate` protocol; the operator's GO is the stage's condition). The order is the one the live integrator uses **per lane**: a **local** `--no-ff` merge, then the review packet, then suite ∥ review, then teardown of that lane's worktree and branch (`lane-integrate.md` :117-139); the single `git push` and the Actions verdict of the pushed merge follow the whole walk (:386, :192-195). **Where the push sits relative to the per-lane block is unresolved** — the file says so and escalates it (:204-217, `[#750]`) — and this ADR does not settle it; the stage table records "MERGE" as two acts (a local merge, a push), with 14 and 15 after the first, and leaves the push position to `[#750]`.
- **D2 — ADR-28's invariant is narrowed, not repealed.** "Layer 2 never executes" keeps its ground: **no script in the hub drives state in a child repo**, and the caller-side shim (`templates/dispatch-shim.ps1`) remains the only sanctioned spawner. What changes is that hub-local scripts that run the hub's own work loop (`dodo.py` extended to 13-16, adapters that call a model) are in scope, exactly as hub-local validators, generators and gates already are (`CLAUDE.md` §5 rule 4). Any adapter that writes into a child repo stays barred. `dodo.py`'s docstring (:8-11) and `harness.yaml` (:5) each carry scope text ("prepares a contract; moves no row through a phase") that must change with the build; the MAPPING `dodo.py` row names both.
- **D3 — AM-5 keeps binding until it is re-ruled.** Probe B4 is the evidence for a re-ruling, not the re-ruling. A session-side stage 13 (a session that spawns lanes) is barred by AM-5 as written; the first stage-13 adapter must either be caller-side, or the architect re-rules AM-5 on the B4 record. This ADR does not do it.
- **D4 — The GO is one per batch.** Stage 16's condition is a single batch-scoped operator GO. This is **STANDING_RULINGS AH-B2** (`/lane-integrate` §0 is canon), restated only to fix the stage's cardinality; PLAYBOOK Ch8 D2 (:2387, "operator GO each") is the defective text and is fixed by the Ch8 rewrite. The GO artifact for merge does not yet exist on the integrator side; the boot-side reader (`lane_boot.check_go_artifact`, `[#685]`) reads roster state — a manifest row not marked HELD — which is not proof of the operator's own consent, and the stage-16 reader must not claim more.
- **D5 — Evaluation before build (DECLARE R2).** No stage 13-16, nor the stage-7 / stage-11 fixes, is built until the MAPPING and LIVE-PROBES records are merged and read by the seat; the build contract is frozen from them.
- **D6 — One graph edge is added.** The graph (FPG-1) has no edge for "a `harness.yaml` stage's argv runs script X", so `dodo.py` and `stage_library_first.py` read as false orphans in `graph_queries.py orphan-census`. The build adds that edge class under ADR-118 (organs are views of one graph), so the loop's own runner is not a disposition-register entry.
- **D7 — Build order.** (1) Unblock the spine: `[#922]` (stage 7) and stage 11's missing command, then a resume policy replacing `uptodate: [False]` — B3 is the failing witness. (2) Stage 15 as one declared gate list. (3) A merge-side GO reader for stage 16 and its single entry point. (4) Tracked review evidence for stage 14. (5) The stage-13 adapter last, because it is the only stage whose premise (AM-5, ADR-28) needs a ruling. Each step is a row filed by the seat first (R3); each is RED-first (ADR-108 §B).
- **D8 — The dispatch shim copy stays deferred** (DECLARE R5): the old launch surface is live and dry-run verified; the swap waits for stage 13's decision about dispatch's role. **Contract effort levels are `low | medium | high | xhigh` only** (DECLARE R6): PLAYBOOK Ch8 lists `max`, `Invoke-Dispatch.ps1` refuses it, and the Ch8 fix folds into `[#920]`. **Recorded conflict, not resolved here:** PLAYBOOK Ch8 (:3390-3398) records a 2026-08-22 architect ruling that the CLI-validated five-value enum is canonical and `max` is valid for a contract, while `max` stays out of dispatch *routing* (:3527); R6 is a later, window-scoped instruction that contracts avoid `max` until `[#920]` lands, and is followed as such.

## Consequences

- **Easier:** the operator's touches per unit of work fall from one-per-hand-off to a GO at stage 16 plus decisions; an interrupted run can resume at the stage it stopped on; each stage's evidence is a spine row rather than a chat message; the loop's own runner stops reading as an orphan.
- **Harder:** `dodo.py` becomes load-bearing for the whole loop, so a bug in it stalls every stage; `uptodate` semantics must be designed (a stage's inputs, not `False`), which pydoit leaves to the author; a stage-13 adapter puts a model call inside a gate-adjacent chain, which ADR-118 §4 forbids on a hot path — the adapter must be the *work* step, never a gate's judge.
- **Baselines this ADR touches (integrator's pass, not this lane's):** adding an ADR reds two pinned baselines in `tests/test_validate_adr_status.py`, and `claude-rosters-freshness` blocks until `.claude/generated/recent-adrs.md` is regenerated. The ADR number may collide with a peer lane's; `ADR-120` was free on `origin/main` when drafted.
- **Honest limits of the evidence:** B1 tested one process; teardown, cancellation, crash recovery and run identity were not probed. B3 measured a single-run resume, not concurrent runs on one doit database. B4 shows a nested job has a row; it does not prove a quiet spawn is safe. B2 gives no cost. The adversary's served model was requested as `gpt-5.6-sol` and is not attestable (`QUESTION-lane-loop-eval.md` Q1).

## Flip-condition

Reverse to "the spine stays 12 stages; 13-16 remain separate organs" if, after stages 1-12 are unblocked (D7 step 1), a resumed `dodo.py` run still loses a step on interruption in a re-run of probe B3 — pydoit then cannot carry the loop and the runner must be chosen again. Also reverse D2 if the ADR-28 owner rules that a hub-local runner of the work loop is the orchestration ADR-28 was written to bar.

**30-day success metric** (measured from the first merged D7 step): **operator touches per unit of work** — counted from the session record as messages that carry an operator command or relay rather than a decision or a GO — trends to the two ADR-110 already names (one GO, one end-of-batch packet); and **interrupted runs resumed without a lost step** — every spine run that stops mid-way is re-run and skips its completed stages, counted from doit's own state, target all of them. A metric that no run can produce (no interrupted run in the window) reads "not measured", not "met".

## Alternatives considered

- **Keep 13-16 as separate organs and improve each.** Rejected: it leaves the operator as the event loop, which is the cost the DECLARE names; the organs work (B1, B4) and are not what fails.
- **Replace pydoit with a bespoke runner.** Not chosen: the library-first check names pydoit as the established dependency already carrying stages 1-12; B3's failure is one line (`uptodate: [False]`), not a runner defect. Reopens only under the flip-condition.
- **Repeal ADR-28's invariant.** Rejected: the invariant protects child repos from a hub that drives them, and that ground is real; only its reach over the hub's own work loop is wrong.
- **Re-rule AM-5 in this ADR on the B4 evidence.** Not chosen: DECLARE R7 and A4 authorize the re-witness and the launch, and say they re-rule nothing; re-ruling is the architect's act on the record.
- **Build stage 13 first (the most visible stage).** Rejected by the evidence: it is the only stage that needs a ruling, and the spine under it does not resume (B3) or run end to end (stages 7, 11).
