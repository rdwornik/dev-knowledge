## Findings
## Critical

### CRITICAL — scripts/desired_state_loader.py:281 — Required component model is silently empty

**What:** The loader never populates `components` or `assignments`; the live manifest contains 17 component declarations, but the resulting model returns empty tuples.

**Why:** This violates ADR-109 §7 D3 and makes the core “which repos have component X?” query return false-empty results.

**Fix direction:** Derive component specifications and repo assignments from the manifest and parity declarations, with assertions for known live components and non-empty populations.

## High

### HIGH — scripts/desired_state_loader.py:131 — Parity selectors are misclassified

**What:** Every non-role tier key is assumed to be a repository without checking the fleet set, while a repository whose ID equals `hub`, `consumer`, or `pre-deploy` would be classified as a role.

**Why:** Typos and off-fleet selectors silently load, and the grammar’s repo-overrides-role rule is not preserved.

**Fix direction:** Classify against known fleet IDs first, then role tokens, and reject selectors matching neither set.

### HIGH — scripts/desired_state_loader.py:116 — Live registry paths retain Markdown delimiters

**What:** The parser returns the complete Path cell, including backticks; live paths therefore look like `` `C:\...\ai-council` ``. The fixture omits the live backticks and misses this.

**Why:** The model does not contain a usable filesystem path, breaking downstream path resolution and C6 attribution.

**Fix direction:** Parse the inline-code wrapper into a usable path while retaining the original cell separately as raw data; update the fixture to reproduce the live table grammar.

### HIGH — scripts/desired_state_loader.py:214 — Non-hub parity roles incorrectly become lifecycle assertions

**What:** `consumer` and `pre-deploy` roles are mapped to `unonboarded` assertions. The live `ai-council` model consequently carries both `unonboarded` and deployed `full`.

**Why:** ADR-109 D2 explicitly makes role non-lifecycle-bearing except for `hub → source`; these synthetic assertions create false contradictions.

**Fix direction:** Use the schema’s role-to-lifecycle helper and append an assertion only when it returns a stage; strengthen the test to require no parity lifecycle assertion for non-hub repos.

### HIGH — scripts/desired_state_loader.py:155 — Fields labeled raw are reconstructed from normalized YAML

**What:** `tier_raw` is produced using `yaml.safe_dump`, which reorders and reformats the source map; lifecycle `raw_value` fields also originate from already-parsed YAML scalars.

**Why:** ADR-109 finding 4 requires raw values beside normalized projections. Lexical distinctions and ordering are silently lost.

**Fix direction:** Capture raw source spans or source envelopes before `safe_load`, and assert exact raw equality rather than merely checking that `tier_raw` is non-empty.

### HIGH — scripts/desired_state_loader.py:172 — Unmapped declarations are incorrectly modeled as effective waivers

**What:** Every `.methodology.yaml` entry becomes a `parity-waiver` with `effect="waive"` without joining it to a surface’s `waiver_component`. Seven live declarations are currently unmatched.

**Why:** The live parity contract treats unmapped declarations as inert; the loader instead overstates their suppression effect and leaves the concern join unvalidated.

**Fix direction:** Join declarations by exact concern ID, enforce one declaration per mapped concern, and represent or retain unmatched declarations as inert rather than active waivers.

### HIGH — tests/test_desired_state_loader.py:333 — Live read-only test can false-pass

**What:** The test compares unchecked `git status` stdout before and after. Both calls can return empty output on failure, and Git cannot detect a same-byte rewrite or other write that leaves content unchanged.

**Why:** The test does not actually prove the Layer-2 “no write path” invariant it claims to cover.

**Fix direction:** Require successful Git commands, snapshot all seven inputs, and install a write-denial spy around filesystem mutation APIs during the loader call.
