## 4. How the merge queue ran at all — the exemption that did not apply

**Reported here because it changes what a future batch must do, and because no lane could see it.**

`batch_manifest.exempt()` grants the ADR-110 declared-integration-arc exemption only when **both**
hold: a committed manifest declares an open batch, **and** the merge is of a branch matching
`LANE_BRANCH_RE = ^worktree-lane-[a-z0-9]+(?:-[a-z0-9]+)*$`.

The manifest armed condition 2 correctly — it was committed at dispatch, it is enumerable by
`MANIFEST_GLOB` (which the manifest itself verified, having caught that exact defect), and
`open_batches()` returned it. **Condition 1 was unreachable.** The lanes were cloud sessions, and
the runtime names their branches `claude/<slug>`. Verified live against all five names before
merge #1:

```
claude/new-session-x7lkr5                          -> False
claude/manifest-filename-parser-validation-v4n1ew  -> False
claude/new-session-mdmwu1                          -> False
claude/new-session-ljw038                          -> False
claude/new-session-foidbt                          -> False
worktree-lane-a-123-x            (control)         -> True
```

So `check_journal_spine_anchor` — a **FAIL**, gating `audit-health` at pre-commit — would treat
every lane merge as unanchored. Four of the five merges conflicted on the generated index, and a
conflicted merge is the case where the full pre-commit stack fires. **The queue would have wedged
at merge #1 exactly as batch 3 did, with a manifest that is correct, committed, enumerable — and
inert.** A precondition can be satisfied and still not apply.

**Discharged with zero bypasses, by using the ADR-85 predicate as specified rather than around
it.** §A7 anchors a spine entry by a SHA it **introduced**, and a `--no-ff` merge introduces the
merged branch's commits — which already existed. So the JOURNAL entry naming all five lane tips
was written and merged **before** the queue ran (`c0a6a160`), and every lane merge was anchored on
arrival. Evidence that it worked: the four conflicted merges each ran the full pre-commit stack
and `Audit self-conformance gate … Passed` on every one.

**Cost: the batch's JOURNAL is two entries, not one** — (b) anchors the queue, (c) closes it. That
is a real divergence from the contract's "JOURNAL entry as the LAST commit before pushing" and is
recorded in §9 rather than smoothed over.

**Ownership.** `[#510]` (OPEN, P2/M) is adjacent but does not cover this: it is scoped to the
exemption being *too loose* — self-grantable by `git branch -m` — whereas this is the same
predicate being *unreachable*. Its proposed fix (resolve the exemption against a lane roster the
manifest declares) **would** cover this case, and tonight's manifest deliberately declined to
enumerate branch names because cloud lanes are named at launch. That is the tension the architect
now has to resolve, and it is indexed as I-1/I-2.

is reported rather than backfilled.

   the exemption did not cover it. Entry (c) is still the last commit before the push and names

   was ever created. These are **remote refs produced by another runtime**; deleting them is
