# Backlog.md adoption trial — Tier-S sandbox trial, measured

> **Lane N** (`worktree-lane-n-171-backlogmd-trial`), 2026-08-19. Frozen contract of record:
> `docs/audits/2026-08-19-technical-backlogmd-trial-lane-contract.md` (committed `c3f2c025`).
> **This artifact proposes a verdict. It does not rule one.** ADR-112's two-tier adoption bar
> puts a candidate of this blast radius in **Tier L — evaluate**; the architect and the operator
> ratify. Nothing in the real repo changed except this file and the contract.

---

## 0. Verdict (proposed, not ruled)

**`ADOPT-VIEW-LAYER`** — Backlog.md becomes a **read-only operator surface** generated by a
one-way export from `tasks/`, which stays the single source of truth. It is **not** adopted as
the store, and no gate is re-pointed at it.

The three-value enum resolves this way because the trial measured a clean split:

- Backlog.md's **presentation** is better than anything we have and cheap to get. Board, web UI,
  search, filters, `--ready` scheduling, and an `overview` health page all worked over our full
  288-row tree on the first try, with our ids and our status vocabulary preserved (§5).
- Backlog.md's **store semantics conflict with our doctrine at the record level**, not at the
  cosmetic level. Its own integrity checker reports a clean tree while two files carry the same
  id (§4.3). That is disqualifying for the store, and irrelevant for a view.

`ADOPT-WHOLESALE` is refused on the id-ledger evidence in §4.3 plus the 52%-of-clauses typing
gap in §3.2 and the 18-script / 3-audit-check / 3-git-hook coupling in §6.2.
`REJECT` is refused because the view layer is genuinely useful, prototyped in 130 lines, and
carries no doctrinal cost when the export is one-way (§5).

**The single hazard that decides whether the view layer is safe: two writers, one id space
(§5.3). It is real, it is proven, and it is cheap to close.**

### 1.1 Windows friction, verbatim

Three items. Two are real product defects; one was my own mapping bug and is recorded as such.

**(a) `backlog board export` cannot take an absolute path.** It joins the argument onto the
project root unconditionally:

```
$ backlog board export "C:\Users\...\Temp\backlogmd-trial\board-export.md"
ENOENT: no such file or directory, mkdir
  'C:\Users\...\backlogmd-trial\sandbox\C:\Users\...\backlogmd-trial\board-export.md'
```

Exit 1, so it is at least detectable. The workaround is a project-relative path. Any wrapper we
write must not pass an absolute path.

**(b) `ENAMETOOLONG` — the task filename is derived from the untruncated title.** Bracketed on
the operator host, with a 73-character project root:

| title length | result |
|---|---|
| 165 chars | OK |
| 170 chars | OK |
| **175 chars** | **FAIL — `ENAMETOOLONG`, exit 1** |

Our longest live task title is **161 characters** (`terminal-setup registered + the blind spot
mechanized — …`). That is **nine characters of headroom**, and the headroom shrinks
one-for-one with the depth of the project root — our lane worktrees sit at
`…\.claude\worktrees\lane-n-171-backlogmd-trial\`, which is deeper than the sandbox was. A
title-length cap is not optional if the CLI is ever the write path. The prototype exporter
sidesteps it by truncating the slug to 80 characters (§5.1); the filename is decorative there
because `id:` is authoritative.

**(c) My own bug, recorded so it is not mistaken for a product defect.** My first import passed
the whole first clause — title *and* rationale, ~1600 chars — as the title, and all 15 rows
failed `ENAMETOOLONG`. The fix was to read the frontmatter `title:` instead of splitting the
body. The product limitation in (b) is real and was isolated separately.

### 1.2 What `init` did that we would have to undo

`backlog init --defaults` **created `AGENTS.md`** — the file ADR-53 retired, and which
`CLAUDE.md` §10 names as an anti-pattern ("Narrating or managing AGENTS.md — AGENTS.md is
retired; CLAUDE.md is the single instruction file"). It is opt-out
(`--agent-instructions none`), so this is a flag, not a blocker — but the default is a direct
collision with a ratified decision and must be pinned in any install we sanction.

Its contents are also a standing token tax and a doctrine conflict:

```
**For every user request in this project, run `backlog instructions overview`
  before answering or taking action.**
...
Do not edit Backlog task, draft, document, decision, or milestone markdown files
  directly. Use the `backlog` CLI so metadata, relationships, and history stay consistent.
```

A per-request CLI call before *any* answer is not something we would adopt. And the second line
is flatly incompatible with a generated view: our exporter writes those files directly, by
design. Under `ADOPT-VIEW-LAYER` the instruction file is not installed at all.

## 3. Field mapping

### 3.1 Per-field, measured

| our field | Backlog.md home | fidelity |
|---|---|---|
| `id: "[#533]"` | `id: TASK-533` | **lossless as a bijection, but only by writing the file directly.** The CLI always allocates; `--json` and every command accept a hand-written id (verified: `backlog task TASK-533` resolved) |
| `title` | `title` | clean, ≤170 chars (§1.1b) |
| `status` (open/deferred/closed/retired/superseded) | `status`, enum in `backlog/config.yml` | **clean** — all five accepted; counts round-tripped exactly (188/24/72/3/1). **But the enum has no CLI setter** (`config set` refuses the key); hand-edit `config.yml` |
| `priority` (P0–P3) | `priority` | accepted, but **silently lowercased to `p2`** on write and in `--json`. Any consumer must case-fold |
| `size` (S/M/L) | none | carried as label `size:M`; filterable, not typed |
| `theme` `[E2]` | `milestone` (`m-0`) **or** label | milestone works and drives `board --milestones`; label is simpler for a generated view |
| `story` `[S3]` | none | carried as label `story:S3` |
| `serialize-group` | **none** | carried as label; `backlog task list -l serialize-group:audit-py` filters correctly, so the batch pre-dispatch matrix could still read it — but as an untyped string, with no scheduling meaning to the tool |
| `depends-on` | `dependencies` | **better than ours.** Referential integrity is enforced (`TASK-9999` → error, **exit 1**), and `--ready` / `overview`'s "Blocked Tasks" consume it live. Our own `[#424]` records that `_DEPID_RE` makes our clause inert |
| `· Done when:` | `acceptanceCriteria` | **good fit, and an upgrade** — each clause becomes an individually checkable box (`--check-ac 3`). #533's single Done-when decomposed into six criteria |
| `· refs …` | `references` | clean array; also `--doc` and `--modified-file` for finer typing |
| `· kill-candidates:` | **none** | 206 occurrences tree-wide. No field carries "an id **plus the reason it is not a kill candidate**". `--ref` is a flat string list; the reason has nowhere typed to go |
| dated amendment clauses (`PARTIAL 2026-08-16`, `LEG 2`, `RELOCATED`, `OBSOLETED`, `UN-DEFERRED`, `DEFER — peg:`) | `--comment` / `--append-notes` | **a better home than we have.** `--comment` is append-only, timestamped, and carries `--comment-author`. Our equivalent is inline prose in one ever-growing line |
| `generates: BACKLOG.md` | none | provenance marker; irrelevant once `tasks/` is the source |

**One trap worth naming: `--notes` replaces, silently.** Measured — first `--notes` written,
second `--notes` issued, first gone, exit 0, no warning. It *is* documented ("replaces
existing") and `--append-notes` exists, so this is a correctly-labelled sharp edge rather than a
defect. But an agent that reaches for the obvious flag destroys the record, and our amendment
trail is append-only by doctrine.

### 3.2 The typing gap, counted over the whole tree

Census over all 288 task files, splitting each body on its ` · ` clause separator:

```
rows: 288      clauses after the head: 1196
clauses with a native typed field:  576  (48%)
clauses with NO native typed field: 620  (52%)

  288  HOMED     references  (--ref)
  284  HOMED     acceptanceCriteria  (--ac)
    4  HOMED     dependencies  (--depends-on)
  206  NO FIELD  kill-candidates:
  185  NO FIELD  serialize-group:
  ~200 NO FIELD  dated amendment / ruling / leg clauses (DEFER 26, UN-DEFERRED 7,
                 CLOSED 5, RELOCATED, RE-PHRASED, INTEGRATION, ARCHITECT-REVIEW-PENDING,
                 P3/P4/P5/P6 sub-legs, and 149 unprefixed prose clauses)
    2  NO FIELD  verify-first:
```

**Read this carefully — "no native typed field" is not "no home".** Every one of those 620
clauses *can* be carried (as a label, a comment, or description prose); the export prototype
carries all of them and loses nothing. What is lost is **machine-readability by a typed field**,
and that is what our gates depend on: `check_backlog_filing.py` parses `kill-candidates:` at
commit time, and the batch pre-dispatch matrix parses `serialize-group:`. Under a Backlog.md
store those become untyped strings and both organs need re-authoring against a new surface. Under
a view layer nothing changes, because the gates keep reading `tasks/`.

### 3.3 What Backlog.md has that we lack

Not a courtesy list — these are the things that would actually change how the backlog is worked.

- **Definition of Done per task**, separate from acceptance criteria, with configurable
  project-wide defaults. We have one `· Done when:` clause and three *different* DoD scopes
  (session-close / arc-shipped / organ-done) living in three different documents.
- **Live dependencies** with referential integrity and a `--ready` filter that shows only
  unblocked work. `[#488]` is our row saying the backlog "has no ranking function"; this is one.
- **Arbitrary-depth subtasks** — verified to `TASK-244.1.1`. Combined with milestones this
  models theme → epic → story → task natively. `[#244]`'s four prose sub-legs (P3/P4/P5/P6)
  became four real subtasks in one command each.
- **Append-only authored comments** on a task.
- **A drafts → tasks → archive lifecycle** with CLI verbs (`draft promote`, `task archive`,
  `task demote`, `cleanup`).
- **Scored full-text search** across tasks, docs and decisions, plus exact label filtering.
- **A local web UI with a real REST API** (`/api/tasks`, `/api/config`, `/api/decisions`,
  `/api/statuses`).

## 4. Driving it as an agent (protocol step 3)

### 4.1 `--json` is versioned and adequate

`backlog task list --json` returns `{schemaVersion, kind, tasks[]}`; a single task returns
`kind: "task-view"` with the full `description`, AC, references and `path`. A **versioned
envelope** is the right shape for an agent contract.

Cost: **9542 bytes for 19 tasks ≈ 500 B/task metadata-only** (no description, AC or references in
the list form). Extrapolated to our 288 rows that is ~144 KB for the index, versus **279 KB for
`BACKLOG.md` today** — so the list view is roughly half the tokens of reading the generated file,
with a per-task detail call available on demand. That is a genuine improvement over "read
BACKLOG.md and grep".

### 4.2 The board, as the operator would see it

`backlog board view` in a non-TTY **degrades gracefully to the markdown export** — no hang, no
garbage, exit 0. Over the full 288-row export:

```
$ backlog task list --priority P1 --plain
open:
  [P1] TASK-359 - PHANTOM ENFORCEMENT — `protocols/HANDOFF_PROCESS.md` §14a FILE-BOUNDARY …
  [P1] TASK-514 - Two rival `LANE_BRANCH_RE` constants ship in one repo
  [P1] TASK-519 - The close path is two edits, and nothing makes a half-done close visible
  [P1] TASK-528 - Lane-latency — the full suite × per-lane + per-merge runs is the real batch cost
  [P1] TASK-529 - Telemetry v1 EMIT — stage-1 events from the gate mesh
  [P1] TASK-555 - Closing campaign batch 1 + kill-candidates instrument
deferred:
  [P1] TASK-218 - Safe-removal gate M2+M3 boundary
  [P1] TASK-300 - Hermetization residual d.ii
```

```
$ backlog overview                       # 3.2s over 288 rows
Status Overview:
  open: 188 (65%)   deferred: 24 (8%)   closed: 72 (25%)   retired: 3 (1%)   superseded: 1 (0%)
Blocked Tasks (waiting on dependencies):
  TASK-112, TASK-169, TASK-385, TASK-389
```

The status counts match `tasks/` exactly. **Two metrics are wrong and it is worth knowing why:**

- `Completion: 0%` — Backlog.md computes completion against a status it recognises as terminal,
  and our renamed enum contains no such status. Terminal-status semantics are **not
  configurable**. Completion and parts of `--ready` are only correct if we adopt *their* status
  vocabulary, which we would not.
- `Average Task Age: 0 days`, `No stale tasks` — the exporter stamps `created_date` at export
  time. Fixable (derive from `git log --diff-filter=A`), and it must be fixed before anyone reads
  the health page, because "no stale tasks" over a tree with rows from June is an actively
  misleading answer.

`board export` produced a full pipe-table Kanban with subtask nesting rendered (`└─ TASK-5.1`).

### 4.3 The disqualifying finding for the store

This is the single measurement that settles `ADOPT-WHOLESALE`.

```
$ backlog task archive TASK-16
Archived task TASK-16

$ backlog task create "id-ledger probe after archive" --plain
Task TASK-16 - id-ledger probe after archive          # ← the id was re-issued

$ grep -l '^id: TASK-16' backlog/tasks/*.md backlog/archive/tasks/*.md
backlog/tasks/task-16 - id-ledger-probe-after-archive.md
backlog/archive/tasks/task-16 - intake-40-library-first-for-the-management-loop.md

$ backlog doctor
No duplicate task, document, or decision IDs found.
```

**Archiving frees the id; the next `create` re-issues it; two files now carry `id: TASK-16`; and
`doctor` — the tool's own duplicate-id diagnostic — reports clean, because the archive directory
is outside its scan.**

Our ids are the primary key of the whole methodology: they appear in commit messages, in the
`backlog-id-on-close` commit-msg regex, in JOURNAL entries, in ADRs, in `STANDING_RULINGS`
register entries, and in handoff bundles. `tasks/README.md` already documents our own ledger's
honest limit — deleting a retired file silently frees its id — and `[#440]` tracks closing it. The
difference in posture is the whole point:

| | our `tasks/` tree | Backlog.md |
|---|---|---|
| retire path | **`--prune` is REFUSED**; retire-never-delete, terminal `status:`, file stays as the allocation record | `task archive` moves the file out of the id space, by design, as a first-class verb |
| re-issue detection | `task_tree_coherence` REDs on a re-issued id while the record is present | none — `doctor` says clean |
| documented limit | yes, in `tasks/README.md`, with a tracking row | not documented |

We were about to migrate a ledger whose *known* weakness is undetected deletion onto a store
where deletion is a supported workflow and the built-in checker cannot see it. That is not a fit.

## 5. Coexistence probe (protocol step 5) — the prototype

### 5.1 One-way export, `tasks/` stays source of truth

The CLI cannot preserve our ids and costs a node process per row. Writing Backlog.md's on-disk
format **directly** solves both. ~130 lines of Python, no dependencies:

```
$ py export_view.py <repo> <backlog-project>
exported 288 rows in 1.11s (3.9 ms/row)
rows carrying clauses with no native field: 266
total such clauses: 624
```

Then, unmodified upstream tooling reads it:

```
$ backlog task TASK-533 --plain
Task TASK-533 - Decompose the `audit.py` check monolith into `scripts/audit_checks/` — …
Status: ○ open        Priority: P2
Labels: size:M, theme:E2, story:S3, serialize-group:audit-py
References: scripts/audit.py, tests/test_audit.py, D-1v2, docs/audits/2026-08-16-…, [#531], [#505]
```

**`[#533]` ↔ `TASK-533` is a lossless bijection.** Every citation in every ADR, commit and
JOURNAL entry still resolves. Mapping applied:

| our field | export target |
|---|---|
| `[#N]` | `id: TASK-N` |
| `title` | `title` |
| `status` | `status` (five-value enum in `config.yml`) |
| `priority` | `priority` (lowercased by the tool) |
| `size` / `theme` / `story` / `serialize-group` | `labels: [size:M, theme:E2, story:S3, serialize-group:audit-py]` |
| `depends-on` | `dependencies: [TASK-23]` |
| `· Done when:` | `## Acceptance Criteria`, one box per clause |
| `· refs` | `references:` |
| the whole authoritative body line | `## Description`, verbatim — the lossless carrier |
| every clause with no typed field | `## Implementation Notes`, one bullet each, verbatim |

Nothing is dropped. The description holds the exact `BACKLOG.md` line, so the view is
reconstructible and diffable against the source.

### 5.2 Where it would live

`backlog/` **must not** land in the repo. It is 288 generated files that duplicate `tasks/`
byte-for-byte in the description field, and ADR-101 Rule C would refuse the new top-level home
anyway (correctly). Generate it into an ignored scratch path, or into a sibling directory
outside the repo, on demand: `python scripts/export_backlog_view.py && backlog browser`.
Never committed, never a second copy of the truth in git.

### 5.3 Sync hazards — all four proven, not asserted

**(1) Two writers, one id space.** This is the one that matters.

```
$ ls tasks/ | grep -oE '^[0-9]+' | sort -n | tail -1
558                                  # our next-free id is 559

$ backlog task create "sync-hazard probe: a create inside the VIEW" --plain
Task TASK-559 - sync-hazard probe: a create inside the VIEW
```

Backlog.md's allocator is `max + 1`. Ours is `max(id in tasks/) + 1`. **They are the same
function over the same range and neither knows the other exists.** A create in the view claims
exactly the id our generator will hand to the next real row.

**(2) The next export destroys view-side writes, silently.** Two edits made in the view, then
one re-export:

```
$ backlog task edit TASK-171 --status closed --comment "operator note added in the view"
$ py export_view.py …
exported 288 rows in 0.86s
$ backlog task TASK-559 --plain
Task TASK-559 not found.                          # the created row: gone
$ backlog task TASK-171 --plain
Status: ○ open                                    # status reverted, comment gone
```

No warning, no diff, exit 0.

**(3) The web UI is read-write, unauthenticated, with no read-only mode.** `backlog browser` has
exactly three flags — `--port`, `--no-open`, `--non-interactive`. A single unauthenticated PUT
mutated the file on disk:

```
$ Invoke-WebRequest http://127.0.0.1:6499/api/tasks/TASK-4 -Method PUT \
    -Body '{"title":"Hooks hygiene EDITED-IN-UI","status":"deferred"}'
PUT 200
$ head -5 "backlog/tasks/task-4 - Hooks-hygiene.md"
title: Hooks hygiene EDITED-IN-UI
status: deferred
```

Note the filename did **not** follow the title — after any API edit, filename and title diverge.
So the operator's natural gesture (drag a card, fix a title) writes to a generated tree that the
next export deletes. **Combined with (1), an operator who files a real row in the pretty UI loses
it *and* burns the id.**

**(4) Cross-branch state resolution.** `checkActiveBranches: true` by default, with
`remoteOperations: true`. Observed on every read: *"Indexing 7 recent remote branches… Applying
latest task states from branch scans…"* (2.8s of the 3.2s `overview`). Backlog.md deliberately
reads task files from other branches and applies their state over the local ones. Under our lane
model an in-flight lane's row state would surface as authoritative on `main`. Untested here —
the export was never committed, so no branch carried a `backlog/` tree — but the behaviour is
documented and was observed to run. **Set `check_active_branches: false` and
`remote_operations: false` in any view we sanction.**

### 5.4 Closing the hazards

All four are closable, and cheaply:

1. **Make the view non-writable.** Generate into a scratch dir and `chmod`/ACL it read-only after
   export, or simply re-export before every read so a stale write can never be mistaken for
   truth. This closes (1), (2) and (3) at once — the id can still be burned in a transient tree,
   but nothing survives to collide.
2. **Set `check_active_branches: false`, `remote_operations: false`.** Closes (4) and takes 2.8s
   off every read.
3. **Never install `AGENTS.md`** (`--agent-instructions none`).
4. **Derive `created_date` from `git log --diff-filter=A`** before anyone reads the health page.
5. **Do not use the CLI as a write path** — it cannot set ids and it has a 170-char title cliff.

None of these needs upstream cooperation.

## 6. Decisions lifecycle (protocol step 4) — where it cannot express our rules

### 6.1 What `backlog decision` actually is

```
$ backlog decision create "Two-tier adoption bar — Tier L evaluates, Tier S tries and keeps or deletes" -s accepted
Created decision decision-1
---
id: decision-1
title: 'Two-tier adoption bar — Tier L evaluates, Tier S tries and keeps or deletes'
date: '2026-08-19 11:04'
status: accepted
---
## Context

## Decision

## Consequences
```

Four frontmatter fields and a three-heading skeleton. That is the entire feature. Mapping our
intake → ADR → archive gate onto it:

| our mechanism | Backlog.md | verdict |
|---|---|---|
| intake file with a stable ADR-98 intake-id, cited from BACKLOG rows | `draft` → `promote` | **breaks the citation.** `DRAFT-1` promoted to `TASK-16` — the id changes on promotion. Our intake ids are cited *before* ratification, which is the whole point |
| ADR number, permanent | `decision-N`, sequential | works, until an archive frees it (§4.3 class) |
| ADR **status line editable in place on ratification**, decision content immutable (ADR-94) | `-s <free-form>` | status is free-form, unvalidated; **nothing enforces content immutability** |
| supersession (`superseded-by`, ADR relation fields, `[#23]` validates them) | **absent** | no relation fields at all |
| `reconciled_with` / spec-version coupling | **absent** | — |
| Council provenance, ratification by architect + operator | **absent** | — |
| ADR archive | **absent** | `backlog/archive/` has `tasks/`, `drafts/`, `milestones/` — **no `decisions/`**. Decisions cannot be archived at all |
| PreToolUse transcript-immutability guard (ADR-77) | **absent** | nothing prevents an in-place rewrite |
| `--context` / `--decision` / `--consequences` on the CLI | **absent** | the three sections can only be filled by editing the file — which its own `AGENTS.md` forbids (§1.2) |

**Conclusion: the decisions feature is a note-taking convention, not a gate.** It expresses
roughly the surface of an ADR title page and none of the lifecycle. Our intake → ADR → archive
gate is ratification machinery — provenance, immutability, supersession, in-place status
amendment under a named exception, and a hook that refuses edits. There is nothing here to adopt
and nothing here to migrate onto. **This is the operator pain Backlog.md does not touch.**

### 6.2 What wholesale adoption would cost, counted

Not an argument, a bill of materials — every organ that reads the backlog surfaces today:

- **18 scripts** under `scripts/` reference `BACKLOG.md` or `tasks/`
- **7 named organs**: `gen_task_tree.py`, `validate_backlog.py`, `validate_git_backlog.py`,
  `check_backlog_commit_msg.py`, `check_backlog_filing.py`, `probe_child_backlogs.py`, and the
  `tasks/manifest.json` schema-2 reconstructor
- **3 audit checks**: `check_task_tree_coherence`, `check_git_backlog_drift`,
  `check_preflight_backlog_ids`

Every one of these reads a **typed** clause that Backlog.md does not type (§3.2). Wholesale
