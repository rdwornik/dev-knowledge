## 2. Designed/intended shape (per governing doc)

- `docs/decisions/ADR-98-intake-pipeline.md` §1 (Decision, lines 22-28): three **modes**, not scripts — `--mode functional` (intake doc only) → `--mode architect` (human triage: accept/defer/reject, then authors BACKLOG epics + any forced ADRs + §14a handoffs) → `--mode developer`/`epic` (executes). §3 (lines 34-39) draws the genre line: intake = WHAT/WHY (0..1 per initiative), ADR = decision at a genuine fork (0..n per intake), backlog epic = the work (1..n per accepted intake, each **citing intake-id + ADR-id(s)**).
- ADR-98's 2026-07-07 amendment ("intake↔ADR traceability", lines 79-85) is explicit design intent: `templates/ADR-template.md` gains an `Intake:` field and **"an ADR born from an intake doc MUST cite its intake-id"** — stated as a rule, but the amendment's closing sentence self-limits it: **"The intake↔ADR edge is advisory (a convention, not a gate) ... no new enforcement organ is created here."** So the doc *itself* records that this was designed as prose-only.
- `protocols/PLAYBOOK.md:2225-2236` (Part II §2, "The intake pipeline") is the canonical one-place chain restatement CLAUDE.md §1 points to; it repeats the three-mode chain and the citation rule but adds no new mechanism — it is documentation of the ADR-98 design, not an independent enforcement layer.
- `protocols/HANDOFF_PROCESS.md:582-619` (§16) designs the functional boot's scope precisely as **intake-doc-only** — "No live-state probes ... by design, not omission" — confirming the boot was never intended to reach the backlog or ADRs directly; the technical-architect triage is the deliberately-manual seam.
- `BACKLOG.md:219` (**#347**, filed 2026-07-18 — yesterday, operator priority-program item 2) is the governing doc that names this exact gap as still open: *"decompose the full dev loop into a governed harness: intake → functional-requirements (a functional-architect session that SEEDS the backlog) → ADR → implementation → ... This entry is the decomposition/design anchor, not the build."* This is the clearest on-disk acknowledgment that the intake→functional-requirements→ADR chain is not yet a mechanism.

## 3. Gap

1. **Status-enum drift is real, on-disk, and self-diagnosed but not gated.** 6/17 intake docs (35%) use a *second*, undeclared status vocabulary (`RULED`, `settled`, `plan-of-record-active`, `superseded-pending`, `input-for-deferred-work`, `READY-TO-FIRE`) that borrows the ADR/BACKLOG governance register's own verbs (`RULED`, `settled`) rather than the intake-doc lifecycle README §5 declares. All six are `tech`-genre docs (per the `{func|tech}` infix, `docs/intake/README.md:114-133`) functioning as fleet-hygiene plan-of-record / decision-tracking artifacts — closer to an ADR or a living plan than a WHAT/WHY requirements doc, which blurs ADR-98 §3's hard genre line between "intake = WHAT/WHY" and "ADR = decision." `gen_intake_index.py`'s author built the `OTHER` bucket *knowing* this would happen (comment: "so a typo/new-state surfaces instead of vanishing") but stopped at visibility — nothing forces a ruling (extend the enum, or reclassify the docs).
2. **The BACKLOG-side citation gets a WARN (#279, live); the ADR-side citation gets nothing.** `check_backlog_filing.py` enforces intake citation on new L-epics. No equivalent exists for ADRs — the `templates/ADR-template.md:9` rule is unenforced prose, proven by absence: ADR-102 and ADR-103, which build directly on intake #12 and intake #14's RULED pack via intervening BACKLOG tickets, both omit the `Intake:` field entirely. The rule is not merely theoretically unenforced — it is **observably not followed** on the two most recent, most on-point ADRs.
3. **The "technical architect triage" step — the actual intent→ADR/backlog decomposition — is 100% human-judgment, zero mechanism.** Confirmed by absence: only 2 of `scripts/*.py` reference `docs/intake` at all, and neither performs triage or writes downstream artifacts. This is ADR-98's deliberate design (a boot **mode**, not a script), so it is not a bug — but it is the exact gap BACKLOG #347 (filed 2026-07-18, still open) was filed to formalize, and CLAUDE.md's Layer-2 invariant ("no orchestration scripts", §5 item 4) means any fix here can only ever be a **read-only WARN/gate**, never an executor — consistent with how #279 was built.
4. **The nightly SEED feed (the second half of "requirements come from a conversation, automatically") does not exist yet**, gated on #270 (load-gauge, open) landing before #271 (nightly proposal loop, P3/L, `depends-on: #270`). So today only one of the two designed feeds is live.

## 4. Proposed MECHANISM (script/hook/gate — not prompt prose)

**A. `scripts/validate_intake.py` (new pre-commit hook, WARN-only, mirrors the `gen_intake_index.py` OTHER-bucket detection but as a gate, not just a rendered list).** Enforcement site: new pre-commit hook entry in `.pre-commit-config.yaml`, id `intake-status-enum`, invoked as `python scripts/validate_intake.py --check` on any staged `docs/intake/*.md`. Logic: read each doc's frontmatter `status:`, compare against a `_CANON` set expanded from `docs/intake/README.md` §5 (`SEED|DRAFT|READY-FOR-TECHNICAL|CONSUMED|REJECTED`) plus an explicit, doc-committed `_TECH_EXTENSION` allowlist (the six values currently observed, ratified once by this audit's disposition) — anything outside **both** sets prints a WARN (never blocks, consistent with the ADR-98 advisory-until-hardening posture) naming the offending file:line and the nearest canon value. This converts the current silent `OTHER` bucket into a loud, per-commit signal instead of something only visible by reading the generated README index.

**B. Extend `scripts/check_backlog_filing.py`'s sibling logic to ADRs: a new leg in the same commit-msg hook (or a small new `scripts/validate_adr_intake.py` pre-commit hook) that WARNs when a staged/new `docs/decisions/ADR-*.md`'s `Related:` line cites a BACKLOG `#NNN` that itself (per a `git log --grep` or a static BACKLOG-history lookup) traces to an intake-id, but the ADR's own header has no `Intake:` field.** Enforcement site: `scripts/check_backlog_filing.py` (extend, since it already parses commit diffs and already implements the exact WARN-only/advisory contract ADR-98 §5 requires) or a parallel `validate_adr_intake.py` wired into the same `backlog-filing-backpressure` pre-commit stage. This is the ADR-side mirror of #279 and directly targets the ADR-102/103 evidence in §1/§3.2 above.

Both proposals stay inside the Layer-2 read-only-validator invariant (CLAUDE.md §5 item 4) — neither writes an ADR, decomposes a backlog epic, or auto-promotes a status; both only surface drift that currently exists only as an artifact someone would have to notice by reading files individually.
