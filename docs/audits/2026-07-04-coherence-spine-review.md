## 0. Verdict in one paragraph

The coherence layer is **real, tested with genuine teeth, and honest about its limits** — the mutation-closure test, the move-safety proofs, the no-auto-declare rule, and the coverage drift-guard are better engineering than most production dependency tooling. But it has an inverted investment profile and one demonstrated self-blindness. **Inverted investment:** the heaviest machinery (the doc→code rule mesh: 12 rules, 4 YAML registries, a FAIL-class drift-guard, xfail-strict tests) guards the least-drifting edge class, while the doc↔doc spine — the axis the paradigm was named for — is a **registry of one spec**, and the repo's own #1 declared drift risk (CLAUDE.md §5: "ESSENTIALS summarizes PLAYBOOK; divergence causes drift") has **no mechanized edge at all**. **Demonstrated self-blindness:** the layer cannot see qualitative claims about its own state — three canonical surfaces still describe the undeclared-edge scan as "not in gate" one day after it was wired into ALL_CHECKS, and PLAYBOOK has called the safe-removal gate "pending" for 8 days after it shipped. Every axis also shares one structural blind spot the repo has already half-named (#220): the spine checks **presence and version, not content currency** — an edge can be green while its meaning rots. Nothing here says tear down; several things say **rebalance before extending**.

## 1. How it was implemented — axis by axis

**doc↔doc, declared half (#172).** `reconciled_with: <spec>@<ver>` frontmatter → `validate_reconciliation.py` reads the spec version LIVE from `_SPEC_REGISTRY` → `check_reconciled_versions` FAILs a mismatch (fail-closed), WARNs its own input errors (fail-open). The semantic half is deliberately split out: a mismatch emits a copy-pasteable `check-against-spec` invocation (`restamp_invocations`), the skill verdicts each enumerated site into the re-stamp commit message, and the gate deliberately never gates the skill. Live state: **1 spec (`handoff-process`), 5 dependents, all @5.3, 0 mismatches** (verified live). The forgotten-bump case is held by the non-blocking `coherence-nudge` pre-commit hook (fired 4×, see RF-6). **Solid mechanism, minimal population.**

**doc↔doc, discovery half (#179/#199).** `scan_undeclared_edges.py`: 3-tier evidence (path/basename → spec-id → key-terms), GAP-ONLY filter, fenced-code exclusion, immutable/gitignored pruning with an allowlist-first no-recall-loss guarantee, NO auto-declare. Wired 2026-07-03 (consult-1 ruling #2) as `check_undeclared_edges` — one WARN per tier≤2 candidate, ship-gate-bound via dispositions, shipped with a crafted-repo TEETH test. First live run surfaced 6 candidates, all dispositioned pre-existing, adjudication parked at #241. **Precision engineering is genuinely good; the candidate set is bounded by the registry-of-one.**

**doc→code (#194, ADR-89 OQ1, ADR-90).** Rule-ID identity on both sides (`<!-- rule: ID -->` ↔ `# rule: ID`), path+AST resolution, empirically move-safe (e22e883, four proofs). `ecosystem/doc-code-edge.yaml` carries four registries (declaration_docs / coverage_scope / multi_site / exempt); `check_doc_code_edge` WARNs broken/ambiguous/orphan (advisory-first, promotion data-gated OQ3); `check_doc_code_coverage_drift` **FAILs** any ALL_CHECKS member neither annotated nor exempt — a new check cannot silently escape. 12 rules resolved, multi-organ rules via exact-N `multi_site`. **The most complete axis. Note what it checks: structural presence, not currency — `staleness_signal` is explicitly deferred (`validate_doc_code_edge.py:23`).**

**code→code (#193/#195, ADR-89).** Pyright `references()` oracle with mandatory provenance (git_rev / dirty set / completeness / three honest-limit caveats on every answer) and a never-crash `oracle-unavailable` envelope; consumed by `safe_remove.py` — diff-triggered, FAIL per surviving referrer, WARN+allow on unverifiable (operator-ratified fail-open honoring the static-only limit). M1 (module removal) only; M2 (path/dotted-string refs) + M3 (declared-prose reverse-deps) deferred to #218. **Doctrine-clean; gates removal only, not modification.**

**Self-claims + versions adjacent organs.** `doc_claims` (4 claims: 3 counts + 1 roster, mostly re-anchored to `ecosystem/doc-counts.md` per #222); `amendment_coherence` (exactly 1 CoupledSet: `handoff-major-version`, anchor HANDOFF_PROCESS `Version:`, 2 surfaces, **major granularity**). Graph-level integration owned by `test_legibility_graph_conformance.py` with an env-aware skip-honest tally.

**What is unambiguously well done** (state it plainly, because the red flags below are against a high baseline): the closure metric is a real mutation test, not "tests pass"; every organ states its failure posture and honest limit in its own docstring and Finding text; fail-soft-on-own-error vs fail-closed-on-drift is applied deliberately per row; the disposition register decorates its own stale entries; the no-auto-declare and narrow-first rules held under pressure (blanket-declare was refused on the first live WARN batch, correctly).

## 2. Red-flag list (severity-ranked)

### RF-1 [map-integrity — the layer cannot see claims about itself; demonstrated ×3, recurring]
**Finding:** qualitative mechanism-state claims in canon rot invisibly, including the coherence layer's own descriptions.
**Evidence:**
- `ARCHITECTURE.md:318` "**Not** in `ALL_CHECKS`, not a hook" and the legibility table `ARCHITECTURE.md:392` "undeclared … In gate? **no** (awareness, exit 0)" — false since 2026-07-03 (`check_undeclared_edges` in `ALL_CHECKS`, `audit.py:2012`; the wiring commit touched audit.py/yaml/register/tests but not ARCHITECTURE).
- `protocols/PLAYBOOK.md:253` "consuming gate = **#195 safe-removal, pending**" — false since 2026-06-26 (the gate shipped and #195 closed); `PLAYBOOK.md:256` "does **not** gate" — stale same as above. Eight days, two wirings, tables left behind both times.
- `tests/test_legibility_graph_conformance.py:22,234-235` ledger strings "awareness CLI, **NOT in gate by design**" — same stale claim inside the conformance proof itself (descriptive strings, so the suite stays green).

**Why no organ catches it:** `doc_claims` tracks only counts/rosters (4 claims); `canonical_freshness` A2 fires on *edited-but-not-reviewed*, and these docs were **not** edited — the world moved while the doc stood still; the rule-ID mesh checks annotation presence, not prose truth. This is the prior review's RF-1 class (map claims vs reality), now demonstrated **inside the layer whose job is exactly this**.
**How to improve:** (a) fix the three surfaces now (minutes). (b) Extend `doc_claims` with a *mechanism-state* claim kind — "prose says in-gate/not-in-gate" reconciled against auto-enumerable ground truth (`ALL_CHECKS` membership is already derivable; the deriver pattern exists in `validate_doc_claims.py`). (c) Adopt a working rule: any commit that adds/removes an ALL_CHECKS member greps canon for that organ's name (cheap, mechanizable as a WARN later). The deeper "reality moved, doc stood still" generalization is audit #3's rot-algorithm territory — boundary noted, not designed here.

### RF-2 [coverage inversion — registry-of-one on the axis that matters most]
**Finding:** the entire declared doc↔doc spine guards **one spec** (`_SPEC_REGISTRY`, `validate_reconciliation.py:72-77`), while the repo's most explicitly declared coupling — CLAUDE.md §5 item 6 "ESSENTIALS summarizes PLAYBOOK, not copies it; **divergence causes drift**", reiterated as a §10 anti-pattern — has **no mechanized edge**: PLAYBOOK carries no `Version:` line (verified — the spec parser cannot even read it), is in no registry, and ESSENTIALS declares nothing. The drift is not hypothetical: #77 leg-2 exists precisely because three divergent lesson→rule statements accumulated across these files, found by hand.
**How it was implemented:** narrow-first is ADR-88 Principle 4 and was the right v1 call; but v1 shipped 2026-06-17 and the registry never grew while the doc→code axis grew to 12 rules + 4 registries + a FAIL drift-guard. The ceremony concentrated where drift is rarest (audit-check docstrings), not where the repo says its failure mode lives (canon↔canon prose).
**How to improve:** a deliberate registry-growth pass, not a blind append: give PLAYBOOK a `Version:` line + registry row and let ESSENTIALS/CLAUDE declare edges — **or** decide that the summarizing relation is better served by #180 transclusion (remove the drift surface instead of detecting it) and record that as the reason the edge is not declared. Exact-version pins on a fast-moving PLAYBOOK would thrash (see RF-4's granularity gap) — resolve that first. Either outcome closes the "biggest named drift risk has zero mechanism" hole; leaving it implicit is the one thing ADR-88 forbids.

### RF-3 [presence ≠ reconciliation — the shared currency blind spot, plus a gameable re-stamp]
**Finding (answers the mandate question directly):** the spine reconciles **versions**, not content, and only doc↔doc even does that. doc↔doc: the FAIL clears when the frontmatter version is bumped — running `check-against-spec` is convention, unverified; a blind re-stamp passes. The repo has already witnessed this gaming class on a sibling gate (the 2026-07-01 forced-false `canonical_freshness` re-stamp, caught and answered by #222) — the same pressure applies here and nothing detects it. doc→code: existence-only by design (`staleness_signal` deferred). code→code: gates removal (M1), not modification. All three axes converge on the same hole, which the repo itself filed as **#220 (MODIFY/semantic-drift axis)** — good; it is open and verify-first.
**How to improve (cheap, deterministic, not the rot algorithm):** enforce the re-stamp *ritual* where it already lives — a commit-msg check: a diff that changes a `reconciled_with:` line must carry the check-against-spec checklist marker in its message (the invocation emitter `restamp_invocation` already prints the exact contract; the commit-msg hook pattern exists in `backlog-id-on-close`). That doesn't verify judgment quality (nothing deterministic can — ADR-88 Principle 2), but it makes the blind re-stamp *visible* instead of free. Deeper semantic detection stays with #220/audit #3.

### RF-4 [fragmented edge vocabulary; the discovery half speaks one dialect of four; no granularity knob]
**Finding:** four declaration mechanisms coexist — `reconciled_with` frontmatter, `CoupledSet` surfaces (`amendment_coherence`, which supports **major** granularity), rule-ID doc↔code, BACKLOG `serialize-group`/`depends-on`. The undeclared-edge scan's GAP-ONLY filter reads **only frontmatter** (`_declared_spec_ids`), so a doc guarded by a CoupledSet would still WARN as "undeclared" forever. This is not academic: #241's two genuinely version-coupled candidates (PLAYBOOK `L1008` "Authoritative spec: protocols/HANDOFF_PROCESS.md **v5**"; SESSION_SETUP `L185-197` "follow HANDOFF_PROCESS **v5**") are **major-granularity** couplings. The only offered remedy — `reconciled_with: handoff-process@5.3` — over-couples them (every minor bump would force a re-verdict of PLAYBOOK's ~24 reference sites), which is exactly why the register deferred them. Meanwhile the mechanism that fits (one-row append to the existing `handoff-major-version` CoupledSet, `audit.py:1041-1056`) appears in none of the six disposition reasons.
**How to improve:** (a) resolve #241's two genuine edges via the CoupledSet (or add a granularity form to `reconciled_with`, e.g. `@5.x`); (b) teach the scan that a CoupledSet-guarded surface counts as declared (read the manifest — or move `_COUPLED_VERSION_SETS` to YAML beside `doc-code-edge.yaml` so both organs share config); (c) record the unified vocabulary in one place (ADR-88 names frontmatter + BACKLOG edges only; the CoupledSet and rule-ID dialects post-date it — an ADR-88 amendment candidate, operator's call).

### RF-5 [latent FAIL-trap — asymmetric corpus definitions between the two doc↔doc walkers]
**Finding:** `scan_undeclared_edges` prunes immutable zones (#199: handoffs, ADRs, transcripts, audits, append-only files) because "such a doc cannot take a `reconciled_with` edge." But `validate_reconciliation.discover_dependents` **walks those same zones** (its `_EXCLUDE_DIRS` prunes only `.git/.claude/node_modules/aborted/in-progress/archive*`). Every handoff bundle's `PASTE_THIS.md` embeds `reconciled_with: handoff-process@5.3` (live at L22/L37 of the 2026-07-x bundles); they escape the FAIL-class gate **only because** the file's first line is `=== HANDOFF_BOOT.md (session header) ===`, so the frontmatter parser (`startswith("---")`) returns None — an accident of the assembly format, not a rule. Any future artifact that leads with frontmatter (a bundle-format tweak; an audit doc copying a canon template) enters the reconciliation gate and, on the next spec bump, FAILs with **no legal remediation** — the artifact is immutable (CLAUDE §5.3; ADR-77 guard blocks the edit).
**How to improve:** port `_is_immutable_artifact` (with its living-README allowlist) into `discover_dependents` — one shared corpus definition for both halves of the same spine. This is the spine's own "one regex, N consumers" dedup principle applied to corpus scope. One function move + tests.

### RF-6 [posture inversion — a vanished spec degrades FAIL-strength edges to WARN]
**Finding:** `reconcile()` classifies spec-file-absent/unparseable as `unknown-spec` → **WARN** (fail-open, "own input error"). But a removed or renamed spec is not the checker's input error — it is the **highest-severity coherence event** (every dependent now dangles), and it currently rates *weaker* than a version mismatch's FAIL. Nothing else guards md removal (`safe_removal` covers `scripts/*.py` only; M3 prose reverse-deps deferred to #218). A `git rm protocols/HANDOFF_PROCESS.md` commits through audit-health (WARNs don't block commit) and surfaces only at ship-gate as dispositionable WARNs.
**How to improve:** split the status: registry-id-unknown / malformed frontmatter stay WARN (genuinely own-input); **spec path absent → FAIL** (a mismatch against nothing is still a mismatch). Three lines in `check_reconciled_versions`' mapping plus a test.

### RF-7 [#181's data-gate has data nobody can see]
**Finding:** the nudge **has fired** — 4 entries (2026-06-24/25, HANDOFF_PROCESS content changed while `version=5.2`), sitting in the primary checkout's gitignored `logs/coherence-nudge.log`. The signal is exactly what #181 needs to adjudicate (all four look like mid-arc edits before the eventual 5.3 bump — i.e., evidence for "noisy → escape-hatch/deferred-hash" rather than promote-to-gate). But the log is per-checkout (absent in every worktree — verified here), unversioned, and read by no organ and no session-start surfacing. A data-gated backlog item whose data channel nobody reads never resolves — #181 has been "waiting for data" that has existed for 10 days.
**How to improve:** surface the log tail at SessionStart (the `billing_leak_sentinel` pattern) or fold a one-line "nudge fired N× since last review" into `fleet_health`; then actually adjudicate #181 on the 4 rows.

### RF-8 [self-model lag in the spine's own code + untracked count claim]
**Finding:** `validate_reconciliation.py:11-12` and `check_reconciled_versions`' docstring both still say "in v1 exactly ONE edge is declared" — live count is **5** (verified). The 2026-07-02 self-audit flagged this at 3 declarants; it is now 5 and the claim is unchanged. Similarly `ARCHITECTURE.md:333` "live on **12 rules**" is a prose count no `_CLAIMS` entry tracks (correct today; rots at rule 13).
**How to improve:** fix the docstrings at next touch (they're code comments — no freshness ripple); either add a `len(coverage_scope)` deriver to `doc_claims` or de-number the prose (the #222 pattern: point at `doc-counts`).

### RF-9 [scan-corpus noise — test fixtures are inside the scanned universe]
**Finding:** the live run surfaces `tests/fixtures/repo-with-structural-checks/CONTRIBUTING.md` as a weak signal — `tests/` is neither immutable nor gitignored, so fixtures are candidates-in-waiting; a fixture that ever contains the spec path becomes a tier-1 ship-gate WARN. Also the confirm-hint is uniform ("add frontmatter to BACKLOG.md") where the right answer per doc differs — and frontmatter on BACKLOG.md is untested against the `validate_backlog` schema.
**How to improve:** prune `tests/fixtures/` (one tuple in the prune set); make the confirm-hint conditional or silent for docs whose adjudication is recorded permanent-defer.

## 3. The mandate's direct questions, answered

**Are any of the 6 undeclared-edge WARNs (#241) a genuine missing edge?** Two: **PLAYBOOK** and **SESSION_SETUP** — both carry normative, version-coupled authority claims ("Authoritative spec … v5"; "follow HANDOFF_PROCESS v5"), the register's own reasons already suspect as much. But the right mechanism for both is arguably the **major-granularity CoupledSet**, not an exact-version `reconciled_with` (RF-4). The other four are benign: VISION `L136` (pointer), ESSENTIALS `L377/L230` (pointer-class: "see HANDOFF_PROCESS.md"), AI_COUNCIL_PROCESS `L408` (explicit analogy), BACKLOG (ticket refs; also the one doc where the suggested frontmatter fix is schema-risky). No hidden genuine edge beyond the two. Watch-item: "permanent-defer" entries make the disposition register a **shadow edge-graph** ("known undeclared") with no re-visit trigger — acceptable if named, drift if not.

**Is per-consumer divergence really "stated rule, no mechanization"?** Real but narrower than stated, and mostly outside this layer: within the coherence layer proper, consumers declare **zero** edges (Informant: `reconciled_versions` n/a-no-edges ×4) and the doc→code registry is hub-only **by construction** (not a closable gap in kind). The consumer-side doc-integrity that exists is the ADR-93 floor hash-guard + deployed `canonical_freshness` (both fire-proven). The gitignore-shape divergence class got **one instance mechanized** on 2026-07-03 (carrier `verify()` now asserts committability via `git check-ignore`, with a regression test reproducing ai-council's exact ignore shape — JOURNAL `5f8be71`); the *general* divergence allowlist is decision **D2**, deliberately deferred under #244. So: "no mechanization" is now "partially mechanized, general rule pending an operator decision" — deploy-audit territory, boundary respected.

**Can an edge be declared but stale (target moved/removed)?** Mostly no — with two exceptions now flagged. Registered artifacts are well covered: declaration-doc moved → broken_edge WARNs + the xfail-strict coverage test FAILs (hard catch); code annotation moved → re-found (move-safe, proven); annotation deleted → broken_edge + coverage FAIL. The two soft spots: a vanished **spec** rates only WARN (RF-6), and edges *outside* any registry — canon §-references, "Standalone CLI: python scripts/X.py" prose — rot silently (M3/#218 + audit #3's territory).

**Is `doc_claims` coverage complete?** No — 4 claims, all counts/rosters. The demonstrated gap class is qualitative mechanism-state prose (RF-1); the minor gap is untracked counts (RF-8).

**Over-engineered anywhere?** Less than feared. `multi_site` exact-N earns its bookkeeping (N−1 catches a *lost* annotation that `>=1` would wave through). The genuine ceremony-watch items: (a) the per-candidate ritual — 6 WARNs spawned 6 register entries + a backlog item + a memory rule; fine at N=1 spec, scales linearly with registry growth — decide the pointer-exempt/permanent-defer mechanism **before** adding spec #2; (b) an honesty note, not a flaw: today the doc→code mesh mostly guards rules whose code sites are the audit machinery itself — the spine guarding the spine. Its outward value arrives via the deploy/mesh path; keep that ratio visible when weighing further mesh investment against RF-2's unpopulated axis.
