## Critical

### CRITICAL [ecosystem/schema/desired_state.py:471](<C:/Users/1028120/Documents/Dev/.dev-knowledge/ecosystem/schema/desired_state.py:471>) — Adjudicated root model is incomplete

**What:** `FleetDesiredState` omits the required component/assignment layer, row surfaces, residue manifests, schema-wide lineage, and the D1 composition of desired and observed state; `ComponentSpec` and `ComponentAssignment` do not exist at all.

**Why:** This violates ADR-109 §7 D1/D3 and makes the core “which repos have component X?” requirement impossible.

**Fix direction:** Add the adjudicated component, assignment, lineage, row/residue, and composed fleet-model types and require them through the root; add root-shape tests rather than testing only `schema_version`.

## High

### HIGH [ecosystem/schema/desired_state.py:356](<C:/Users/1028120/Documents/Dev/.dev-knowledge/ecosystem/schema/desired_state.py:356>) — Opaque identity enforcement is incomplete

**What:** `Edge` has no edge ID, while identity-bearing containers such as `Repo.membership`, `Surface.gate_rev_ahead`, and `ResidueManifest.row_order` use ordinary `str`; Pydantic therefore accepts and decodes values such as `bytes`.

**Why:** ADR-109 §3 requires every identity—including edge IDs—to be opaque, byte-exact, and non-coercing.

**Fix direction:** Add a `StrictStr` edge ID and use `StrictStr` for every nested identity position; extend coercion-refusal tests beyond `Repo.id`.

### HIGH [ecosystem/schema/desired_state.py:39](<C:/Users/1028120/Documents/Dev/.dev-knowledge/ecosystem/schema/desired_state.py:39>) — Write-path and preserve-raw guarantees are not represented

**What:** `extra="allow"` retains parsed Python values, not byte-exact YAML, while `Surface` uses `extra="forbid"` and retains neither unknown top-level parity keys nor the original `tier` map. `FleetDesiredState.sources` also defaults empty, despite the requirement that write-policy silence be impossible.

**Why:** Quoting, comments, lexical scalars, key layout, and future fields can be normalized or rejected, so round-trip byte stability and D5’s raw-tier retention cannot be met.

**Fix direction:** Introduce raw source envelopes alongside parsed projections, retain the raw `tier` block, and validate complete per-source write-policy coverage; test actual lexical round trips and unknown top-level surface keys.

### HIGH [ecosystem/schema/desired_state.py:412](<C:/Users/1028120/Documents/Dev/.dev-knowledge/ecosystem/schema/desired_state.py:412>) — Derived lineage accepts a missing hash

**What:** A derived `ResidueManifest` requires `source` but not `source_sha256`; the test at `tests/test_desired_state_schema.py:249` explicitly treats that incomplete pair as valid.

**Why:** This contradicts §3 findings 5–6, which require the provenance pair and hash for derived surfaces.

**Fix direction:** Require `source` and `source_sha256` together for derived manifests and add negative tests for either half missing.

### HIGH [ecosystem/schema/desired_state.py:383](<C:/Users/1028120/Documents/Dev/.dev-knowledge/ecosystem/schema/desired_state.py:383>) — Allocation model can claim concurrent prevention

**What:** `concurrent_prevention` accepts `"externally-coordinated"` even though ADR-109 requires `"not-provided"` until #429 supplies prevention. The test rejects only the unrelated value `"prevented"`.

**Why:** The model can overstate a guarantee the accepted ADR explicitly says does not exist.

**Fix direction:** Restrict the v1 literal to `"not-provided"` and test every prevention-claiming alternative.

### HIGH [ecosystem/schema/desired_state.py:336](<C:/Users/1028120/Documents/Dev/.dev-knowledge/ecosystem/schema/desired_state.py:336>) — Divergence kind/effect coherence and uniqueness are bypassable

**What:** Only `gate-rev-ahead` constrains its effect. A parity waiver can use `suppress-warning`, an audit disposition can use `waive`, and uniqueness is keyed by `(kind, concern_id)`, allowing two kinds with the same concern and effect. The test covers duplicate declarations only within one kind.

**Why:** Suppressions can be misclassified or duplicated, defeating one-per-concern/effect semantics and declaration-only honesty.

**Fix direction:** Enforce the exact kind→effect mapping, validate kind-specific fields, and deduplicate by the ADR’s concern/effect key with cross-kind negative tests.

### HIGH [ecosystem/schema/desired_state.py:43](<C:/Users/1028120/Documents/Dev/.dev-knowledge/ecosystem/schema/desired_state.py:43>) — “Frozen” source mirrors remain mutable

**What:** Pydantic’s `frozen=True` is shallow; allowed extras can contain mutable dictionaries and lists. For example, a nested list passed to `Probe` can be appended after validation.

**Why:** Callers can silently mutate supposedly frozen contract state, invalidating cached validation or comparison results.

**Fix direction:** Convert arbitrary parameters to recursively immutable representations or constrain them to immutable typed structures; test nested mutation, not only direct field reassignment.

### HIGH [ecosystem/schema/desired_state.py:166](<C:/Users/1028120/Documents/Dev/.dev-knowledge/ecosystem/schema/desired_state.py:166>) — Enforcement enum drifts from ADR vocabulary

**What:** `Enforcement` defines `fail-gating` and `warn-only`, while ADR-109 §6/§7 specifies `fail` and `warn`. The tests instantiate `warn-only` without pinning the normative vocabulary.

**Why:** ADR-conforming edge rows will be rejected, while non-contract vocabulary is accepted.

**Fix direction:** Align the enum with `fail | warn | never-gates | inert` and add exhaustive accepted/rejected vocabulary tests.
