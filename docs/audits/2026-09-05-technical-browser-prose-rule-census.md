# Browser-prose rule census — which behavioural rules have a carrier, and which are prose only

**Consumers:** `intake #70` (session roles with a commit-shape carrier — this census is the wider
survey that intake's non-goals deliberately excluded), and the CANDIDATE list in §3 below, which
routes to `protocols/STANDING_RULINGS.md` §AD. Related open rows: `[#609]`, `[#552]`.

**Arc:** architect inbox 2026-09-05, item 008-B. Read-only survey; no rule was changed by it.

---

## §0 — The result, in two sentences

Of the behavioural rules addressed to the browser seat in the two protocol files and the seat's own
notes, **the large majority are prose-only** — they state what a seat must do and nothing in the
repo can refuse a seat that does otherwise. The carried minority are almost all rules that happen
to coincide with a mechanism built for a different reason (a git constraint, a generator, a commit
gate), which means the coverage we have is **incidental rather than designed**.

## §1 — Method, and an honest limit that changes how the numbers read

The item specified `scripts/silent_rule_detector.py` over `protocols/HANDOFF_BOOT.md`,
`protocols/OPERATOR-INTERFACE.md`, and — until `BROWSER-SEAT-FLOOR.md` exists — the seat-notes copy
at `docs/audits/2026-09-05-technical-browser-seat-notes.md` §2–§3.

**The detector was run and its answer is not usable as the census.** Measured at the commit this
lands on:

    silent_rule_detector.py (silent-rule-v5, whole scoped corpus)   files: 61   count: 440
    grep -icE '\b(must|shall|never)\b' protocols/HANDOFF_BOOT.md          4 lines
    grep -icE '\b(must|shall|never)\b' protocols/OPERATOR-INTERFACE.md    2 lines
    wc -l of those two files                                            247 + 193 = 440 lines

Six keyword lines across 440 lines of governance prose. The detector's own docstring states the
limit — *"it cannot tell a rule from a mention of one in an example, and it counts keywords, not
rules"* — and `TOKEN_RE` is `\b(?:must|shall|never)\b`, case-insensitive.

**Why the under-count is structural and not an accident.** The register's own editing note records
that entries in this corpus are *"phrased declaratively"* precisely to avoid raising the ratchet,
which has zero headroom. So the corpus has been shaped, deliberately and correctly, to avoid the
token this census was told to search for. A rule written as *"A file travelling in either direction
lands in the operator's prompts directory"* is fully normative and contains no keyword. **The
ratchet's pressure to phrase declaratively and the detector's keyword proxy point in opposite
directions**, and the second cannot survey a corpus the first has reshaped.

The census below is therefore produced by READING the three sources and enumerating behavioural
rules — a rule being any statement that constrains what a seat does — then resolving each one's
carrier by opening it. The detector run is retained as evidence of the under-count, not as the
method. This is the census's principal honest limit: enumeration by reading is judgment, and a
second reader would draw the boundary of "a rule" slightly differently.

Note what the carried seven have in common: not one of them was built to carry a browser-seat rule.
They are git's own constraints, commit/push gates built for the repo's integrity, and a
dispatch-table drift check. **The seat's own conduct — how it reviews, what form it emits, what it
refuses to act on — is carried by nothing at all.**

## §3 — The prose-only list, as CANDIDATEs

Per the item, prose-only rules become one candidate list, each with a carrier proposed or marked
deliberately prose. Filed as a LIST here; register admission is a separate act with one writer
(§AD), and nothing below was filed into the lettered register by this census.

**Carrier proposed — already has a candidate, no new entry needed:**
- Rules 15, 17 → **candidate (v)** (SessionStart prints the resolved prompts dir).
- Rules 16, 20 → **candidate (n)** and its mechanism leg.
- Rules 10, 11, 22 → **candidate AB-1** (the FORM probe), whose second predicate was added the same
  day by inbox item 008-C.
- Rule 26 → **candidate (f)** (contract-freeze coupling scan).
- Rule 23 → the freeze-gate refusal recorded in LESSONS 2026-09-04; not yet a lettered candidate.

**Carrier proposed — NOT yet carried by any candidate (the genuine gap this census adds):**
- **Rule 7** (raw `git worktree add` skips the seed). Proposed carrier: the seed proof already
  exists as `scripts/worktree_import_proof.py` / `tests/test_worktree_import_proof.py`; a worktree
  whose seed is absent is detectable, so the rule can be carried by testing the RESULT rather than
  policing the command. Cheap, and it does not need a new organ.
- **Rules 3, 4, 5** (boot reply, count mismatch, truncation refusal). Proposed carrier: these are
  all one predicate — *did the seat act on the sentinel* — and it is the same family as AB-1. Fold
  into AB-1 rather than filing a fourth probe.
- **Rules 24, 25** (SHA-named numbers, live-session census). Both are BUNDLE-CONTENT predicates and
  belong to the v7.1 amendment pack (intake #68), which already carries items of exactly this
  shape. Route there, not to a new candidate.

**Deliberately prose, recorded as such:**
- **Rule 1** (do not act unilaterally). This is the seat's constitutional posture, not a checkable
  act; the enforcement that exists is architectural — the seat has no file access. Marking it
  carried would be false, and proposing a carrier would be inventing one.
- **Rule 14** (a locator may be a Downloads path). Descriptive, not an instruction.
- **Rule 21** (role file installed once). A one-time setup fact about a surface outside the repo;
  nothing in the repo can observe it.

## §4 — Limits

1. **The detector did not produce this census** (§1). Enumeration is by reading, so the rule count
   is a judgment, not a measurement. The tally is reproducible only against this file's own list.
2. **`BROWSER-SEAT-FLOOR.md` does not exist.** The item names it as the eventual target, under a
   "candidate (l)" — and **there is no candidate (l)**; §AD records (l) as never filed by anyone,
   the same way it records the absent (h). The fallback the item supplied (seat notes §2–§3) was
   used. If the floor file is wanted, it needs filing as a candidate first.
3. **Seat-notes §2–§3 were read at `worktree-docs-seat-notes` @ 0c57e765**, which has since merged
   and then been EXTENDED post-landing (30166377). Rules 23-26 are quoted from the pre-extension
   text; the extension added error-register entries, not rules, so the census is unaffected — but
   the tail of that audit now differs from what was read here.
4. **Carrier resolution is one-directional.** Each rule was checked for a carrier; no check was made
   for carriers enforcing something no rule states. That inverse survey is a different arc.
