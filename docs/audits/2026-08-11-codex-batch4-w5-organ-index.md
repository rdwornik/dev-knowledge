## Focus

The `[#132]` organ-index generator: `scripts/generate_organ_index.py`, its 33 tests, the
`organ-index-freshness` pre-commit hook, `ecosystem/organ-registry.yaml`, and the generated
`docs/ORGAN-INDEX.md`. The prompt named four constraints the code was required to hold and asked
the reviewer to judge against them rather than describe the diff: **(1) determinism** — the output
must be a pure function of committed repo state, since a regen-and-diff gate over
machine-dependent bytes is unholdable on a second machine, with `--probe-user-level` the one path
allowed to read `~/.claude`; **(2) Layer-2 read-only**; **(3) loud degradation** — an
unparseable/absent source must produce a visible row, never a silently shorter index; **(4)** the
`--check` 0/1/2 contract the hook depends on. It was also asked specifically whether the hook's
`files:` regex covers every source the generator reads.

here, but the diff also spans generated markdown; `codex exec` let the prompt state the four

## Findings

**All four were REPRODUCED against live state before being accepted** (PLAYBOOK Ch7 — read the
finding body, not the severity band). None was taken on the reviewer's say-so, and none was
dismissed. Reproduction evidence is recorded per finding below.

### [CRITICAL] Untracked files change the generated bytes — `generate_organ_index.py`

**Claim.** Collectors glob the working tree, so an untracked `.claude/commands/local.md` renders
as a `/local` row. The output is then not a pure function of committed state, and `--check` reds
on an otherwise identical checkout.

**Reproduced.** Wrote an untracked `.claude/commands/zz-untracked-probe.md` into the live tree:
`'/zz-untracked-probe' in render_index()` → `True`. Probe removed, removal verified.

**Why it mattered most.** This falsified the module's CENTRAL claim — asserted in the module
docstring, the registry header, the generated index header, the closing commit message, and a
test. The freshness gate would have looked armed and been unholdable on any machine but the one
that last regenerated.

**Fixed.** `tracked_files()` runs `git ls-files -z` once per render; every collector filters
through it. This SUBSUMES the previous hand-written `.claude/settings.local.json` exclusion, which
was a special case for one file while every other private scratch file still leaked in. Honest
limit stated in the function: outside a git work tree there is no tracked set, so filtering is
disabled rather than emptying the index.

**Pinned by:** `test_an_untracked_source_file_does_not_change_the_generated_bytes` (builds a REAL
git repo, asserts the untracked file does not move the bytes, then `git add`s it and asserts it
appears) and `test_tracked_files_returns_none_outside_a_git_work_tree`.

### [HIGH] Valid-but-wrong-SHAPED sources crash the gate — `generate_organ_index.py`

**Claim.** `.claude/settings.json` = `[]`, `.pre-commit-config.yaml` = `repos: [bad]`, plugin
`hooks.json` = `{"hooks":{"Stop":"bad"}}` all parse cleanly, then raise on `.get()`.

**Reproduced.** `repos: [bad]` → `AttributeError: 'str' object has no attribute 'get'`;
`{"Stop": "bad"}` → same. (`settings.json == []` did not raise on the isolated call but is the
same class and is guarded with the others.)

**Why it mattered.** `--check` owes its caller exit 0/1/2. A traceback gives the pre-commit hook
neither a verdict nor a diff.

**Fixed.** `_mapping()` / `_sequence()` guards at every nested level; a wrong shape renders a
visible `(unparsed)` row. `_sequence` rejects `str` deliberately — iterating one yields
characters, which is exactly how the next finding became silent.

**Pinned by:** 13 parametrized cases across all four structured sources, each asserting no raise,
`--write` 0, `--check` 0, and every class section still present.

### [HIGH] Registry entries disappear silently — `ecosystem/organ-registry.yaml` handling

**Claim.** `organs: [not-a-mapping]` skips the entry; `organs: bad` iterates the STRING and skips
every character. Either way the inventory shortens and says nothing.

**Reproduced.** By code reading and then by the tests below, which fail against the pre-fix code.

**Why it mattered.** This is the "loud degradation" constraint broken in the one file that carries
the organs no gate can see — the failure mode the whole row exists to eliminate.

**Fixed.** A non-list `organs:` renders the unparseable row; a non-mapping entry renders
`(registry entry N is not a mapping)`.

**Pinned by:** 2 parametrized cases.

### [HIGH] An absent source is masked by another source's rows — `generate_organ_index.py`

**Claim.** With `.claude/agents/` absent, `collect_agents()` returns `[]`; the committed registry
still supplies two L0 agents, so the `agent` section renders normally with no absence indication.

**Reproduced.** The pre-fix test `test_a_missing_source_directory_is_skipped_not_fatal` passed
ONLY because the synthetic registry happened to declare no agents — i.e. the existing test was the
thing making the defect look covered.

**Why it mattered.** The subtlest of the four: loud degradation has to be per-SOURCE, not
per-class, or any source that shares a class with another can vanish without trace.

**Fixed.** Every declared local source root that is not on disk emits a visible
`(<path> — source absent)` row.

**Pinned by:** `test_absent_source_stays_visible_even_when_another_source_fills_the_class`, which
builds exactly that shape (registry agent row present, `.claude/agents/` deleted) and asserts
both rows. The older class-level assertion was REPLACED, not kept.

## The reviewer's negative, recorded because a negative from an adversarial pass is evidence

> "The pre-commit `files:` regex covers every repository path the generator currently reads,
> including all listed `.claude` roots, settings, plugins, manifests, registry, target, config,
> and generator; I found no regex hole."

This was the review's second explicit question. A silent-rot hole in that regex — a source that can
change without the gate firing — is the specific defect the hook exists to prevent, so the
absence of one is a result, not silence.

## Disposition

**4 accepted, 4 fixed, 0 rejected, 0 deferred.** All four reproduced; none was speculative. The
fixes changed robustness only — **the shipped `docs/ORGAN-INDEX.md` is byte-unchanged**
(`--check` exit 0 taken BEFORE any regeneration), because every hub source is tracked and present.

the code now does rather than left asserting a property the review had just falsified.
