## Governing doctrine — read this before acting on any verb

**ADR-100 (Accepted 2026-07-07) = KEEP-ALL-ACCEPTED.** Every accepted audit is kept, unbounded; audit files are **never physically moved, rolled up, or compacted.** ~78% of citations to them live in immutable ADRs / append-only LESSONS / immutable transcripts that a physical move would **permanently break**. Any physical move is **gated** (ADR-100 §3) behind a full referential-currency scan **plus** an explicit architect ruling. This pins the default verb hard to **keep**.

Verb semantics used here, reconciled to ADR-100:

- **keep** — genuine evidence / review / finding / design artifact with lasting citation value. The default and the overwhelming majority. No action; already correct under keep-all.
- **archive-candidate** — a recurring/transient dated digest (ecosystem-audit, conformance-nightly-digest) or a superseded discovery-snapshot whose *standalone* lasting value is low. **This does NOT propose a filesystem move.** It means: a candidate for grouping under the index's **archive *section*** — exactly the count-tiered mechanism ADR-100 §2 already prescribes (files never move; only their index grouping does, and everything older than the ~20 most recent lands there automatically). Flagging it here is informational for the operator; it is not a deletion or relocation proposal.
- **delete-candidate** — a pure duplicate, empty stub, or evidence-free superseded draft. **None survived verification this leg (count = 0).** Even one would require an explicit operator *override* of ADR-100 keep-all before any action.

Verb corrected to **archive-candidate** (same recurring-snapshot class as every other ecosystem-audit). Net delete-candidate count = 0.
