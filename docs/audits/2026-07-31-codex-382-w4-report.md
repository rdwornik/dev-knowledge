## [HIGH] scripts/desired_state_report.py:84 — Surface cells claim conform without observational evidence

What: Every applicable cell without a declaration becomes `conform`, while `_cell()` never uses `model.observed`; `index.yaml` contributes only its timestamp.
Why: Known or unavailable actual state is silently counted as conform, contradicting the report’s “no divergence observable in hub-side records” definition and ADR-109’s requirement that `index.yaml` feed the actual side.
Fix direction: Join explicit per-surface observations into verdicts, or introduce an honest unknown/unavailable result instead of counting cells with no evidence as conform.

## [HIGH] scripts/desired_state_report.py:93 — C3 is inferred from null deployment without consulting the ruling

What: Any non-hub repository with a null deployed version becomes `diverge`, regardless of whether its desired lifecycle contains a `full` ruling.
Why: A legitimate floor-only or unonboarded repository would be falsely reported as the C3 “ruled full but undeployed” gap.
Fix direction: Derive the expected corpus posture from lifecycle assertions using the ruled precedence, and classify null deployment as C3 only when the desired target is `full`.

## [HIGH] scripts/desired_state_report.py:111 — gate_rev_ahead never performs the declared pair join

What: The report reduces every gate declaration to a repository ID, while surface cells separately trust `Surface.gate_rev_ahead`; neither path verifies that both halves reference the same concern or uses `gate_tag_raw`.
Why: An orphaned, mismatched, or stale declaration permanently turns the corpus cell into `declared`, even after the deployed `source_tag` reaches the gate tag and the declaration should self-invalidate.
Fix direction: Resolve the exact `<surface>/<repo>` reference against its matching `gate-rev-ahead` divergence and evaluate the deployed tag against `gate_tag_raw`; test both orphan directions and the self-invalidating equality case.

## [HIGH] scripts/desired_state_report.py:82 — Repository selector is treated as a departure without comparison

What: `_posture_for()` returns only `is_override`, so every repo-keyed LOCAL/IGNORE/INVERSE/TOMBSTONE rule is declared even when it equals the applicable role rule.
Why: A redundant repository selector can produce a false declared verdict; the documented “where the role row says otherwise” condition is not implemented.
Fix direction: Preserve the resolved role posture and classify a repository override as declared only when it semantically differs; explicitly define and test the repo-only/no-role case.

## [HIGH] tests/test_desired_state_report.py:25 — The complete W4 suite skips in the default gate environment

What: Module-level `pytest.importorskip("pandas")` skips all 11 tests when only the default `dev` dependency group is installed, while pandas belongs solely to `analytics` and no analytics-specific test invocation is wired.
Why: A clean `uv run --locked pytest` can report green without collecting any W4 contract test.
Fix direction: Wire an analytics-group test leg, or isolate verdict logic from pandas so semantic tests always run and only the DataFrame integration test is analytics-dependent.

## [HIGH] tests/test_desired_state_report.py:87 — Frozen negative and precedence cases are untested

What: Tests cover only successful joins; they omit unmatched/hub-only waiver behavior, stale or unpaired gate declarations, equal/no-role repository overrides, corpus equality, null deployment without a full ruling, and observed-failure handling. The read-only test also checks only seven existing files, not creation of new outputs.
Why: These omissions allowed the false-verdict paths above to satisfy all 11 tests.
Fix direction: Add a parameterized verdict matrix covering positive, negative, overlapping, and stale declarations, plus a whole-tree before/after assertion for read-only behavior.
