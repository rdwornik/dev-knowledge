## 2. Designed/intended shape (fleet-parity target; cite)

## 4. Proposed MECHANISM (how each divergence gets equalized under RULING-W; any parity-surface additions)

RULING-W (2026-07-18, codified `ADR-36`/`ADR-41` amendments, `docs/decisions/ADR-41-cross-session-backlog-architecture.md:334-342`): *"The hub MAY and SHOULD write into a consumer repo for methodology/cleanup work. The only sanctioned write shape is: consumer worktree/branch → report… never a direct push into a live consumer checkout; re-witness the consumer live before any edit; the consumer's own merge discipline (operator GO, `--no-ff`) governs integration."* Every proposal below is therefore a **report/BACKLOG-seed for a future worktree/branch → report leg**, not an action this audit takes.

1. **#331 resolution + parity-surfaces addition (BACKLOG schema).** Because both consumers have de facto already adopted the schema + gate, the operator ruling #331 asks for ("adopt-at-P6 vs accept-durable, per repo") is arguably already answered by practice — but per RULING-W's "re-witness before any edit" discipline and the standing "don't verdict an unruled question" posture in `parity-surfaces.yaml:526-533`, this audit does NOT add the rows itself. Recommend: operator closes #331 by ratifying the observed state (adopt, both), then a hub leg adds `backlog-story-map-schema`/`backlog-schema-gate` consumer-tier rows (`tier: {consumer: MUST}` or `SHOULD`) to `parity-surfaces.yaml`, and separately reconciles the corp-vs-ai `validate_backlog.py` content gap (either ai-council adopts corp's fuller plugin-form via its own worktree/branch → report leg, or the Wave-1 `[S<n>]`-omission becomes its own declared, time-boxed `.methodology.yaml` divergence rather than an undocumented comment).
2. **`hub-toc-hooks` re-scope or ai-council withdrawal.** Two RULING-W-compliant paths, gated on an operator DECISION (this is not self-executing): (a) extend corp's precedent — a consumer worktree/branch → report leg in ai-council adds a `hub-toc-hooks` `.methodology.yaml` declaration and removes `toc-freshness`/`toc-generate` from its `.pre-commit-config.yaml`, mirroring corp exactly; or (b) a hub-side manifest re-scope (v1.3.2+) drops `toc-freshness`/`toc-generate` from the fleet-generic install set entirely (matching the hub's own retirement), after which a remove-leg prunes ai-council's copy and corp's declared waiver becomes moot/retirable. Either way, file the DECISION before touching either consumer tree.
3. **corp `deployed-versions.yaml` currency.** No new mechanism needed — already tracked by hub `#276` (durable per-consumer prune scoping) and self-invalidates per ADR-102 once a real `deploy/tool.py --execute` redeploy lands for corp. This audit surfaces it as corroborating evidence for #276's priority, not a new ticket.
4. **No parity-surface addition proposed for item 5** (the `normalize-headers`/`normalize-dated-headers` local convention) — insufficient evidence it's methodology-owned; would need a design decision on whether to consolidate, which is out of this stream's remit.
