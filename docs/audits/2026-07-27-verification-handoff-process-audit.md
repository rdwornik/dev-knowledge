## 0. Verdict in one paragraph

The v5 transport machinery is healthy where it is machine-held and leaking exactly where it is prose-held — the 2026-07-04 adoption review's law ("every handoff property with a mechanical guard held; every property held by prose eroded") re-verified end-to-end on the 2026-07-25/26/27 window with zero counterexamples found. The anti-bluff probe contract, the supplement fill→fold lifecycle, the FILL-IN completeness gate, and the ADR-85 SHA-anchor stop-gate all held under load, including under cross-repo re-authoring and a filled 217-line supplement. What failed was never the bundle: it was (1) rules that ride as prose inside consumed transients — the boot-reconciliation rule was skipped by three consecutive windows *while sitting in the paste*, the file-upload transport rule was violated repeatedly *the same window it was written down*, a BINDING ruling was nearly relitigated because it lived in a superseded supplement; and (2) whole coordination surfaces v5 never claimed — parallel-lane JOURNAL allocation, primary-HEAD ownership, chat-born term provenance, per-prompt MODE/model/effort routing — where the browser-witnessed incidents of this window all have prior siblings in the s6/s7 night audits' ledgers, filed but unbuilt. The v6 pack therefore proposes almost no new prose: it proposes probe legs, template fields, generator/assembler beats, and one hook extension, and it defers everything whose structural owner already exists ([#433] restructure, #353/#344/#349 organs, #301 PLAN artifact, [#423] integration mechanization).

## 4. Classification

### 4.1 Class (i) — covered, failed anyway: WHY

One mechanism explains every class-(i) row: **the covering clause is prose and the failing surface has no organ.** BW-f's rule sat in the paste the sessions that skipped it had just consumed; BW-h's ruling sat in a supplement that was faithfully transported, then became unsearchable history; RM-1/RM-2 are claims no validator reads; RM-3 grew because nothing meters it; RM-4 shipped because §5 has no boundedness condition for probe design; RM-5 bites because the sweep that catches it is "manual and therefore skippable" (the 07-25 session's own words). This is not a new diagnosis — it is the 2026-07-04 audit's law re-confirmed with this window's incidents, and the law's oldest statement in the record predates every handoff era audited: "Confidence level … without enforcement mechanism = decoration. Markdown cannot force compliance" (LESSONS:376, 2026-04-30). It is why every v6 proposal for a class-(i) finding is a mechanism (probe leg, template field, assembler beat, validator rung), never a stronger sentence.

### 4.2 Class (ii) — structurally uncovered: the boundary is real

Four surfaces sit genuinely outside what a handoff bundle can carry or check, and the equilibrium contract (ADR-87) says which side must move:

- **Parallel-lane coordination** (BW-c, BW-d): lanes are concurrent *sessions*, not handoff receivers; the transport spec cannot serialize them. Owners: the JOURNAL-allocation convention (proposal A5), the filed #353/#344/#349 organs + s6 §4 session-lock shape, and [#423] (integration-sequence mechanization). The handoff's legitimate share is the destination-contract (declare worktree/branch/write-scope ex-ante — §14a already does this for epic lanes; A4 generalizes it).
- **Prompt-development lifecycle** (BW-g): the mandate artifact is off-repo by construction; no repo gate can reach it unless it is committed. The ruled fix exists (intake #17 D3 four-state PLAN; #301), and s7 §4 already drafted the checklist. A4/A9 adopt these by reference.
- **Chat-born provenance** (BW-e): only the browser holds a chat-ratified term at ratification time, so per ADR-87 this is one of the few legitimately browser-side loads: the capture question must be asked OF the chat. The cheapest existing channel is the supplement interview (A6: one added question), which the fold pipeline then persists mechanically.
- **Browser-side memory / transport integrity** (BW-a): the browser cannot verify it received all of a paste; only the emitter can make truncation visible. v5 already solved this once for the boot ("on-load acknowledgment line so a partial/missing paste is visible", §4 — the ADR-79 idea); it was never generalized to the other direction or to mid-session reports (A1/A2).

### 5.3 Longitudinal verdicts

- **The same failure classes recur across eras until they get an organ, then stop:** VISION-not-internalized (v3.2) → articulation gate → reborn as the v5 orientation probe; `expected:` erosion → v5.4 rung → zero recurrence; unfilled FILL-INs → `residual_completeness` → zero recurrence.
