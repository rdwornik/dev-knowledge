## 1. The finding this lane returns

**`--force-with-lease=<ref>:` does not, on its own, refuse a racer whose value equals the held
one.** Measured on git **2.55.0.windows.3**, first against a local bare remote and then against
`https://github.com/rdwornik/dev-knowledge.git`:

| racer's value vs the held lock | git's answer | exit |
|---|---|---|
| different | `! [rejected] … (stale info)` | 1 |
| **same** | `= … [up to date]` | **0** |

The lease is evaluated only when the values differ. When they match, git short-circuits to
"up to date" **before** the lease decides, and returns success. The design sketch's success test is
`if r.returncode == 0: return 0`, so it reads the same-HEAD race as *lock won* — the exact race the
lease was adopted to close, in the exact state the research names as normal ("N lanes fork from one
HEAD"). The recorded claim that the lease "is not a hardening detail; it is the entire mechanism"
is half right: the **remote arbitration** is real and cross-machine, the **success test** is not.

**The repair stays inside the ruled mechanism.** The claim push now runs with `--porcelain`, and a
claim counts as won only on the status flag `*` (`[new reference]`):

- `*` → claimed (exit 0)
- `=` `[up to date]` → already held, refused (exit 3)
- `!` with a lock-attributable reason (`stale info` / `non-fast-forward` / `fetch first`) → refused
- anything else, or no status line at all → internal error (exit 2, fail closed)

The exit code is not the verdict; the flag is. Flags are single characters git does not translate,
so this also survives a localized git in a way prose matching does not.

Two tests pin the behaviour so it cannot regress silently — one on the raw refusal-that-isn't
(`test_t2_the_lease_alone_does_not_refuse_a_same_value_racer`), one on the won claim
(`test_a_won_claim_is_reported_by_git_as_a_new_reference`). If a future git starts rejecting the
same-value racer, the first fails and the guard can be simplified deliberately rather than drift.

## 7. Decisions taken under the lane budget

Each decided per contract and reported here rather than dripped as a question.

1. **The porcelain verdict** (§1). Made because the contract's own step-2 list requires "T4 same-HEAD
   via force-with-lease refused" and the ruled sketch does not deliver it. Treated as executing the
   Done-when rather than amending the design: what is pushed, the ref namespace, the lease flag and
   the fail-closed posture are all unchanged.
2. **git's repo-local env vars are scrubbed from every child**, enumerated via
   `git rev-parse --local-env-vars` and never blanket-stripped. `GIT_DIR` overrides both cwd and
   `-C`, and a lock claimed in the wrong repository is this guard's own failure class.
3. **`GIT_TERMINAL_PROMPT=0` and `LC_ALL=C`.** A gate that hangs on a credential prompt is worse
   than one that exits 2, and a localized git would defeat message matching.
4. **Bytes on the wire for `git update-ref --stdin`.** `subprocess.run(text=True)` rewrites `\n` to
   `\r\n` on Windows and git rejects the CR as `extra input` — witnessed here.
5. **Exit 128 alone does not mean "held".** 128 is git's generic fatal, including for the payload
   defect above; the `reference already exists` marker decides. Reading the code alone reported a
   lock nobody held.
6. **Release is idempotent, and says "is now free" rather than "released"** — GitHub answers a
   delete of a never-existing ref with `- [deleted]` and exit 0, so the action is not knowable
   while the outcome is.
7. **No `slow` marker**, following `test_merge_serialization` / `test_block_ff_push` for plain
   real-git spawns.
8. **The guard is wired into no hook.** The contract's manifest is the script and its tests; making
   it fire at step 0 would be a gate change nobody asked this lane for.
