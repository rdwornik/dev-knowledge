## Use

1. **Boot the browser.** Open a fresh Claude.ai chat; paste the full contents of
   `protocols/HANDOFF_BOOT.md` (per `HANDOFF_BOOT.md` here). The browser replies with its
   on-load acknowledgment (`Booted as architect under HANDOFF_PROCESS v5. Ready for CC's
   handoff.`). Because this handoff **names architect mode**, it adopts the generative
   posture — orient first, drive decomposition, hold the whole-system view, surface design
   tensions.
2. **Orient first — the architect's first move (v5 §13c).** Before anything else, run the
   **orientation probe** in `PROBES.md` (P1): the browser, having no files, replies
   **"run `<command>`"**; **CC** reads the **live** `VISION.md` / `ARCHITECTURE.md` Ch1 and
   substring-checks the quote. The two orienting lines enter the session only by CC reading
   them live — never copied into this bundle, never paraphrasable from a summary.
3. **Hand over the residual.** Give the browser `RESIDUAL.md` — **drift-flags first**, then
   the open architecture questions + the task-graph.
4. **Run the comprehension gate.** Work the rest of `PROBES.md`. The browser has no file
   access, so for every probe it must answer **"run `<command>`"** — surfacing the off-bundle
   dependency rather than hiding it. **CC** runs each command against **live state at
   check-time**, re-derives ground truth, and emits PASS/FAIL. **Any FAIL blocks
   onboarding** (degrade loudly — never synthesize a pass).

## Teeth note (v5 §5)

Every probe's exact answer — the orienting lines, the check count, the HEAD sha, the
drifted `#id` — is deliberately kept **out of this whole bundle**. Only question + locator +
command ship, so the only path to an answer is opening the live file/state. A summary can't
bluff them; that is the point. See `RESIDUAL.md` §"Why the probes have teeth".
