# 06 · Comprehension check

Before you do any work, answer these from what you read in `01`–`05`. This is not a
quiz for its own sake — it confirms you can **apply** the bundle, not just paraphrase
it. Answer concisely. Rob will confirm before you proceed.

## Static (methodology + project)

1. What is Rob's model-selection rule — when do you use Sonnet vs Opus, and when
   should you use no AI at all? (Include his standing rule about defaulting.)
2. When do you convene **AI Council** rather than deciding yourself?
3. Name two **sacred files** in this repo and the lifecycle rule that protects each
   (e.g. append-only, immutable, newest-first prepend).
4. What does the **ADR-41 cross-repo ownership** rule forbid you from doing this
   session — and what cross-repo action *is* still allowed?

## Tailored to recent work

5. The v3.4 handoff process produced 13 audit findings, yet the session replaced it
   with v4 wholesale instead of patching the 13 bugs. **Why?** What principle drove
   "the cluster is the diagnosis," and what does it imply about how you should treat
   *your own* mistakes this session?
6. `04_RECENT.md` lists two sender claims that drifted from repo state. Name **one**
   of them, state the actual repo fact, and say what you should (and should not) do
   about it.
7. Two candidate first-moves compete: ratifying v4 via Council, and a doc-truth
   sweep. There's a sequencing tension and a small piece of hygiene that should
   come first regardless. What is that hygiene task, and why does doing it early
   matter (tie it to finding ML-2)?

## Pass criterion

You pass when answers 1–4 are correct and 5–7 show you grasped the current work —
not when you can restate the files verbatim. If you are unsure of a fact, say so
rather than guessing; that is the correct behavior here, and this bundle was built
on exactly that discipline.
