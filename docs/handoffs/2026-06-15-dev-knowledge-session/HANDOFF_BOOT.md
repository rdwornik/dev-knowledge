## What the operator does (paste-pointer)

1. Open a fresh Claude.ai chat.
2. Paste the **full contents of `protocols/HANDOFF_BOOT.md`** (the **repo** role file — not this
   bundle file of the same name; see the collision note in the runbook). The browser replies with
   its on-load acknowledgment line, so a partial/missing paste is visible.
3. **This handoff is execution mode** — the lean default. The browser runs the **reactive
   partner + filter** posture (`HANDOFF_PROCESS.md` §7); the architect-only orientation probe and
   operator-context beat (§13c/d) are **skipped**.
4. Hand the browser `PROBES.md` and work it **straight through** (no separate orientation half) via
   the run loop in the runbook: for each probe the file-less browser replies `run <command>`, you
   (or CC) run it live and paste the result, CC substring/state-checks. **Any probe FAIL blocks
   onboarding** (the escalation ladder, §10).
5. Hand `RESIDUAL.md` — **drift-flags first** (§1: the origin gap is the headline), then the
   **embedded architect brief** (§2, the Layer-1 strategic "why" — read it as the priorities/owner
   ledger), then the task-state pointer (§3) and the hybrid-design surfacing (§4).

## Why a pointer, not a copy

The methodology, the browser role, and the operator runbook all live in the repo and are
referenced by **pointer**; CC (which holds the repo) serves any part the file-less browser needs,
just-in-time. This file points; `protocols/HANDOFF_BOOT.md` is the boot source and
`docs/handoffs/README.md` is the operator runbook. If a pointer and its source disagree, the
source wins — fix the pointer.
