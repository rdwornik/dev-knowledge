## Purpose
<!-- scope: meta -->

Operational protocol for generating handoffs in the `.dev-knowledge` ecosystem. Implements ADR-42 three-stage flow. A handoff transfers session state across browser chats or Claude Code sessions. All handoff artifacts live in `.dev-knowledge/docs/handoffs/{date}-{slug}/` — ADR-36 read-only contract preserved (no writes to target repos).

---

## When to use
<!-- scope: meta -->

| Trigger | Type | Stage 2? |
|---|---|---|
| Audit cycle complete (per ADR-36) | audit-sync | Implicit (findings as substitute) |
| Browser session wrapping work-in-progress | session-sync | Required |
| Cross-repo migration coordination | feature-X-sync | Required |

Handoffs are explicitly triggered by Rob. The browser does not propose handoff generation unprompted.

## Three-stage flow
<!-- scope: hybrid -->

### Stage 1: Question generation
<!-- scope: hybrid -->

Rob in Claude Code (.dev-knowledge):
> "Make handoff for {repo} at {path}, type {audit|session|feature-X}"

Claude Code:
1. Reads target repo state (`git rev-parse HEAD`, `git branch`, `git status`)
2. Reads `.dev-knowledge/BACKLOG.md` for relevant items
3. Reads `.dev-knowledge` audit history for {repo} if it exists
4. Loads `templates/HANDOFF_QUESTION_TEMPLATE.md`
5. Customizes template with repo-specific context
6. Outputs `01_question_for_browser.md` to working directory
7. Reports to Rob with brief summary

**For audit-sync:** Claude Code proceeds directly to Stage 3 — audit findings substitute for browser-2 response. No `01_question_for_browser.md` generated.

### Stage 2: Architect response (skipped for audit-sync)
<!-- scope: llm -->

Rob:
1. Opens browser-2 (target project chat)
2. Pastes `01_question_for_browser.md` content as first message
3. Browser-2 architect provides structured answers to all 5 pipeline questions
4. Rob copies response back to Claude Code

### Stage 3: Reconciliation + folder generation
<!-- scope: hybrid -->

Rob in Claude Code (.dev-knowledge):
> "Generate handoff folder using {response_path or audit_report_path}"

Claude Code:
1. Reads Stage 2 response or audit findings
2. Re-verifies target repo HEAD SHA (drift check vs Stage 1)
3. Loads `templates/HANDOFF_FOLDER_TEMPLATE.md`
4. Generates folder at `.dev-knowledge/docs/handoffs/{date}-{slug}/`
5. All 11 files populated per template spec
6. SHA-256 checksums computed for `01_manifest.json`
7. Validators run (`python scripts/validate_scope_tags.py`, `pre-commit run --all-files`)
8. Single commit on dedicated branch

## Folder structure (per ADR-42)
<!-- scope: meta -->

```
docs/handoffs/{date}-{slug}/
├── 00_README.md                 (Rob's upload instructions)
├── 00_first-message.md          (browser-2 first message, copy-paste)
├── 01_MANIFEST.md               (entry point, file index, HEAD pin)
├── 01_manifest.json             (machine-readable, SHA-256 checksums)
├── 02_VISION.md                 (FULL .dev-knowledge VISION copy)
├── 03_PLAYBOOK.md               (FULL .dev-knowledge PLAYBOOK copy)
├── 04_ESSENTIALS.md             (FULL .dev-knowledge ESSENTIALS copy)
├── 05_GOVERNANCE_ESSENCES.md    (ADR essences relevant to actions)
├── 06_STATE_OF_PLAY.md          (current state, audit findings)
├── 07_ACTION_PLAN.md            (goals, directives, boundaries)
├── 08_TREE.txt                  (target repo file inventory)
└── 09_EXECUTION_EVIDENCE.md     (return trip template)
```

Slug: `{YYYY-MM-DD}-{repo}-{type}` (e.g., `2026-04-30-ai-council-audit-sync`). Folder is immutable post-close.

## File responsibilities
<!-- scope: meta -->

| File | Purpose | Content origin |
|---|---|---|
| `00_README.md` | Rob's instructions: how to use this handoff | Generated by Claude Code |
| `00_first-message.md` | Copy-paste for browser-2 first message | Generated by Claude Code |
| `01_MANIFEST.md` | Entry point, file index, HEAD pin, receiver synthesis prompt | Generated by Claude Code |
| `01_manifest.json` | Machine-readable metadata + SHA-256 checksums | Generated by Claude Code (last) |
| `02_VISION.md` | Ecosystem context (why .dev-knowledge exists, scope, methodology) | Full copy of `.dev-knowledge/VISION.md` |
| `03_PLAYBOOK.md` | HOW we work — methodology preserved across sessions | Full copy of `.dev-knowledge/protocols/PLAYBOOK.md` |
| `04_ESSENTIALS.md` | High-leverage cheat-sheet rules | Full copy of `.dev-knowledge/protocols/ESSENTIALS.md` |
| `05_GOVERNANCE_ESSENCES.md` | ADR rules driving specific actions in this handoff | Curated by Claude Code from relevant ADRs |
| `06_STATE_OF_PLAY.md` | Current State per ADR-37 | Stage 2 REALITY/RATIONALE answers or audit findings |
| `07_ACTION_PLAN.md` | Future State per ADR-37 | Stage 2 OBJECTIVE/DIRECTIVES/BOUNDARIES answers |
| `08_TREE.txt` | Target repo file inventory at Stage 3 | `git ls-files` in target repo |
| `09_EXECUTION_EVIDENCE.md` | Return trip: browser-2 fills post-work | Empty template, filled by next session |

**Invariant rule:** `02_VISION.md`, `03_PLAYBOOK.md`, `04_ESSENTIALS.md` are FULL copies — never curated. They are the methodology anchors that prevent browser-2 from hallucinating norms.

**ADR essence rule:** `05_GOVERNANCE_ESSENCES.md` includes ONLY ADRs cited in `07_ACTION_PLAN.md` directives. Format per essence: title + 2-3 operational sentences + reference path to full ADR.

## Drift mitigation
<!-- scope: dev -->

Stage 1 captures target repo HEAD SHA. Stage 3 re-verifies before generation:
- **Match:** proceed
- **Mismatch:** Claude Code STOPS, flags to Rob, does not generate folder until Rob approves or resolves drift

`01_manifest.json` SHA-256 checksums prevent post-generation file tampering.

Browser-2 first action upon opening handoff: verify HEAD SHA via `git rev-parse HEAD` in target repo. Mismatch → STOP, report drift, do not proceed.

---

## Return trip
<!-- scope: hybrid -->

`09_EXECUTION_EVIDENCE.md` is filled by browser-2 or Claude Code in the target repo after completing the handoff work. Provides:
- Commands run (with raw stdout)
- Test results (pytest output)
- Git diffs of changes made
- Final HEAD SHA after work
- Failures or partial completions (explicit, not omitted)
- Handoff for next session if applicable

Next `.dev-knowledge` session reads `09_EXECUTION_EVIDENCE.md` to verify what actually happened — eliminates "Self-Correction Theatre."

---

## Roles
<!-- scope: meta -->

- **Rob.** Triggers handoff (never browser-2 unprompted), reviews question prompt (Stage 1 output), carries browser-2 response back (Stage 2), accepts handoff folder.
- **Claude Code (.dev-knowledge).** Executes Stage 1 and Stage 3: reads target repo state, generates question prompt, generates folder, computes checksums, runs validators, commits.
- **Browser-2 (target project chat).** Executes Stage 2: answers 5 pipeline questions with project-level intelligence. Also consumes the handoff: opens it, verifies HEAD SHA, provides receiver synthesis, executes directives, fills `09_EXECUTION_EVIDENCE.md`.

Browser-2 does NOT generate folders or run git in target repo (unless Rob explicitly directs it to, for small single-file changes). Claude Code does NOT redesign architecture or invent session content.

## What changed from v2.0
<!-- scope: meta -->

| Dimension | v2.0 | v3.0 |
|---|---|---|
| Flow | Single-stage (one actor generates everything) | Three-stage (question → architect → reconcile) |
| Structure | 3-level nesting (`contents/relevant-decisions/`) | Flat 11-file |
| File count | 13 (with subdirs) | 11 (flat) |
| Invariants | VISION/PLAYBOOK/ESSENTIALS missing | Full copies mandatory |
| ADRs | 7 full ADR copies | Essences only (~2-4 sentences each) |
| Question pipeline | Hand-crafted per handoff | Standardized 5-question SBAR/I-PASS |
| Return trip | Missing | `09_EXECUTION_EVIDENCE.md` template |
| ADR-32 §4 | Pending items in HANDOFF.md | BACKLOG.md canonical (per ADR-41) |
