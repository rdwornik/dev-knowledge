## Purpose [CORE]

`.dev-knowledge` is the universal LLM-driven development guide and methodology
framework for all `Dev/` projects. It is **Layer 2** of the ADR-28 three-layer
ecosystem model — passive storage and governance authority, not an execution engine. It
holds protocols, ADRs, intake docs, handoffs, templates, and hub-local validators,
generators and gates; it prescribes conventions child repos must follow. **Layer 2 may
not drive a CHILD repo's state** (Ch1 invariant 2).

**A fleet count is meaningless without its surface** — three nest (machine-registered ⊂
human-registered ⊂ all git repos):

| Denominator | Authoritative surface | Answers |
|---|---|---|
| machine-registered | `ecosystem/index.yaml` — derived from `ecosystem/<repo>/state.yaml`; regen via `audit.py registry update`; never hand-edit | which repos the audit machinery walks |
| human-registered | `ecosystem/registry.md` — hand-maintained | which repos the operator tracks |
| all git repos | ADR-104 | the fleet's shape as ruled |

`onboarded` is `registry.md`'s Status column — a separate axis, not a fourth denominator.
Read a count off the surface that defines it; do not restate one here.

## Layer Boundaries & Invariants [CORE]

**Chapter 1 — Layers & authority.** A closed loop across three actors:

| Actor | Role |
|---|---|
| L1 — browser chat | architect — analysis & design |
| Operator (Rob) | consent gate — the operator pasting a prompt *is* consent |
| L3 — Claude Code | executor — does Layer 3 work |
| **L2 — `.dev-knowledge`** | **this repo** — passive storage & governance |

Loop: L1 → Operator (prompt/handoff) → L3 executor (ratified prompt) → L2 (handoff → git
commit) → L3 (read/pull, prescribes read-only) → L1 (reflection → new chat). The
architect proposes, the operator ratifies, the executor acts only inside ratified scope.
**Ratification bandwidth is the scarce resource** every context-compressing protocol
(handoff bundles, the floor, valves) exists to spend less of.

**Invariants** (→ ADR-28, ADR-36, ADR-39, ADR-41):
1. **Layer 2 never executes** — no script here orchestrates or drives state in another repo.
2. **Validators are read-only on siblings** — `scripts/` only reads/checks/reports; the
   cross-repo `audit.py run` writes only into `.dev-knowledge` (ADR-36, ADR-69).
3. **Prescriptive authority** — PLAYBOOK + ADRs bind child repos; no local override (ADR-31).
4. **Append-only files never edited** — `LESSONS.md`, `logs/TOKEN-LOG.md` (ADR-29, ADR-39);
   LESSONS.md may relocate a byte-identical older block into `LESSONS-legacy-<span>.md`.
5. **Dated artifacts are immutable** — ADRs, transcripts, handoffs, audits (Ch5).

## Authority and governance [CORE]

Per **ADR-31**, `.dev-knowledge` is the binding source of cross-repo prescriptions
(Authority model 1B). Operator = ratification authority; hub = prescription authority;
enforcement is out-of-band and read-only.

- **Ratification, not adjudication.** The operator rules on *constraints, priority,
  scope*, not correctness (ADR-63); the architect surfaces trade-offs.
- **Enforcement.** `scripts/audit.py`: self-audit `health` + cross-repo `run` (manual).
  Live check registry: `python scripts/audit.py checks`.
- **Tier system retired** 2026-05-23 — the ADR-38 A5 baseline applies to every repo.
  `ARCHITECTURE.md` is mandatory for every repo (ADR-51).
- **Baseline rule:** the audit runs green on first invocation (ADR-31).

→ Full doctrine: ADR-31, ADR-36, ADR-63. Codex reviewer config: `~/.codex/AGENTS.md`
(canonical source `deploy/global-instructions-codex.md`, ADR-54).
